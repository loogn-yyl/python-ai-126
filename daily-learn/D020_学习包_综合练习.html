1一条命令长什么样：三种参数形态

先把目标写死。今天结束时，下面这条命令要能跑：

python logtool.py access.log -n 5 --format json
形态例子代码里怎么写读出来是什么
位置参数access.logadd_argument("path")args.path 是字符串
选项（带值）-n 5add_argument("-n","--top",type=int)args.top 是整数 5
开关（不带值）-qadd_argument("-q",action="store_true")args.quiet 是布尔 True

三条约定记牢，能省掉一半查文档的时间：

  • 属性名取第一个长选项名。"-n","--top" 写成一起，属性就叫 top，不是 n。只写 "-n" 才会叫 n。
  • 位置参数的属性名就是变量名，"path" 对应 args.path，名字自己定。
  • 短选项可以粘连：-n 5、--top 5、-n5 三者等价。
import argparse

parser = argparse.ArgumentParser(prog="logtool", description="分析 nginx 访问日志")

parser.add_argument("-q", "--quiet", action="store_true", help="只输出结果，不打进度")
parser.add_argument("--format", choices=["text", "csv", "json"], default="text")

只给位置参数: Namespace(path='a.log', top=3, quiet=False, format='text')
注意 parse_args([...]) 这里传了一个列表。这是给自己调试用的：不传参时它读的是 sys.argv，也就是你在终端敲的整条命令。留一个 argv=None 的形参，测试时塞列表，正式跑时走默认值——这个形参在第 7 节会用到。
没写 -h，但 -h 已经有了。argparse 会自动加上 -h/--help，按你写的 help= 生成长帮助，退出码 0。
它的换行位置跟终端宽度有关，别把 -h 的输出当固定格式背——同一份代码在 80 列和 120 列的终端上排出来不一样。

2argparse 替你做的三件事：校验、报错、退出码

这三件事以前是你自己在代码里 if 来 if 去写的。现在交给 argparse，你只管「声明」，它负责「守门」。

你输入了什么argparse 的反应退出码
缺必填参数打 usage + error: the following arguments are required: path2
--format xml（不在 choices 里）invalid choice，并把可选项列出来2
-n abc（type=int 转不动）invalid int value2
两个互斥的开关同时给not allowed with argument2
-h打印帮助0
一切正常返回 Namespace不退出，交给你

看它实际怎么退：

import argparse
import contextlib
import io

parser = argparse.ArgumentParser(prog="logtool", description="分析 nginx 访问日志")
parser.add_argument("path", help="日志文件路径")
parser.add_argument("-n", "--top", type=int, default=3, help="Top N，默认 3")
parser.add_argument("--format", choices=["text", "csv", "json"], default="text")

for argv in (["-n", "5"], ["--format", "xml", "a.log"], ["-n", "abc", "a.log"]):
    err = io.StringIO()
    try:
        with contextlib.redirect_stderr(err):
            parser.parse_args(argv)
        print(f"{argv} -> 正常返回")
    except SystemExit as e:
        print(f"{argv} -> 退出码 {e.code}")
        print("   ", err.getvalue().strip().splitlines()[-1])
['-n', '5'] -> 退出码 2

['--format', 'xml', 'a.log'] -> 退出码 2

['-n', 'abc', 'a.log'] -> 退出码 2

报错信息是打到 stderr 的，不是 stdout。所以这个例子里必须用 contextlib.redirect_stderr 才抓得到——正常写代码时你一行都不用写，用户在自己终端上会直接看见。

互斥的两个开关

-q（安静）和 -v（啰嗦）同时给没有意义，让人家自己报错比你在代码里猜要好：

生产代码里不要 try/except SystemExit。parse_args() 报了错就应该让程序死掉——它已经替你打好了人话，重新包一层只会让信息变模糊。捕获它只发生在两种场合：写测试，或者像上面这样在笔记本里演示。
退出码的分工，今天就定下来：
0 成功 ｜ 1 业务失败（文件不存在、没有可解析的行）｜ 2 用法错误（argparse 专用，别自己占）
shell 脚本和 CI 都靠这个数字判断成败，别一律 sys.exit(1)。

3logging：五个级别，三行配置

级别数值什么时候用
DEBUG10变量值、耗时、循环到第几轮——只在排查问题时想看
INFO20「开始处理 X」「完成，共 7 行」——正常流程的里程碑
WARNING30跳过 1 行坏行——不致命但需要知道
ERROR40文件不存在、全解析失败——这次任务废了
CRITICAL50整个程序没法继续（日常脚本基本用不到）

配置只有三件事：级别、格式、往哪写。

import logging
import sys

logging.basicConfig(
    level=logging.WARNING,
    format="%(levelname)-8s | %(name)s | %(message)s",
    stream=sys.stdout,
)
log = logging.getLogger("logtool")

log.debug("debug 看不到")
log.info("info 也看不到")
log.warning("warning 看得到")
log.error("error 看得到")
log.critical("critical 看得到")
print()
print("有效级别:", log.getEffectiveLevel())
WARNING  | logtool | warning 看得到
ERROR    | logtool | error 看得到
CRITICAL | logtool | critical 看得到

有效级别: 30
level 是一条水位线：低于它的日志连字符串都不会拼，直接在源头被丢掉。所以 log.debug(f"...{很贵的计算}...") 只写 DEBUG 是不会拖慢正式运行的——但写成 log.debug("..." + 很贵的计算()) 就会，因为参数先算完才进函数。

format 里最常用的四个占位符

占位符出来是什么备注
%(levelname)sWARNING-8s = 左对齐补到 8 格，日志才会成列
%(name)slogtool哪个 logger 打的，拆模块后特别有用
%(message)s你写的那句话唯一必写的
%(asctime)s2026-11-13 02:49:46排查线上问题才加，学习笔记里别加，否则输出每次都不同
%(asctime)s 和 %(lineno)d 会让输出不可复现。写学习笔记、贴示例输出时删掉这两项，不然你没法判断「这次输出和上次是不是一样」。

4logging 的三个坑，每个我都踩过

坑一：basicConfig 只生效一次

第二次调用不会报错、不会警告，什么都不会发生。这就是「我明明设了 DEBUG，怎么还是看不见」的原因。

import logging
import sys

logging.basicConfig(level=logging.INFO,
                    format="%(levelname)-8s | %(message)s",
                    stream=sys.stdout)
logging.getLogger("logtool").info("第一次配置：INFO 级别生效")

# 第二次调用：所有参数都被忽略
logging.basicConfig(level=logging.DEBUG,
                    format=">>> %(message)s",
                    stream=sys.stdout)
log = logging.getLogger("logtool")
log.info("第二次 basicConfig 被忽略，格式还是第一次的")
log.debug("级别也没变成 DEBUG，这行不显示")
print()
print("根 logger 上的 handler 数量:", len(logging.getLogger().handlers))

INFO     | 第二次 basicConfig 被忽略，格式还是第一次的

根 logger 上的 handler 数量: 1
所以配置要放在程序最早的地方，且只放一次。被 import 的模块里绝对不要调 basicConfig——谁先 import 谁说了算，行为取决于 import 顺序，这种 bug 极难查。
模块里只写 log = logging.getLogger(__name__)，配置交给入口文件。

5拼装：从日志文本到一份报告

前几天的零件一个都不用改，只要按下面的顺序串起来。关键是中间那步——先把结果算成一个 dict，最后才决定怎么打印。

argv ──parse_args──▶ args （谁来跑、跑什么、跑多细） args ──load──────▶ rows, bad （正则解析，坏行单独记） rows ──build─────▶ d: dict ★ 与打印方式无关的「事实」 d ──render_*──▶ 字符串 ──print──▶ stdout
import re
from collections import Counter

LINE = re.compile(
    r'(?P<ip>\d{1,3}(?:\.\d{1,3}){3})'
    r' - - '
    r'\[(?P<time>[^\]]+)\]'
    r' "(?P<method>[A-Z]+) (?P<path>\S+) HTTP/[\d.]+"'
    r' (?P<status>\d{3})'
    r' (?P<size>\d+)'
)

RAW = """10.0.0.7 - - [12/Nov/2026:09:01:11 +0800] "GET /api/user HTTP/1.1" 200 512

10.0.0.11 - - [12/Nov/2026:14:05:30 +0800] "GET /api/detail HTTP/1.1" 404 87"""


def parse_line(line):
    m = LINE.match(line)
    if not m:
        return None
    d = m.groupdict()
    d["status"] = int(d["status"])
    d["size"] = int(d["size"])
    return d


def load(text):
    rows, bad = [], []
    for i, line in enumerate(text.splitlines(), 1):
        if not line.strip():
            continue
        rec = parse_line(line)
        rows.append(rec) if rec else bad.append(i)
    return rows, bad


def top_n(counter, n):
    # 次数降序，次数相同按名字升序 —— 少了第二关键字，顺序就不固定
    return sorted(counter.items(), key=lambda kv: (-kv[1], kv[0]))[:n]


def report(rows, bad, n=3):
    ips = Counter(r["ip"] for r in rows)
    paths = Counter(r["path"] for r in rows)
    codes = Counter(r["status"] for r in rows)
    errors = sum(c for s, c in codes.items() if s >= 400)
    out = [f"文件共 {len(rows) + len(bad)} 行，解析成功 {len(rows)} 行，坏行 {len(bad)} 行"]
    if bad:
        out.append(f"坏行行号：{bad}")
    out.append("")
    out.append(f"Top {n} IP")
    for ip, c in top_n(ips, n):
        out.append(f"  {ip:<12}{c:>4}  {c / len(rows):>6.1%}")
    out.append(f"Top {n} URL")
    for p, c in top_n(paths, n):
        out.append(f"  {p:<18}{c:>4}")
    out.append("状态码")
    for s, c in sorted(codes.items()):
        out.append(f"  {s}  {c:>4}")
    out.append(f"错误率 {errors / len(rows):.1%}（{errors}/{len(rows)}）")
    return "\n".join(out)


rows, bad = load(RAW)
print(report(rows, bad))

看第 2 行和第 3 行：10.0.0.11 排在 10.0.0.9 前面。两次都是 2 次请求，凭什么它在前？因为第二排序键是字符串，"10.0.0.11" < "10.0.0.9"（逐字符比，1 比 9 小）。
字符串比较下 "10.0.0.11" 反而「更小」，这跟直觉相反但完全一致——只要规则固定，这个顺序就是可复现的。想按 IP 真实大小排，得用第 8 节第 5 题的办法。
为什么一定要有第二排序键？没有它，sorted 对相等元素的先后不做任何承诺，这次跑出 A 在前、下次可能 B 在前。你贴进笔记的输出、写进测试的断言，全都会随机失败。任何「Top N」都必须有确定的 tie-break 规则。

7错误处理：三种死法，三种交代

工具给人用，就得替人想到「他可能会做错什么」。这一节只有三件事：检查、报错、给出退出码。

import contextlib
import io
import re
import sys
from pathlib import Path

LINE = re.compile(
    r'(?P<ip>\d{1,3}(?:\.\d{1,3}){3})'
    r' - - '
    r'\[(?P<time>[^\]]+)\]'
    r' "(?P<method>[A-Z]+) (?P<path>\S+) HTTP/[\d.]+"'
    r' (?P<status>\d{3})'
    r' (?P<size>\d+)'
)

GOOD = '10.0.0.7 - - [12/Nov/2026:09:01:11 +0800] "GET /api/user HTTP/1.1" 200 512\n'


def load(text):
    rows = []
    for line in text.splitlines():
        m = LINE.match(line)
        if m:
            rows.append(m.groupdict())
    return rows


def run(path):
    p = Path(path)
    if not p.exists():
        print(f"错误：找不到文件 {path}", file=sys.stderr)
        return 1
    rows = load(p.read_text(encoding="utf-8"))
    if not rows:
        print(f"错误：{path} 里一行都没解析出来", file=sys.stderr)
        return 1
    print(f"成功：{path} 解析出 {len(rows)} 行")
    return 0


Path("ok.log").write_text(GOOD, encoding="utf-8")

8练习：在能跑的工具上继续加东西

八道题全部基于第 7 节的 logtool.py。样例数据就用第 5 节那 8 行（7 行能解析、1 行坏行），所以每道题的预期数字都能自己核对。

  1. 加一个 --min-status N：只统计状态码 ≥ N 的请求。跑 --min-status 400 应该只剩 3 条。想清楚过滤该放在 build() 之前还是之后。
  2. 加 -o/--output FILE：把报告写进文件，不传就照旧打到屏幕。做完顺手验证 python logtool.py access.log -o r.txt 之后屏幕上还剩什么。
  3. 把 -q 换成三档：默认 INFO，-v 变 DEBUG，-q 变 WARNING。用 action="count" 让 -vv 也能用。
  4. 让 -q 和 -v 互斥。验证同时给时退出码是 2，并检查你写的帮助信息里有没有出现 [-q | -v]。
  5. 修第 5 节那个「10.0.0.11 排在 10.0.0.9 前面」的问题，改成按 IP 真实数值排序。注意 top_n 同时被 IP 和 URL 用着，改之前先想会不会把 URL 那边弄炸。
  6. 加日志文件：终端和 logtool.log 同时输出。要求两边格式一致，且 -q 时文件里也不该有 INFO。
  7. 把 errors="replace" 改成默认的 strict，然后造一个 GBK 编码的日志文件去读它。看到 UnicodeDecodeError 之后，写一个能自动试编码的函数把这个问题真正解决掉。
  8. 加 --by-hour：按小时分组统计请求数。样例日志应该输出 09 点 5 条、14 点 2 条。时间字段长这样：12/Nov/2026:09:01:11 +0800，想清楚取哪一段。

参考答案 6 · 终端 + 文件双输出 
def setup_log(quiet):
    level = logging.WARNING if quiet else logging.INFO
    fmt = logging.Formatter("%(levelname)-8s | %(message)s")

    fh = logging.FileHandler("logtool.log", encoding="utf-8")
    fh.setFormatter(fmt)
    sh = logging.StreamHandler(sys.stderr)
    sh.setFormatter(fmt)

    # ★ 一旦传了 handlers，format / stream 这两个参数就被忽略
    logging.basicConfig(level=level, handlers=[fh, sh])
    return logging.getLogger("logtool")

三个必须知道的点：

  • 传了 handlers=[...] 之后，format= 和 stream= 会被静默忽略——格式得自己 setFormatter 到每个 handler 上。这也是「配了格式却不生效」的常见原因。
  • FileHandler 必须写 encoding="utf-8"，否则在中文 Windows 上按 GBK 写，换台机器打开就是乱码。
  • level 设在 logger 上（这里是 basicConfig 的 level），是总闸；handler 上还可以再各设一个 setLevel，是分闸。想「终端只留 WARNING、文件全留」就靠分闸，别把一个 level 用到底。

验证 -q：python logtool.py access.log -q 之后 logtool.log 里应该只有 WARNING 那一行——因为 INFO 在总闸就被拦掉了，两个 handler 谁都收不到。

修法：按可能性从高到低逐个试，第一个能解开的就用它。

def read_text(path):
    data = Path(path).read_bytes()
    for enc in ("utf-8-sig", "utf-8", "gbk"):
        try:
            return data.decode(enc)
        except UnicodeDecodeError:
            continue
    raise ValueError(f"{path} 编码认不出来，请手动指定")


# 顺带解决 D016 那个 BOM 问题：utf-8-sig 会把 BOM 吃掉，
# 所以用它的返回值的首行不会是 "\ufeffip,count"
def read_csv_text(path):
    return read_text(path).splitlines()[0]

为什么不直接用 errors="ignore"？因为它会静默删掉解不开的字节——4 个汉字可能只剩 1 个字符，日志里 IP 还在、URL 变半个，报表看着挺正常，实际全错。宁可报错，也别静默出错。

注意先 read_bytes() 再 decode()：read_text() 会在读的瞬间就按给定编码解码，解不开直接抛，没法在里面换编码重试。

## argparse 三种形态
位置参数  add_argument("path")                     args.path
选项带值  add_argument("-n","--top",type=int)      args.top   ★名字取长选项
开关      add_argument("-q",action="store_true")   args.quiet
选择      add_argument("--format",choices=[...])
计数      add_argument("-v",action="count",default=0)   ★default 不写是 None

## argparse 替你做的三件事
校验（缺参 / 类型 / choices / 互斥）→ 报错到 stderr → 退出码 2
-h 自动生成 → 退出码 0
★ 退出码分工：0 成功 / 1 业务失败 / 2 用法错误（2 是 argparse 专用）
★ 生产代码别 except SystemExit；argv=None 的形参是留给测试的

## logging 五个级别
DEBUG 10  INFO 20  WARNING 30  ERROR 40  CRITICAL 50
★ level 是水位线，低于它的连字符串都不拼

## logging 三行配置
basicConfig(level=..., format="%(levelname)-8s | %(message)s", stream=sys.stderr)
★ -8s 左对齐补 8 格，日志才成列
★ 别加 %(asctime)s：输出就不可复现了

## 三个坑
1 basicConfig 只生效一次，第二次静默忽略 → 只在入口调一次
  被 import 的模块里只写 getLogger(__name__)
2 不配置时默认 WARNING，info 全丢，格式也没有
3 logger 是树：logtool.report 的父级是 logtool，消息向上冒泡
  → 根配好了，子 logger 自动有格式

## 为什么不用 print
给排错看的过程 → log；给人看的结果 → print
日志走 stderr，结果走 stdout
→ python x.py > report.txt 得到的只有干净正文

## 拼装顺序（今天最重要的一页）
parse_args → load(rows, bad) → build(dict) → render_* → print
★ 先算成 dict，最后才决定怎么打印：换格式不用动中间逻辑
★ 过滤在 build 之前：换的是数据，不是打印方式
★ Top N 必须有第二排序键，否则顺序随机
★ "10.0.0.11" < "10.0.0.9"（字符串比较），要真实大小得用 ip_address
★ 共用的函数别写死某一种数据的规则，用 key= 从外面传

## 出口一行
if __name__ == "__main__":
    sys.exit(main())
★ 不写 sys.exit()，return 1 就只是被丢掉的值，进程照样退 0
