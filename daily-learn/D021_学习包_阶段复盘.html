2自测十题：先说出输出，再点开对答案

全部是这三周出现过的坑。每题先在心里（或在纸上）说出输出，再点开。十题对八题以上，阶段一就算过。

第 1 题 · 默认参数

def f(x, box=[]):
    box.append(x)
    return box

print(f(1), f(2))
答案 
[1, 2] [1, 2]

默认值在函数定义时求值一次，之后所有调用共用同一个 list。第二次调用时 box 已经是 [1] 了。
改法：def f(x, box=None): box = [] if box is None else box。

第 2 题 · 切片

s = "Python"
print(s[::-1], s[1:4], s[-2:])
答案 
nohtyP yth on

[::-1] 是步长 −1，从尾到头；[1:4] 是下标 1、2、3（不含 4）；[-2:] 是最后两个字符。

第 3 题 · == 与 is

a = [1, 2]
b = [1, 2]
c = a
print(a == b, a is b)
print(c is a, c is b)
答案 
True False
True False

== 比内容，is 比是不是同一块内存。a 和 b 内容一样但两个对象；c = a 只是多了一个名字指向同一个对象。
实践：只对 None、True、False 用 is，其余一律 ==。数字和小字符串的 is 结果取决于实现细节，别依赖。

第 4 题 · 闭包与延迟绑定

fs = [lambda: i for i in range(3)]
print([f() for f in fs])

fs2 = [lambda i=i: i for i in range(3)]
print([f() for f in fs2])
答案 
[2, 2, 2]
[0, 1, 2]

lambda 里引用的 i 是变量名，不是当时的值；循环结束后 i 已经是 2，三个函数看到的是同一个 2。
第二行用 i=i 把当前值绑成默认参数，就固定住了。这个坑在 D012/D013 都出现过。

第 5 题 · 生成器只能走一次

g = (x * x for x in range(3))
print(list(g))
print(list(g))
答案 
[0, 1, 4]
[]

生成器是一次性的：走完就空了，第二次 list() 拿不到任何东西，也不报错。不报错是它最危险的地方——你会以为「没有数据」，其实是「已经用掉了」。
要重复用就存成 list：squares = [x * x for x in range(3)]。

第 6 题 · try/finally 与 return

def f():
    try:
        return "try 里的值"
    finally:
        print("finally 先跑")

print(f())
答案 
finally 先跑
try 里的值

finally 在 return 之后、函数真正返回之前执行。所以打印顺序是 finally 在前、返回值在后。
推论：别在 finally 里 return，它会吃掉 try 里准备好的返回值。

第 7 题 · 类属性

class A:
    n = 0
    def __init__(self):
        A.n += 1

A()
A()
print(A.n)
答案 
2

A.n += 1 写的是类属性，所有实例共享，所以两次实例化累加到 2。
如果写成 self.n += 1，Python 会先读类属性 0、再加 1，然后创建一个实例属性 n=1 盖住类属性——A.n 永远是 0。这一条是 D008 里最容易被记反的。

第 8 题 · dataclass 的可变默认值

from dataclasses import dataclass, field

@dataclass
class Item:
    tags: list = field(default_factory=list)

a, b = Item(), Item()
a.tags.append("x")
print(a.tags, b.tags)
答案 
['x'] []

field(default_factory=list) 让每个实例各自新建一个空 list，所以 b 不受影响。
写成 tags: list = [] 会直接报 ValueError: mutable default ... use default_factory——dataclass 替你挡住了第 1 题那个坑，这也是它值得用的理由之一。

第 9 题 · match / search / fullmatch

import re

print(re.match(r"\d+", "abc123"))
print(re.search(r"\d+", "abc123").group())
print(re.fullmatch(r"\d+", "123").group())
答案 
None
123
123

match 只从开头试，"abc123" 开头是字母，直接 None；search 扫全文；fullmatch 要求整串都匹配。
校验数据用 fullmatch（match 不管结尾，"123abc" 用 match 也会成功）。

第 10 题 · 协程只是「声明」

import asyncio

async def hello():
    return "hi"

c = hello()
print(type(c).__name__)
print(asyncio.run(c))
答案 
coroutine
hi

async def 只是把函数变成「协程函数」，调用它不执行函数体，只返回一个协程对象——真正的执行发生在 await 或者 asyncio.run() 的时候。
所以只加 async/await 并不会变快：顺序 await 三次 0.2 秒仍然是 0.6 秒，得用 gather 才算并发。

3概念十问：能不能一句话说清

这十问没有代码，全是「你以为是 A，其实是 B」。先自己答，再点开。

1. r"\bword" 和 "\bword" 有什么区别？

r 前缀让反斜杠保持字面。不加 r 时 "\b" 是退格符（一个不可见字符，长度 1），所以 "\bword" 长度是 5；r"\bword" 长度是 6，才是正则里的「单词边界」。
写正则一律加 r，不用想。

2. 校验一个 IP 格式，用 match 还是 fullmatch？

fullmatch。match 只管起点，"1.2.3.4; rm -rf /" 用 match(r"\d+\.\d+\.\d+\.\d+") 也会成功——它不关心后面还有没有脏东西。

3. open() 不写 encoding 有什么风险？

会按系统默认编码打开：Windows 中文版是 GBK，macOS/Linux 是 UTF-8。同一份文件在两台机器上读出不同结果，甚至抛 UnicodeDecodeError。
永远显式写 encoding="utf-8"。

4. 什么时候用线程池，什么时候用进程池？

等 IO（网络、磁盘、数据库）用线程池，等的时候 GIL 会释放，能重叠。纯计算用进程池，但要看单任务有多大：本机实测 4M 次循环 × 2，单线程 0.80 秒、线程池 2 线程 0.70 秒、进程池 2 进程 1.27 秒——启动进程的成本比省下的时间还多。
结论：进程池单任务超过 0.5 秒才划算，别凭感觉加。

5. asyncio.gather 的结果顺序按什么排？

按你传进去的顺序，不是完成顺序。想按完成顺序处理，用 asyncio.as_completed。
这一条极易记反，因为名字里有个「gather（收集）」，感觉像是「谁先回来谁在前」。

6. 调用两次 logging.basicConfig() 会怎样？

第二次完全无效，且不报错不警告。根 logger 上已经有 handler 了，basicConfig 就直接返回。
所以配置只放在入口文件里，且只调一次；被 import 的模块里只写 getLogger(__name__)。

7. 退出码 0 / 1 / 2 分别代表什么？

0 成功；1 业务失败（文件不存在、数据全坏）；2 用法错误（argparse 专用，别自己占）。
shell 脚本和 CI 靠这个数字判断成败，一律 exit 1 等于放弃了这门语言。

8. 写了 return 1 但没写 sys.exit(main())，会怎样？

进程照样退 0。return 的值只是回到了调用者手里，没写 sys.exit() 就没人把它交给操作系统。
表现是「明明失败了，脚本却继续往下跑」——在 bash 里用 set -e 或 && 串命令时特别坑。

9. 用 list 做函数默认值为什么危险？

默认值只在定义时创建一次，之后所有调用共用。往里 append 的东西会跨调用累积，而且这种 bug 在小数据量下看不出来，跑一天之后才爆。
改法：默认写 None，进函数再 if x is None: x = []。

10. errors="ignore" 解码为什么不能用？

它会静默丢掉解不开的字节：4 个汉字的 GBK 内容按 UTF-8 读，可能只剩 1 个字符，不报错、不提示。
报表里 IP 还在、URL 变半个，看着挺正常，实际全错。要么报错，要么显式试多种编码——但不许静默。
