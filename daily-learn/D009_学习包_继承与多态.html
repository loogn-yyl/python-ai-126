1继承解决的是「重复」

先看没有继承时是什么样子——两个图形类，各写各的：

import math

class Circle:
    def __init__(self, r):
        self.r = r

    def area(self):
        return math.pi * self.r ** 2

    def describe(self):
        return f"圆，面积 {self.area():.2f}"


class Rect:
    def __init__(self, w, h):
        self.w = w
        self.h = h

    def area(self):
        return self.w * self.h

    def describe(self):
        return f"矩形，面积 {self.area():.2f}"


for s in [Circle(2), Rect(3, 4)]:
    print(s.describe())
圆，面积 12.57
矩形，面积 12.00

两个类里，describe() 几乎一模一样，只有名字不同。这就是继承要解决的问题：把共用的部分提到父类，子类只写不同的部分。

import math

class Shape:
    def __init__(self, name):
        self.name = name

    def area(self):
        raise NotImplementedError("子类必须实现 area()")

    def describe(self):
        return f"{self.name}，面积 {self.area():.2f}"


class Circle(Shape):
    def __init__(self, r):
        super().__init__("圆")
        self.r = r

    def area(self):
        return math.pi * self.r ** 2


class Rect(Shape):
    def __init__(self, w, h):
        super().__init__("矩形")
        self.w = w
        self.h = h

    def area(self):
        return self.w * self.h


for s in [Circle(2), Rect(3, 4)]:
    print(s.describe())

print(isinstance(Circle(2), Shape))
print(type(Circle(2)) is Shape)
圆，面积 12.57
矩形，面积 12.00
True
False

多了三行 class Shape:，两个子类各自少了一半代码，而且 describe() 只有一份。以后想给所有图形加一个「打印带边框」的版本，只改父类一处。

概念代码里的样子说明
父类 / 基类class Shape:被继承的那个，放共用的东西
子类class Circle(Shape):括号里写父类，自动拥有父类的所有方法
继承子类不用重写 describe() 也能调用找不到就往父类找，一层层往上是 D005 的 LEGB 的同类思路
重写 override子类里再写一遍同名方法子类的版本优先，父类的被盖住
C 里没有这个东西，但你有类似的直觉。结构体里嵌一个结构体struct Circle { struct Shape base; double r; }; 就是在手动模拟继承：把公共部分放在开头，describe 只写一次、靠传不同的指针区分。Python 把这个机制做进了语言本身，并且会自动处理「子类的 self 传进去，父类的方法也能用」。

2super()：先让父类把自己初始化好

子类写了 __init__，父类的 __init__ 就不会自动执行了。必须自己调一次，否则父类存的属性全都不存在。

class A:
    def __init__(self):
        self.trace = ["A"]


class B(A):
    def __init__(self):
        super().__init__()          # 推荐写法：不用写父类名字
        self.trace.append("B")


class C(A):
    def __init__(self):
        A.__init__(self)            # 也能跑，但父类改名时要跟着改
        self.trace.append("C")


class D(A):
    def __init__(self):
        self.trace = []             # 忘了调父类的 __init__


print("B:", B().trace)
print("C:", C().trace)
print("D:", D().trace)
B: ['A', 'B']
C: ['A', 'C']
D: []
类写法结果
Bsuper().__init__()['A', 'B'] —— 父类先跑，子类后加
CA.__init__(self)['A', 'C'] —— 结果一样，但写死了父类名
D没调用[] —— 父类什么都没初始化
D 那种写法不会报错，只是少了东西。等到某处访问父类才有的属性时，才会在完全不相干的地方抛 AttributeError。继承链越长，这种错越难查。

纪律：子类只要写了 __init__，第一行就是 super().__init__(...)。
为什么推荐 super() 而不是 A.__init__(self)：前者在父类改名、多重继承时都自动正确；后者写死了名字，而且 D009 最后讲的 MRO 里，它会破坏继承链的传递。

3多态：一行代码，三种行为

这是继承真正值钱的地方。

import math

class Shape:
    def __init__(self, name):
        self.name = name

    def area(self):
        raise NotImplementedError

    def describe(self):
        return f"{self.name}，面积 {self.area():.2f}"


class Circle(Shape):
    def __init__(self, r):
        super().__init__("圆")
        self.r = r

    def area(self):
        return math.pi * self.r ** 2


class Rect(Shape):
    def __init__(self, w, h):
        super().__init__("矩形")
        self.w, self.h = w, h

    def area(self):
        return self.w * self.h


class Triangle(Shape):
    def __init__(self, a, b, c):
        super().__init__("三角形")
        self.a, self.b, self.c = a, b, c

    def area(self):
        s = (self.a + self.b + self.c) / 2
        return math.sqrt(s * (s - self.a) * (s - self.b) * (s - self.c))


# 新增 Triangle 之后，这一行代码一个字都没改
for s in [Circle(2), Rect(3, 4), Triangle(3, 4, 5)]:
    print(s.describe())

shapes = [Circle(10), Rect(3, 4), Triangle(3, 4, 5)]
print("最大的是:", max(shapes, key=lambda x: x.area()).name)
圆，面积 12.57
矩形，面积 12.00
三角形，面积 6.00
最大的是: 圆

注意最后那个循环和 max()——加 Triangle 的时候，它们一个字都没改。循环里只写了 s.describe()，它怎么知道该用哪个 area()？

它是「在运行时才决定的」。s 实际指向谁，就调用谁的方法——这就是多态。

换成 C 你大概会这么写：一个 enum 标记类型 + 一个 switch 分发，每加一种图形都要回去改那个 switch，而且改了要重新验证所有分支。Python 这里加一个子类就完事，调用方不需要知道有几种图形。这是从「用 C 写」到「用面向对象写」最大的一次思维转变。
写法加一种新图形要改哪里
if isinstance(s, Circle): ... elif ...改那个 if 链（所有分支都动过）
s.describe()什么都不用改，加个新类就行

4抽象基类：强制子类实现

上一节 Shape.area() 里写的是 raise NotImplementedError，这是靠自觉——忘了实现，要到调用时才炸。用 abc 可以把这个检查提前到造对象那一刻。

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        ...

class Circle(Shape):
    def __init__(self, r):
        self.r = r

    def area(self):
        return 3.14 * self.r ** 2

class Bad(Shape):
    pass

print(Circle(2).area())
Bad()
12.56
Traceback (most recent call last):
  ...
TypeError: Can't instantiate abstract class Bad without an implementation
for abstract method 'area'

三处变化：

代码作用
from abc import ABC, abstractmethod标准库，不用装
class Shape(ABC):继承 ABC，这个类就变成了抽象基类
@abstractmethod标在方法上：子类必须实现它，否则不许造对象

效果很直接：Bad 没实现 area，于是 Bad() 直接抛 TypeError，连对象都造不出来；而 Circle 实现了，正常使用。

什么时候用：父类只定义「必须有这个东西」，但不打算给它任何实现。
什么时候不用：父类自己就有一份能用的通用实现（比如 describe()），那就别标 @abstractmethod，让子类直接用。上一节的 Shape 就属于这种混合情况——area 抽象、describe 有实现。
Python 3.12 的报错原文是 Can't instantiate abstract class Bad without an implementation for abstract method 'area'；3.11 及更早写的是 with abstract method area。同一件事，措辞不同，别以为是两种错。

5MRO：继承链上先找谁

子类没写某个方法时，Python 会沿着继承链往上找。多个父类时，顺序是算出来的，不是随便排的。

class A:
    def who(self):
        return "A"

class B(A):
    def who(self):
        return "B"

class C(A):
    def who(self):
        return "C"

class D(B, C):
    pass

print([k.__name__ for k in D.__mro__])
print(D().who())
['D', 'B', 'C', 'A', 'object']
B

D.__mro__ 就是查找顺序，读法是从左到右：D → B → C → A → object。所以 D().who() 找到的是 B 的版本——先写的父类优先。

细节说明
object 也在里面所有类最终都继承 object，它是继承链的根
同名方法取最近的那个B 比 C 先，所以是 B
菱形继承不会重复走B 和 C 都继承 A，A 在链里只出现一次
多重继承是 Python 里容易被滥用的特性。真实项目里 95% 的情况是单继承；需要「同时具备多种能力」时，更常见的是用多个小类拼（mixin）。你现在只需要知道__mro__ 怎么读，能看懂报错里那个顺序就够了。
# 想确认任何类的查找顺序，随时 print 一下
print(D.__mro__)
print(Circle.__mro__)

6组合优于继承：通讯录里该用哪种

继承不是「面向对象就要用」。判断标准只有一句：子类是不是父类的一种。

关系例子该用
is-a（是一种）圆 是一种图形；矩形 是一种图形继承
has-a（有一个）通讯录 有一个字典；一个人 有一个地址组合

通讯录 v2 里 Contact 和 AddressBook 没有任何「是一种」的关系，所以不该继承。看看硬要继承会怎样：

class Contact:
    def __init__(self, name):
        self.name = name


class AddressBook:                 # 组合：把字典装进来
    def __init__(self):
        self.items = {}

    def add(self, contact):
        self.items[contact.name] = contact

    def names(self):
        return sorted(self.items)


class BadBook(dict):               # 继承：自己也变成了一个字典
    def add(self, contact):
        self[contact.name] = contact


b = AddressBook()
b.add(Contact("张三"))
b.add(Contact("李四"))
print(b.names())
print(hasattr(b, "clear"))

d = BadBook()
d.add(Contact("张三"))
d["随便塞一个"] = "我不是联系人"     # 字典的方法全都暴露出来了
print(sorted(d.keys()))
['张三', '李四']
False
['张三', '随便塞一个']

BadBook(dict) 把自己变成了一个字典，于是字典的全部方法都暴露出来了——包括 clear()、pop()、[]= 直接塞任意值。上面那行 d["随便塞一个"] = "我不是联系人" 就成功了，绕过了你辛苦写的 add() 里的所有校验。

这就是「继承太强」。组合的 AddressBook 里，items 是私有的内部细节，外面只能通过 add() 动它，校验跑不掉。（hasattr(b, "clear") 是 False，说明它根本没有这个方法。）
一句话记住：想「复用代码」用组合，想「替换实现」用继承。今天写的 Shape/Circle 是前者吗？不，是后者——调用方只认 area() 这个接口，具体怎么算由子类决定。这才是继承的正当用法。

# D009 笔记

## 继承
- class 子类(父类):           子类自动拥有父类所有方法
- 子类写 __init__ 时，第一行必须 super().__init__(...)
- 不写 super 不会报错，只是父类的属性全都不存在 → 以后在别处 AttributeError
- 方法重写：子类再写一遍同名方法，子类的优先

## 多态
- s.describe() 调用哪个版本，看 s 实际是谁，不看变量声明成什么
- 加新子类不用改调用方 —— 这是继承最大的价值
- 反例：if isinstance(...) 一长串，每加一种都要改

## 抽象基类
- from abc import ABC, abstractmethod
- class Shape(ABC):  @abstractmethod def area(self): ...
- 子类没实现就造不出对象 → TypeError，把错误提前到最早的时刻
- 有通用实现的父类方法不要标 abstractmethod

## MRO
- D.__mro__ 就是查找顺序，从左到右，最后一定是 object
- class D(B, C) → 先 B 后 C，B 的方法优先
- 菱形继承里 A 只出现一次

## 继承还是组合
- is-a（圆是一种图形）→ 继承
- has-a（通讯录有一个字典）→ 组合
- 继承 dict/list 会把它们的全部方法暴露出去，绕过你自己的校验
- 想复用代码用组合，想替换实现用继承

## C 对比
- struct 嵌套模拟继承              vs  class Circle(Shape)
- enum + switch 分发              vs  直接 s.area()
- 改了 switch 要重测所有分支        vs  加子类不动调用方
