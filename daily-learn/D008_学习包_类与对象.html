1class 是什么：从字典到对象

D003 你用字典存一个人的信息，D007 用它做了通讯录。{"name": "张三", "phone": "138..."} 这个写法能用，但它有一个根本问题：字典不知道「一个人应该有哪几个字段」。

今天换一种存法：

# D007 的写法：一个字典
c = {"name": "张三", "phone": "13800001111"}
print(c["name"], c["phone"])

# 今天：一个类
class Contact:
    def __init__(self, name, phone):
        self.name = name
        self.phone = phone

c = Contact("张三", "13800001111")
print(c.name, c.phone)
张三 13800001111
张三 13800001111

两段输出一模一样。那为什么要换？因为下面这张表里的事，字典做不到：

能力字典 {name: ..., phone: ...}类 Contact(...)
字段有没有定义没有。随便往里塞 key，谁也不知道标准字段是哪几个有，全写在 __init__ 里
拼错字段名c["nmae"] 到运行时才报 KeyError访问时就报 AttributeError，且 IDE 会自动补全
带自己的行为只能写 show(c) 这种外部函数c.line()，动作和数据在一起
加一个字段每个用到它的函数都要改改 __init__ 一处，缺的字段自动有默认值
C 里你已经见过这件事。struct Contact { char name[32]; char phone[16]; }; 定义的是一个形状，然后你写 void show(struct Contact *c) 来操作它。Python 的 class 把「形状」和「操作它的函数」装在了一起，并且额外送你默认值、继承、运算符重载——D009 到 D010 会一个个见到。

2__init__ 与 self

一个类里最重要的两样东西，第一天就要弄清楚。

class Contact:
    def __init__(self, name):
        self.name = name

    def hello(self):
        return f"我是 {self.name}"

a = Contact("张三")
b = Contact("李四")
print(a.hello())
print(b.hello())
print(a is b)
print(a.name, b.name)
我是 张三
我是 李四
False
张三 李四

逐行看这段发生了什么：

代码发生了什么
class Contact:定义了一个模板，此时还没有任何对象
a = Contact("张三")调用模板造出一个对象；() 会自动去找 __init__
def __init__(self, name)对象的初始化方法，造对象时自动执行，不用手动调
self.name = name把参数存到这个对象自己身上
def hello(self)实例方法，调用时 a.hello() 会自动把 a 传给 self
a is b两个独立对象，所以是 False
self 不是关键字，只是约定俗成的第一个参数名。写成 def __init__(this, name): this.name = name 一样能跑，但全世界的 Python 代码都写 self，你改了就没人看得懂。就像 C 里 for (int i = 0; ...) 的 i，没人规定必须叫 i。

少写 self 会怎样

class Bad:
    def __init__(name):        # 少写了 self
        self.name = name

Bad("张三")
TypeError: Bad.__init__() takes 1 positional argument but 2 were given

报错说「只要 1 个参数却给了 2 个」，看着莫名其妙——你明明只传了 "张三" 一个。原因是 Bad("张三") 这一步自动把新对象当第一个参数塞进去了，而你的 __init__ 只有一个名叫 name 的坑位，接收 "张三" 之后就多出来一个。

看到 takes 1 positional argument but 2 were given，第一反应就是「方法少写了 self」。这是 Python 新手报错频率最高的一条，比 C 里的 expected ';' before '}' 还常见。

3实例属性、以及一个和 C 一致的坑

D003 学过「列表赋值不是复制，是指向同一个对象」。类的对象完全一样，而且更危险——因为它看起来像一个值。

class Contact:
    def __init__(self, name, phone):
        self.name = name
        self.phone = phone

a = Contact("张三", "13800001111")
b = a                       # 不是复制，是给同一个对象再起一个名字
b.name = "李四"
print(a.name, a is b)

c = Contact("李四", "13800001111")
print(a == c, a is c)
李四 True
False False

改了 b.name，a.name 也变了，因为 a 和 b 是同一个对象的两个名字。而 a == c 是 False——它们内容完全一样却不相等，因为默认的 == 比的是「是不是同一个对象」，和 is 一个意思。这不是 bug，是还没教它怎么比。D010 会用 __eq__ 把这件事改掉。

直接 print 一个对象

class Contact:
    def __init__(self, name):
        self.name = name

print(Contact("张三"))
<__main__.Contact object at 0x102a3c350>

这行 <__main__.Contact object at 0x...> 是 Python 的默认打印方式：类名 + 内存地址，和 C 里 printf("%p", p) 输出一个指针值是一个性质。地址每次运行都不同，所以它不是给人看的。D010 的 __str__ 就是专门解决这个的。

4类属性 vs 实例属性

属性有两种存放位置：放在每个对象身上，还是放在类上被所有对象共用。

class Contact:
    count = 0                       # 类属性：所有实例共用一份

    def __init__(self, name):
        self.name = name            # 实例属性：每个对象各有一份
        Contact.count += 1          # 注意：要改类属性，得写类名

a = Contact("张三")
b = Contact("李四")
print(Contact.count, a.count, b.count)

a.count = 100                       # 这一句新建了 a 自己的实例属性
print(Contact.count, a.count, b.count)
2 2 2
2 100 2

关键在于最后两行：a.count = 100 并没有修改类属性，它给 a 新建了一个同名实例属性，把这个类属性「遮住」了。所以 Contact.count 和 b.count 还是 2，只有 a.count 变成 100。

读的时候有顺序：先找实例属性，找不到再找类属性。写的时候永远写在你指定的那一层——a.count = 100 写实例，Contact.count = 100 写类。
要改类属性必须写类名：Contact.count += 1。写成 self.count += 1 就变成了给这个实例新建属性，计数器永远不会涨——这个 bug 不报错，只是数字不对。

更隐蔽的一种：可变类属性

class Contact:
    tags = []                       # 类属性是可变对象 → 所有实例共用一个列表

    def __init__(self, name):
        self.name = name

a = Contact("张三")
b = Contact("李四")
a.tags.append("同学")
print(a.tags, b.tags, Contact.tags)
['同学'] ['同学'] ['同学']
给张三加的标签，李四也看见了。因为 tags = [] 只在类定义时创建一次，所有实例共用这一个列表——和 D005 的 def f(x=[]) 是同一个坑，只是换了个位置。

规则：类属性只放不可变的东西（数字、字符串、元组）。列表、字典、集合这类，一律在 __init__ 里用 self.tags = [] 创建。

构造函数里的可变默认参数，同样的病，同样的药：

class Bad:
    def __init__(self, tags=[]):        # 可变默认参数
        self.tags = tags

a = Bad()
a.tags.append("同学")
b = Bad()
print(a.tags, b.tags, a.tags is b.tags)


class Good:
    def __init__(self, tags=None):
        self.tags = [] if tags is None else tags

a = Good()
a.tags.append("同学")
b = Good()
print(a.tags, b.tags, a.tags is b.tags)
['同学'] ['同学'] True
['同学'] [] False

5类方法与静态方法

类里能写三种方法，区别只在第一个参数收到什么。

class Contact:
    total = 0

    def __init__(self, name, phone):
        self.name = name
        self.phone = phone
        Contact.total += 1

    @classmethod
    def from_text(cls, line):
        """从 '张三,13800001111' 这样的一行构造对象"""
        name, phone = line.split(",")
        return cls(name.strip(), phone.strip())

    @staticmethod
    def is_phone(s):
        """纯校验，不需要 self 也不需要 cls"""
        return s.isdigit() and len(s) == 11

c = Contact.from_text("张三, 13800001111")
print(c.name, c.phone, Contact.total)
print(Contact.is_phone("13800001111"), Contact.is_phone("abc"))
张三 13800001111 1
True False
写法第一个参数调用方式什么时候用
def m(self)实例obj.m()要读写这个对象的数据 —— 绝大多数情况
@classmethod
def m(cls)		类本身Contact.m()另一个构造入口，比如从一行文本、一个字典造对象
@staticmethod
def m()		什么都不给Contact.m()跟这个类有关、但不需要对象数据的工具函数
from_text 是今天最值钱的写法。读 CSV、读 JSON、解析一行日志，都会遇到「手里是一堆散装数据，想变出一个对象」。用 @classmethod 把它做成第二个构造函数，调用方就不用知道内部字段怎么排：Contact.from_text(line) 比 Contact(line.split(",")[0], line.split(",")[1]) 好读得多。
为什么写 cls 而不是直接写 Contact？因为将来 Contact 有了子类（D009），cls 会自动变成子类，构造出来的是子类对象。写死类名就没有这个能力了。

6把通讯录 v1 改成 v2

现在动手。v1 是 {"张三": "138..."}，v2 是 {"张三": Contact(...)}——外层还是字典，值从字符串变成了对象。这样 data[name] 的 O(1) 查找一点没丢，但拿到的东西从「一个电话号码」变成了「一个完整的人」。

第一步：Contact 类

import json

class Contact:
    def __init__(self, name, phone, email=""):
        self.name = name
        self.phone = phone
        self.email = email

    def line(self):
        parts = [self.name, self.phone]
        if self.email:
            parts.append(self.email)
        return "  ".join(parts)

    def to_dict(self):
        return {"phone": self.phone, "email": self.email}

    @classmethod
    def from_dict(cls, name, d):
        if isinstance(d, str):          # v1 留下的旧格式
            return cls(name, d)
        return cls(name, d.get("phone", ""), d.get("email", ""))

c = Contact("张三", "13800001111", "zs@example.com")
print(c.line())
print(json.dumps(c.to_dict(), ensure_ascii=False))

raw = {"张三": "13800001111", "李四": {"phone": "13900002222", "email": ""}}
for name, d in raw.items():
    print(Contact.from_dict(name, d).line())
张三  13800001111  zs@example.com
{"phone": "13800001111", "email": "zs@example.com"}
张三  13800001111
李四  13900002222

这里有三个设计决定，都值得停一下：

决定为什么
to_dict() / from_dict()对象不能直接塞进 JSON。json.dump 只认 dict / list / str / 数字 / 布尔 / None，遇到自定义对象会抛 TypeError。必须自己转
isinstance(d, str) 分支v1 存的是「名字 → 电话字符串」，v2 存的是「名字 → 字典」。旧文件要还能读，否则你 D007 加的人全丢了
line() 而不是 print()函数只负责返回字符串，打印交给调用方。这样以后想写进文件、想加颜色、想输出成网页，都只改一处
注意一个分层：文件里的格式，和内存里的表示，是两件事。contacts.json 里躺着的始终是 JSON 能表达的东西；程序运行时才把它变成对象。这两层之间只靠 to_dict / from_dict 两个函数连接。以后换成数据库，只要改这两个函数，其余代码一行不动。这就是 D006 说的「数据层」。

第二步：完整文件

复制 D007 的 contacts_v1.py 为 contacts_v2.py，把数据层、功能层照下面改。

# contacts_v2.py 通讯录 v2：Contact 类 + JSON 持久化 + 菜单循环
import json
import os

FILE = "contacts.json"


class Contact:
    def __init__(self, name, phone, email=""):
        self.name = name
        self.phone = phone
        self.email = email

    @staticmethod
    def is_phone(s):
        return s.isdigit() and len(s) == 11

    def line(self):
        parts = [self.name, self.phone]
        if self.email:
            parts.append(self.email)
        return "  ".join(parts)

    def to_dict(self):
        return {"phone": self.phone, "email": self.email}

    @classmethod
    def from_dict(cls, name, d):
        if isinstance(d, str):                  # v1 格式：名字 -> 电话字符串
            return cls(name, d)
        return cls(name, d.get("phone", ""), d.get("email", ""))


def load():
    if not os.path.exists(FILE):
        return {}
    try:
        with open(FILE, "r", encoding="utf-8") as f:
            raw = json.load(f)
    except json.JSONDecodeError:
        print("  数据文件损坏，按空通讯录启动")
        return {}
    return {name: Contact.from_dict(name, d) for name, d in raw.items()}


def save(data):
    with open(FILE, "w", encoding="utf-8") as f:
        json.dump({n: c.to_dict() for n, c in data.items()},
                  f, ensure_ascii=False, indent=2)


def add_contact(data):
    name = input("  姓名: ").strip()
    if not name:
        print("  姓名不能为空")
        return
    if name in data:
        print(f"  {name} 已存在，电话是 {data[name].phone}")
        return
    phone = input("  电话: ").strip()
    if not Contact.is_phone(phone):
        print("  电话必须是 11 位数字")
        return
    email = input("  邮箱（可回车跳过）: ").strip()
    data[name] = Contact(name, phone, email)
    save(data)
    print(f"  已添加 {name}")


def delete_contact(data):
    name = input("  要删除的姓名: ").strip()
    if name not in data:
        print(f"  没找到 {name}")
        return
    del data[name]
    save(data)
    print(f"  已删除 {name}")


def find_contact(data):
    kw = input("  要查找的姓名: ").strip()
    if not kw:
        print("  姓名不能为空")
        return
    hits = [c for n, c in data.items() if kw in n]
    if not hits:
        print("  没有匹配的联系人")
        return
    for c in hits:
        print("  " + c.line())


def show_all(data):
    if not data:
        print("  通讯录是空的")
        return
    for c in data.values():
        print("  " + c.line())


def main():
    data = load()
    menu = ["添加联系人", "删除联系人", "查找联系人", "显示全部", "退出"]
    while True:
        print("\n" + "=" * 30)
        for i, item in enumerate(menu, start=1):
            print(f"  {i}) {item}")
        print("=" * 30)
        choice = input("请选择: ").strip()

        if choice == "1":
            add_contact(data)
        elif choice == "2":
            delete_contact(data)
        elif choice == "3":
            find_contact(data)
        elif choice == "4":
            show_all(data)
        elif choice == "5":
            print("  再见")
            break
        else:
            print("  无效选项，请输入 1-5")


if __name__ == "__main__":
    main()

# D008 笔记

## class 三件套
- class 名字:           定义模板，此时还没有对象
- def __init__(self,...):  造对象时自动执行，用来存属性
- def 方法(self):        实例方法，调用时 self 自动是那个对象

## self
- 不是关键字，是约定（第一个参数名）
- 少写 self → TypeError: takes 1 positional argument but 2 were given
- a.hello()  等价于  Contact.hello(a)

## 两种属性
- 实例属性：self.x = ...     每个对象各一份（绝大多数用它）
- 类属性：  count = 0        所有对象共用，改的时候必须写类名
- 读：先找实例，再找类；写：写在你指定的那层

## 三个坑
- 可变类属性 tags = []  → 所有实例共用一个列表
- 构造函数的可变默认参数 def __init__(self, tags=[])  → 同上
  → 都改用 None + if None 判断
- a = b 不是复制；a == b 默认比的还是「是不是同一个」

## 三种方法
- 普通方法     第一个参数 self     obj.m()
- @classmethod 第一个参数 cls      第二个构造入口（from_text / from_dict）
- @staticmethod 没有自动参数       和类相关但不用数据的工具函数

## 对象 ↔ JSON
- json.dump 不认自定义对象 → 必须自己 to_dict()
- 读回来用 @classmethod from_dict(cls, name, d)
- 文件格式和内存表示是两件事，靠两个函数连接

## C 对比
- struct 定义形状，函数在外面      vs  class 把数据和动作装一起
- struct Contact *p                vs  self 就是那个 p
- printf("%p", p) 打地址            vs  print(obj) 打 <类名 object at 0x...>
