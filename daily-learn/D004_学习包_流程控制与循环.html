Python 特有：不用写 > 0、!= ""、!= NULL

Python 里任何值都能直接当条件用，有一套「什么是假」的规则。这条 C 里没有，用熟了能省很多字。

for v in [0, 1, "", "a", [], [0], {}, None]:
    print(f"{repr(v):>8} -> {bool(v)}")
       0 -> False
       1 -> True
      '' -> False
     'a' -> True
      [] -> False
     [0] -> True
      {} -> False
    None -> False
「假」的只有这些：0、0.0、""（空字符串）、[]（空列表）、{}（空字典）、set()、None、False。
其它一切都是真——注意 [0] 是真，因为列表不空；"0" 也是真，因为字符串不空。

所以下面两种写法完全等价，写右边：

if s != "":if s:

⚠️ 但要注意 None 和 0 是不同的假。如果一个函数可能返回 0（有效值）也可能返回 None（失败），用 if result: 会把「结果真的是 0」误判成失败。这种情况必须写 if result is not None:。

4enumerate 和 zip：C 里得自己写的东西

enumerate：同时拿下标和元素

fruits = ["苹果", "香蕉", "西瓜"]

for i, f in enumerate(fruits, start=1):
    print(f"{i}. {f}")
1. 苹果
2. 香蕉
3. 西瓜
C 里要写：for (int i = 0; i < n; i++) printf("%d. %s", i+1, arr[i]);
Python 一行：for i, f in enumerate(fruits, start=1)

start=1 可以省略（默认从 0 开始）。这条替代了 90% 需要「带序号打印」的场景，也是以后写报表、排名、菜单的标配。

zip：并排遍历两个列表

names = ["张三", "李四"]
ages = [18, 20]

for n, a in zip(names, ages):
    print(n, a)
张三 18
李四 20
⚠️ zip 以最短的那个为准。两个列表长度不一样时，多的部分直接丢掉，不报错。
zip([1,2,3], ["a","b"]) 只会得到 2 对。数据长度对不上却静默丢数据，是排查起来很痛苦的那种 bug——用 zip 前先确认两个列表一样长。
这两个函数为什么重要：它们在 C 里没有对应物，因为 C 只有数组和下标。Python 把「按下标访问」这件苦力活收走了，你只需要说「我要同时遍历这两个东西」，剩下的它做。这就是「Pythonic」的核心——描述意图，而不是描述步骤。

5break / continue / for-else

for x in [1, 3, 5, 8, 9]:
    if x % 2 == 0:
        print("找到第一个偶数:", x)
        break
else:
    print("一个偶数都没有")
找到第一个偶数: 8
⚠️ for 后面的 else 不是「否则」。 它的意思是「循环正常跑完了，没被 break 打断」。

这是 Python 独有语法，C 里没有对应物。上面的代码：找到偶数时 break 跳出去了，else 就不执行；如果整个列表都没偶数，循环自然结束，else 才执行。

用不用得上：用来表达「查找失败」非常干净，不用在外面再加一个 flag 变量。C 里你得这么写：

int found = 0; for (...) { if (...) { found = 1; break; } } if (!found) printf("没找到");

Python 里一个 else 就替代了 found 变量。第一次看很别扭，习惯后会爱上。

break 和 continue 的区别

关键字作用用在哪
break整个循环结束，跳到循环外面找到了不用再找；菜单里选「退出」
continue跳过本次，直接进下一轮这一条数据不合格，跳过它继续下一个
nums = [1, -2, 3, -4, 5]
total = 0

for x in nums:
    if x < 0:
        continue          # 负数跳过，不加
    total += x

print("正数之和:", total)
正数之和: 9
用 continue 可以让代码「少一层缩进」。上面如果不用 continue，就得写成 if x >= 0: total += x——数据清洗代码里经常有七八个过滤条件，用 continue 平铺下来比层层缩进好读得多。

6列表推导式：循环的另一种写法

D003 已经见过，今天把它和循环彻底打通。

# 写法一：普通循环
sq = []
for x in range(5):
    sq.append(x * x)

# 写法二：推导式（等价，但快且短）
sq2 = [x * x for x in range(5)]

print(sq)
print(sq2)
[0, 1, 4, 9, 16]
[0, 1, 4, 9, 16]

if 和 if-else 放的位置不一样

# 1) 筛选：if 在最后 → 只要满足条件的
print([x for x in range(1, 11) if x % 2 == 0])

# 2) 转换：if-else 在前面 → 每个都要，但结果不同
print(["偶" if x % 2 == 0 else "奇" for x in range(1, 6)])
[2, 4, 6, 8, 10]
['奇', '偶', '奇', '偶', '奇']
⚠️ 这两种 if 位置不同，含义也不同，很容易混：
· [x for x in ... if 条件] → 筛掉不满足的（元素变少）
· [A if 条件 else B for x in ...] → 每个都保留，只是结果不同（元素个数不变）

差别在于：前者 if 不带 else 时是过滤；后者 if-else 成对出现时是条件表达式（D002 学过）。写成 [x if x > 2 for x in ...] 会直接报 SyntaxError。

生成器表达式：把方括号换成圆括号

sq_list = [x * x for x in range(5)]    # 方括号 → 立刻算出整个列表
sq_gen = (x * x for x in range(5))     # 圆括号 → 先不算，用到才算

print(sq_list)
print(sq_gen)
print(list(sq_gen))
[0, 1, 4, 9, 16]
<generator object ...>
[0, 1, 4, 9, 16]
区别：列表推导式会立刻把所有结果算出来存进内存；生成器表达式一个都不算，等你取值时才逐个算。
数据量小时感觉不到差别；数据量大时（比如读 100 万行日志），生成器不会把内存撑爆。这个知识点 D012 会深入，现在知道「圆括号 = 惰性」就够了。

第 1 题的 {i*j:<3} 是今天的隐藏重点。如果不补宽度，会出现： 
1x1=1
1x2=2  2x2=4
1x4=4  2x4=8  3x4=12 4x4=16
1x4=4 是 5 个字符，3x4=12 是 6 个字符，两列一长一短就错位了。:<3 的意思是「结果部分左对齐、占 3 格」——1 位数补 2 个空格，2 位数补 1 个，每格总宽就都是 7 了。

这和 D002 的中文对齐问题是同一类：想让东西对齐，就得让每格的宽度相同，而不是让它「看起来差不多」。

# D004 笔记

## 流程控制

- [x*x for x in range(5)]

- for (i=0;i<n;i++) → for i in range(n)
- arr[i] 遍历 → for x in arr
- 带下标 → enumerate
- 两个数组 → zip
