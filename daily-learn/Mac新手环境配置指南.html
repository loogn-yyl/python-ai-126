🍏 Mac 新手环境配置 · 保姆级步骤

从开箱第一分钟到环境验收通过 · 全程约 60–90 分钟 · 不需要任何 Mac 使用基础

🖥 Apple Silicon / Intel 通用 📶 需联网 💾 预留 20GB 空间 👨‍💻 零基础可跟做
先看懂一件事：Mac 上的软件分两种装法——「App 版」（图标拖进文件夹，像微信）和「命令行版」（用终端敲命令，像 MySQL）。本课程 90% 的软件都是第二种，所以下面会有大量"敲命令"，别怕，全部是复制粘贴。
0

先认识 Mac 的 5 个地方

花 2 分钟，后面全靠它们
名字怎么打开它是什么
访达 Finder点屏幕最左下角那个蓝白笑脸就是 Windows 的"我的电脑/资源管理器"
启动台触控板四指捏合，或按 F4所有软件的大图标列表，相当于 Windows 开始菜单
聚焦搜索Command + 空格最重要的快捷键，输入任何软件名就能打开，比找图标快 10 倍
终端 Terminal聚焦搜索输入 终端 或 Terminal黑框命令行，本课程的主战场
系统设置左上角苹果图标 → 系统设置就是 Windows 的"控制面板"
⚠️ 新手最容易踩的坑：Mac 键盘上的 Command ⌘ 键 = Windows 的 Ctrl 键。
但注意：终端里的 Control + C 是「强制中断当前程序」，不是复制！复制是 Command + C。这个搞混了会误杀程序。
1

开箱后的 6 项系统设置

不做这 6 项，后面会遇到各种莫名其妙的麻烦

① 用户名必须是英文

如果开机设置时用了中文名（比如"张三"），后面所有终端路径都会变成中文，很多工具会直接报错。
检查方法：打开终端，输入 whoami 回车。如果输出是英文，✅ 通过；如果是中文或拼音乱码，建议重装系统（新机还没数据，越早越好）。

② 允许安装"来源不明"的软件

Mac 默认只允许 App Store 的软件，从网上下载的会被拦截。终端执行：

sudo spctl --master-disable

输入后按回车，会要求输入开机密码（输入时屏幕不显示任何字符，这是正常的，输完直接回车）。

③ 让访达显示隐藏文件

开发时经常要改 .zshrc 这类隐藏文件。在终端执行（一次性生效）：

defaults write com.apple.finder AppleShowAllFiles -bool true
killall Finder

屏幕会闪一下，之后在访达里按 Command+Shift+. 就能切换显示隐藏文件。

④ 开启"点按来点按"（触控板单击）

系统设置 → 触控板 → 勾选「轻点来点按」。不开的话你得用力按下去才有反应，很累。

⑤ 把 Dock 栏调小一点

系统设置 → 桌面与程序坞 → 大小拉到 30% 左右。不然一屏放不下几个图标。

⑥ 记住三个救命快捷键

快捷键作用
Command+Q完全退出软件（Mac 的红色叉只是关窗口，不退出）
Command+Tab切换软件
Command+空格聚焦搜索，找任何东西
2

打开终端，并确认它在正常工作

后面所有步骤都在这个黑框里完成

打开方式：按 Command+空格，输入 Terminal，回车。

你会看到一个白底或黑底的窗口，最后一行长这样：

你的用户名@MacBook-Pro ~ %

末尾的 % 表示等待你输入命令。这时候可以敲字了。

试一条命令，确认能跑：

sw_vers

应该输出类似：

ProductName:		macOS
ProductVersion:		15.1
BuildVersion:		24B83
✅ 能看到版本号 = 终端正常。记下 ProductVersion，后面装软件要用（需 13.0 以上）。
🚨 最重要的一条：终端里必须用英文输入法！
中文输入法状态下敲命令，符号会被自动替换成中文全角字符，命令看起来一模一样但根本无法执行。这是新手最高频、最难自查的错误。

你敲的实际输入的报错
--version——version（中文破折号）unknown option --version
"文本"“文本”（中文引号）提示符变成 dquote> 卡住
-c－c（全角减号）command not found
怎么确认：看屏幕右上角输入法图标，必须是 ABC / A，不能是「中」「拼」。切换用 Caps Lock 或 Control+空格。
最省事的做法：命令一律复制粘贴，不要手敲。
终端使用 3 条铁律：
1. 粘贴用 Command+V，不要用 Control+V
2. 程序卡住不动，按 Control+C 中断
3. 一整段命令要一次性粘完再回车，不要一行一行粘（有些命令是多行的）

装 Xcode 命令行工具（必装第一个）

作用：提供编译器。不装它，后面 90% 的软件装不上

在终端执行：

xcode-select --install

会出现什么：弹出一个小窗口，问你是否安装命令行开发者工具，点「安装」。

要等多久：下载约 1–2GB，视网速 5–20 分钟。期间会显示"正在计算剩余时间"。

怎么确认装好了：装完后回到终端执行：

xcode-select -p

输出类似 /Library/Developer/CommandLineTools = ✅ 成功。
如果提示 error: invalid active developer path，说明还没装完，等它装完再来。

如果没弹出窗口？可能是之前装过。直接执行上面的 xcode-select -p 检查，有输出就跳过这一步。
4

装 Homebrew（Mac 的"软件商店"）

后面所有软件都用它装，这一步最关键，务必装对

Homebrew 是命令行的软件管理器。装好它，以后装任何工具都只要 brew install 名字 一句话。

方式一：官方源（网络好时首选）

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

过程中会要求输入开机密码（不显示字符），然后按 Return 确认，输入 Y 回车继续。

方式二：国内网络装不动时用（清华镜像）

如果上面那条命令卡在 Downloading... 超过 3 分钟没动静，按 Control+C 中断，改用镜像：

/bin/bash -c "$(curl -fsSL https://mirrors.tuna.tsinghua.edu.cn/git/homebrew/install.git/install.sh)"

方式三：无引号法（最容易成功，新手推荐）

上面两条命令都带双引号，如果复制时引号被转成中文弯引号，终端会卡在 dquote> 不动。绕开的办法是分两步、完全不用引号：

curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh -o ~/brew_install.sh

等它跑完回到 % 后，再执行：

bash ~/brew_install.sh
🔧 卡在 dquote> 怎么办？
含义：shell 认为你有一个引号没闭合，正在等你补完。此时脚本还没开始执行，没有任何副作用。
脱困：按 Control+C 回到正常 % 提示符（注意是 Control，不是 Command）。
原因排查：① 引号被换成了弯引号 “ ”（最常见，肉眼几乎看不出）；② 复制时少选了结尾的 " 或 )；③ 粘贴时被换行拆成两行。
根治：改用上面的「方式三」。

方式四：国内网络连不上 GitHub 时（报 Connection reset by peer）

如果看到 curl: (56) Recv failure: Connection reset by peer 或一直卡在 Downloading...，说明 raw.githubusercontent.com 被重置了。改走清华镜像，全程不碰 GitHub。

① 先测镜像通不通（返回 200 就说明可用）：

curl -s -o /dev/null -w "%{http_code}\n" https://mirrors.tuna.tsinghua.edu.cn
curl -s -o /dev/null -w "%{http_code}\n" "https://mirrors.tuna.tsinghua.edu.cn/git/homebrew/brew.git/info/refs?service=git-upload-pack"
⚠️ 不要用 curl -I 测镜像！它是 HEAD 请求，镜像站会直接回 403 Forbidden，这是服务端策略，不代表连不上。看到 403 请用上面的 GET 方式复测，别被误导。

② 从镜像克隆安装仓库（约 1MB，几秒完成）：

git clone https://mirrors.tuna.tsinghua.edu.cn/git/homebrew/install.git ~/brew-install

③ 把下载源全部指向镜像（整段一次粘贴执行，这步是成败关键）：

export HOMEBREW_BREW_GIT_REMOTE="https://mirrors.tuna.tsinghua.edu.cn/git/homebrew/brew.git"
export HOMEBREW_CORE_GIT_REMOTE="https://mirrors.tuna.tsinghua.edu.cn/git/homebrew/homebrew-core.git"
export HOMEBREW_API_DOMAIN="https://mirrors.tuna.tsinghua.edu.cn/homebrew-bottles/api"
export HOMEBREW_BOTTLE_DOMAIN="https://mirrors.tuna.tsinghua.edu.cn/homebrew-bottles"
export HOMEBREW_INSTALL_FROM_API=1

④ 执行安装（这一步必须在 ③ 之后、同一个终端窗口里做，否则变量失效）：

bash ~/brew-install/install.sh
装完要长期生效：把镜像配置写进 ~/.zshrc，否则以后 brew install 还是会去连 GitHub。
终端执行 open -e ~/.zshrc 打开文件，把 ③ 里那五行粘到最末尾，保存关闭后执行 source ~/.zshrc。
如果你有代理工具（Clash / Surge 等）：更简单的做法是先开代理，再执行 export ALL_PROXY=socks5://127.0.0.1:7890（端口按你软件的设置改），然后回去用「方式一」。
注意：这个 export 只对当前终端窗口有效，关掉就失效。

方式五：手动安装（终极兜底，跳过所有脚本）

当镜像站返回 403 Forbidden、install.sh 反复失败时，用这一招——不用 install.sh，直接克隆 brew 主仓库，全程只依赖 git，成功率最高。

① 先看有没有残留（之前失败留下的目录会导致装不上）：

ls /opt/homebrew 2>/dev/null || echo "没有残留，可以继续"

如果列出了一堆文件，先删掉：sudo rm -rf /opt/homebrew（只有在你确定没装好时用）。

② 建目录并交给自己（Apple Silicon 路径，Intel 换成 /usr/local）：

sudo mkdir -p /opt/homebrew
sudo chown -R $(whoami) /opt/homebrew

③ 从镜像克隆 brew 主仓库（约 200–300MB，视网速 3–10 分钟）：

git clone https://mirrors.ustc.edu.cn/brew.git /opt/homebrew

如果 USTC 也不通，把地址换成 https://mirrors.tuna.tsinghua.edu.cn/git/homebrew/brew.git 再试。

④ 加入 PATH：

echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
brew --version

⑤ 配置镜像源（否则 brew install 仍会去连 GitHub）：

cat >> ~/.zshrc <<'EOF'
export HOMEBREW_API_DOMAIN="https://mirrors.ustc.edu.cn/homebrew-bottles/api"
export HOMEBREW_BOTTLE_DOMAIN="https://mirrors.ustc.edu.cn/homebrew-bottles"
export HOMEBREW_INSTALL_FROM_API=1
export HOMEBREW_NO_AUTO_UPDATE=1
EOF
source ~/.zshrc
验证手动安装是否成功：brew doctor 然后 brew install wget。
能装上 wget 就说明整套链路通了，可以回到第 5 步装 Python。

方式六：GitHub 加速代理法（镜像站也不通时用）

当 raw.githubusercontent.com 报 error 35、国内镜像站也打不开时，可用 GitHub 加速代理。它在国内有 CDN 节点，把请求转发到 GitHub。

① 先测哪个代理能用（返回 200 的才可用，依次试）：

for p in ghfast.top gh-proxy.com ghproxy.net; do
  printf "%-20s" "$p"
  curl -s -o /dev/null -w "%{http_code}\n" --max-time 8 "https://$p/https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh"
done

② 用可用的代理下载并安装（下面以 ghfast.top 为例，换成你测通的域名）：

export HOMEBREW_BREW_GIT_REMOTE="https://ghfast.top/https://github.com/Homebrew/brew"
export HOMEBREW_CORE_GIT_REMOTE="https://ghfast.top/https://github.com/Homebrew/homebrew-core"
export HOMEBREW_INSTALL_FROM_API=1
curl -fsSL https://ghfast.top/https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh -o ~/brew_install.sh
bash ~/brew_install.sh
装完还要处理 bottle 下载：brew 装软件时二进制包来自 ghcr.io，若 brew install 卡在下载，把镜像变量换成能通的地址（清华 / 中科大 / 阿里云的 homebrew-bottles），或让 brew 走源码编译（慢但能成）。

路线选择表：哪条通就走哪条

能访问的站点走哪个方式
mirrors.tuna.tsinghua.edu.cn方式四（清华镜像）
mirrors.ustc.edu.cn方式五（USTC 手动安装）
ghfast.top 等加速代理方式六（本方式）
gitee.comGitee 上的第三方脚本（谨慎）
以上全部不通附录 E 的 pkg 安装方案
⚠️ 关于 Gitee 上的一键脚本：网上流传 HomebrewCN 之类的一键脚本确实能装上，但那是第三方代码，会修改你的 shell 配置。能看懂再用，否则优先走上面的官方 + 镜像方案。
⚠️ 不要再输入 sudo 装 brew！网上很多老教程会让你 sudo brew install，这是错的，会导致权限混乱，后面各种 Permission denied。Homebrew 永远不需要 sudo。

关键：把 brew 加入环境变量

装完后终端会打印一段 "Next steps"，里面有两行命令，必须复制执行。

Apple Silicon 芯片（M1/M2/M3/M4）执行这两行：

echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

Intel 芯片执行这两行：

echo 'eval "$(/usr/local/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/usr/local/bin/brew shellenv)"

不知道自己是哪种芯片？终端执行 uname -m，输出 arm64 就是 Apple Silicon，输出 x86_64 就是 Intel。

验收

brew --version

输出 Homebrew 4.x.x = ✅ 成功。

顺手装 4 个常用小工具：
brew install git wget tree jq
分别是：版本管理、下载工具、目录树显示、JSON 处理。后面都会用到。

装 Python 环境（pyenv + uv）

不要用 Mac 自带的 Python，版本太旧且不能乱动

Mac 自带一个 Python，但那是给系统用的，绝对不要拿它装包，否则系统容易出问题。我们用 pyenv 装一个干净的 Python 3.12。

① 装 pyenv 和 uv

brew install pyenv uv

uv 是新一代 Python 包管理器，比 pip 快 10–100 倍，后面装依赖全靠它。

② 配置 pyenv（复制整段一次执行）

echo 'export PYENV_ROOT="$HOME/.pyenv"' >> ~/.zshrc
echo 'export PATH="$PYENV_ROOT/bin:$PATH"' >> ~/.zshrc
echo 'eval "$(pyenv init -)"' >> ~/.zshrc
source ~/.zshrc

③ 安装 Python 3.12

pyenv install 3.12.7
pyenv global 3.12.7

第一条命令会编译源码，耗时 5–15 分钟，屏幕上会滚动大量文字，属于正常现象，等到重新出现 % 就好。

④ 验收

python --version
uv --version

应输出 Python 3.12.7 和 uv 0.x.x。

如果 python --version 显示的还是 3.9.x：说明 pyenv 配置没生效。执行 exec zsh 重开一次终端，再试。仍然不行就把 source ~/.zshrc 再执行一遍。

⑤ 跑第一个 Python 程序

echo 'print("环境好了，开始学 Python")' > hello.py
python hello.py

看到中文输出 = ✅ 完全打通。

装 VS Code（写代码的地方）

替代 Windows 上的 PyCharm / Dev-C++

① 安装

brew install --cask visual-studio-code

装完会自动出现在「启动台」，也可以聚焦搜索输入 code 打开。

② 把 code 命令加进终端（重要）

打开 VS Code → 按 Command+Shift+P 打开命令面板 → 输入 shell command → 选 「Shell Command: Install 'code' command in PATH」 → 回车。

之后在终端任意目录敲 code . 就能用 VS Code 打开当前文件夹。

③ 装 5 个必备插件

VS Code 左侧第四个图标（方块）→ 搜索安装：

插件名作用
Python（Microsoft 官方）语法高亮、调试、自动补全
Pylance类型检查，写错会提前报红
Jupyter在 VS Code 里直接跑 .ipynb 笔记本
Chinese (Simplified)中文界面
Docker图形化管理容器
⚠️ 打开文件夹后如果顶部出现一条黄色「受限模式」提示，必须先点「信任此文件夹」。
VS Code 默认不信任任何文件夹。在受限模式下，Python 扩展的自动补全、跳转定义、运行当前文件、调试全部会被禁用，你会以为扩展装了没用，其实是权限问题。
点一次「信任此文件夹（Trust the authors）」即可，永久生效，之后打开同一目录不再提示。
这不是网络问题，也不是扩展没装好。判断方法：左下角或状态栏能看到 Python 3.12.16，但右键菜单里没有「Run Python File」——那就是受限模式。

④ 验收

code --version

输出版本号 = ✅ 成功。

装 Docker（用 OrbStack 代替）

W4 之后的目标：一条命令同时启动 MySQL + Redis
为什么不用官方 Docker Desktop：它体积 2GB+ 且后台常驻吃内存，大公司使用还要付费授权。OrbStack 同样提供 docker 命令，启动快 5 倍、内存占用只有 1/3，个人免费。

① 安装

brew install --cask orbstack

② 首次打开

聚焦搜索输入 OrbStack 打开 → 点 Next / Continue → 一路同意，它会自动配置好 docker 命令。
首次打开可能需要授权，按提示输入开机密码。

③ 验收

docker --version
docker compose version

两条都有版本号输出 = ✅ 成功。

如果提示 command not found: docker：说明 OrbStack 没启动过。先手动打开一次 App，等菜单栏出现小鲸鱼图标后再试。
8

装 MySQL 和 Redis

W5 数据库阶段的核心工具

① MySQL

brew install mysql
brew services start mysql

第二条命令是"开机自启并现在启动"。看到 Successfully started mysql 就对了。

设置密码（必做）：

mysql_secure_installation

它会问你几个问题，新手照这样回答：

  • Enter password：直接回车（新装的 root 没密码）
  • VALIDATE PASSWORD COMPONENT：输入 n
  • New password：设一个记得住的密码（如 Root@1234），输入时不显示字符
  • Re-enter new password：再输一次
  • 后面 4 个问题全部输入 y

验收：

mysql -uroot -p -e "SELECT VERSION();"

输入刚才设的密码，显示版本号 = ✅ 成功。

⚠️ 密码忘了怎么办？执行 brew services stop mysql，再 brew reinstall mysql 重装一遍（数据会丢，但刚开始学无所谓）。

② Redis

brew install redis
brew services start redis
redis-cli ping

最后一条返回 PONG = ✅ 成功。

③ 装一个数据库图形客户端

brew install --cask tableplus

TablePlus 免费版够用，可以可视化看表、写 SQL。连 MySQL 时填：Host 127.0.0.1、Port 3306、User root、密码是你刚设的。

装 AI 开发工具（W8 之前完成即可）

这一步不急，但早点装好能少折腾

① Ollama —— 本地跑开源大模型

brew install --cask ollama

npm install -g @anthropic-ai/claude-code

需要 Anthropic 账号。国内网络下也可用其他 AI 编程工具替代，不影响学习进度。

网络诊断：403 / 超时 / 连接重置

装软件卡住时，先跑这一组，把结果发出来就知道问题在哪

整段复制粘贴，一次回车：

for u in \
  https://www.baidu.com \
  https://mirrors.tuna.tsinghua.edu.cn \
  https://mirrors.ustc.edu.cn \
  https://mirrors.aliyun.com \
  https://mirrors.huaweicloud.com \
  "https://mirrors.tuna.tsinghua.edu.cn/git/homebrew/brew.git/info/refs?service=git-upload-pack" \
  "https://mirrors.ustc.edu.cn/brew.git/info/refs?service=git-upload-pack"
do
  printf "%-88s " "$u"
  curl -s -o /dev/null -w "%{http_code}\n" --max-time 10 "$u"
done
echo "--- 代理环境变量 ---"
env | grep -i proxy || echo "无代理变量"

现象结论解决
百度 200，镜像全部 403运营商/校园网关拦截镜像站换手机热点试一次，或开代理
某个镜像返回 200就用这个镜像把后面所有命令里的域名替换掉
全部 403 或超时环境里残留了失效的代理变量执行 unset ALL_PROXY HTTP_PROXY HTTPS_PROXY 后重测
百度也连不上根本没联网检查 Wi-Fi / 网络
仅 git 端点 200，根目录 403正常，可以直接克隆忽略根目录的 403，继续安装
curl: (35) Recv failure: Connection reset by peerTLS 握手被中途切断，网络层拦截或代理冲突先 unset ALL_PROXY ... 清代理；再用 Safari 打开同一网址对比判断
🔍 用 Safari 做对照判断（关键技巧）：
Safari 不使用终端的 ALL_PROXY 环境变量，所以能区分两类问题：
· Safari 能打开、curl 报错 → 是终端里的代理变量在捣乱，清掉即可。
· Safari 也打不开 → 网络层拦截（运营商/校园网/防火墙），换手机热点或改用安装包方案。
🔍 判断 403 是谁返回的（看真实 IP）：把 %{http_code} 换成 %{http_code} ip=%{remote_ip}，就能看到实际应答的服务器地址。
curl -s -o /dev/null -w "%{http_code}  ip=%{remote_ip}\n" https://mirrors.tuna.tsinghua.edu.cn
· IP 是清华的（101.6.x.x）→ 镜像站真的在拒绝，换镜像
· IP 是 127.0.0.1 → 本地有代理软件在拦，退出代理或改规则
· IP 是内网段（10.x / 192.168.x）→ 被公司/学校网关接管，只能换网络
最见效的一招：把网络切换到手机热点，再跑一次安装。校园网和公司网络对镜像站的拦截非常常见，而 4G/5G 通常没有这个限制。

软件该装在哪？—— 路径问题一次说清

从 Windows 转过来最容易纠结的一件事，结论是：别纠结
一句话结论：一律保持默认，不要修改安装路径。
Mac 和 Windows 的逻辑不一样。Windows 上软件散落安装、可以随便挑盘符；Mac 上软件是一个 .app 包（本质就是个文件夹），拖进 /Applications 就算装完，卸载直接删掉它。改路径没有任何收益，反而会让聚焦搜索和启动台检索不到、软件自动更新失效，某些应用校验路径后直接拒绝启动。
场景要不要改路径说明
拖 .app 进 /Applications不要标准做法，拖进去即安装完成
.pkg 安装器（Python 官方包、Docker 等）改不了路径由安装器写死到系统目录，强行挪会坏
Homebrew 装的软件不要Apple 芯片自动装 /opt/homebrew，Intel 装 /usr/local，brew 自己判断
Python 虚拟环境需要你定venv 建在项目内，如 ~/python-learn/dayNN/.venv
你自己的代码 / 笔记 / 数据集需要你定放用户主目录 ~/ 下，别放 /Applications

三条硬提醒

  1. 不要手动往 /usr/bin、/System、/Library 里塞东西。 macOS 有 SIP 系统完整性保护，正常情况塞不进去；真塞进去了可能搞坏系统自带的 Python。
  2. 软件本身 ≠ 你的数据。 需要挑位置的永远是后者。本项目代码目录 ~/python-learn 放在用户主目录下，这个选择是对的，保持即可。
  3. 磁盘空间紧张时，可以外置的是用户数据（数据集、虚拟机镜像、素材），不是 /Applications 里的 .app。把应用搬到移动硬盘会导致每次插盘才能用，且权限容易乱。
记一句口诀：软件交给系统，路径只管你自己的文件。

Homebrew 的两个路径，心里有数就行

brew --prefix

Apple Silicon 输出 /opt/homebrew，Intel 输出 /usr/local。
不要手动改这个位置，也不要把 brew 装到外接硬盘——brew 的符号链接依赖固定路径，一挪就全断。

卸载也要用 brew，不要手动删文件：

brew uninstall wget              # 卸载命令行工具
brew uninstall --cask orbstack   # 卸载 App
brew list                        # 看装了什么
