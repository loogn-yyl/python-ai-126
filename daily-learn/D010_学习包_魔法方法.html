1__str__ 与 __repr__：让对象能直接打印

D008 你见过 print(Contact("张三")) 输出的是一串地址。两个魔法方法就是为了改掉它：

class Book:
    def __init__(self, title, price):
        self.title = title
        self.price = price

    def __str__(self):
        return f"《{self.title}》{self.price} 元"

    def __repr__(self):
        return f"Book({self.title!r}, {self.price!r})"


b = Book("流畅的 Python", 128.0)
print(b)
print(str(b))
print(repr(b))
print([b])
《流畅的 Python》128.0 元
《流畅的 Python》128.0 元
Book('流畅的 Python', 128.0)
[Book('流畅的 Python', 128.0)]
方法什么时候被调用写给谁看
__str__print(obj)、str(obj)、f"{obj}"人——尽量好看
__repr__repr(obj)、放进容器里打印、调试器开发者——最好是能重建对象的代码
最容易被忽略的一行：print([b]) 走的是 __repr__，不是 __str__。因为列表的 __str__ 是「把每个元素的 repr 拼起来」。所以 两个都要写——只写 __str__ 的话，打印列表、写日志、看报错时看到的还是一堆地址。
写 __repr__ 的一个实用技巧：用 !r。f"Book({self.title!r}, {self.price!r})" 会自动给字符串加引号、给数字原样输出，得到 Book('流畅的 Python', 128.0)——这行东西粘回 Python 里能直接重建一个对象，这就是 repr 的理想状态。

2__eq__ 与 __hash__：能不能比较、能不能去重

D008 见过：Contact("张三") == Contact("张三") 是 False。因为默认的 == 问的是「是不是同一个对象」，和 is 一样。

class A:
    def __init__(self, v):
        self.v = v


class B:
    def __init__(self, v):
        self.v = v

    def __eq__(self, other):
        if not isinstance(other, B):
            return NotImplemented
        return self.v == other.v


print("没写 __eq__:", A(1) == A(1))
print("写了 __eq__:", B(1) == B(1))
print("值不同:", B(1) == B(2))
print("跟别的类型比:", B(1) == 1)
没写 __eq__: False
写了 __eq__: True
值不同: False
跟别的类型比: False

三个细节值得说清楚：

细节说明
return NotImplemented不是 False。它的意思是「我不会跟他比」，Python 会再去问对方能不能比，两边都不行才返回 False
为什么要 isinstance 检查不检查的话 B(1) == 1 会去访问 1.v，直接抛 AttributeError
!= 自动有了a != c 输出 True——定义 __eq__ 之后 Python 自动给你配一个反向的 !=

然后踩一个必踩的坑：定义了 __eq__ 就不能进 set 了

class A:
    def __init__(self, v):
        self.v = v

    def __eq__(self, other):
        return isinstance(other, A) and self.v == other.v


print("能比较:", A(1) == A(1))
try:
    print(set([A(1)]))
except TypeError as e:
    print("TypeError:", e)
能比较: True
TypeError: unhashable type: 'A'

能 == 但不能进 set，看着很怪，其实是 Python 的规矩：定义了 __eq__ 却不定义 __hash__，Python 会把 __hash__ 设成 None，这个类就不可哈希，也就不能当字典的 key、不能放进 set。

为什么这么设计：哈希表要求「相等的两个东西哈希值必须相同」。你改了「相等」的定义，Python 不知道新的「相等」该怎么算哈希，与其给你一个错的哈希（会导致 in 查不到、去重失效），不如直接拒绝。

补法就三行：相等按什么比，哈希就按同一个东西算。
def __eq__(self, other):
    return isinstance(other, Book) and self.title == other.title

def __hash__(self):
    return hash(self.title)          # 和 __eq__ 用同一个字段

3__lt__：让对象能排序

sorted(books) 对自定义对象默认会报 TypeError: '<' not supported between instances，它不知道谁大谁小。给它一个 __lt__（less than）就行：

class Book:
    def __init__(self, title, price):
        self.title = title
        self.price = price

    def __str__(self):
        return f"{self.title}({self.price})"

    def __lt__(self, other):
        return self.price < other.price


books = [Book("C 程序设计", 59.0), Book("流畅的 Python", 128.0), Book("算法导论", 99.0)]
print("默认按 price 升序:")
for b in sorted(books):
    print(" ", b)

print("按书名排（key 优先于 __lt__）:")
for b in sorted(books, key=lambda x: x.title):
    print(" ", b)
默认按 price 升序:
  C 程序设计(59.0)
  算法导论(99.0)
  流畅的 Python(128.0)
按书名排（key 优先于 __lt__）:
  C 程序设计(59.0)
  流畅的 Python(128.0)
  算法导论(99.0)
写法按什么排什么时候用
定义 __lt__ + sorted(books)对象默认的那个顺序这个类只有一种自然的排序方式（价格、日期、优先级）
sorted(books, key=lambda b: b.title)临时指定的字段临时换一种排法，不动类——更常用
sorted(books, reverse=True)反过来任何排序都能加
key= 永远优先于 __lt__。上面第二段输出按书名排了，说明给了 key 就不会调 __lt__。
所以真实项目里，大部分排序用 key= 就够了，不必去写 __lt__。什么时候该写？当这个对象有一个不可否认的自然顺序时——比如按日期排的事件、按分数排的成绩。
还有一个小陷阱：__eq__ 和 __lt__ 的口径要一致。如果 __eq__ 只看标题、而 __lt__ 只看价格，就会出现「两本书相等，但一本比另一本贵」这种自相矛盾的状态，排序结果会不稳定。
经验：要么都按同一个字段，要么 __eq__ 按全部字段、__lt__ 按第一个字段排。

4让对象像容器：__len__ / __getitem__ / __iter__

三个方法一写，你的对象就能用 len()、obj[0]、for x in obj、in、切片——全部是 Python 原生语法，不需要记你的方法名。

class Shelf:
    def __init__(self, books):
        self.books = list(books)

    def __len__(self):
        return len(self.books)

    def __getitem__(self, i):
        return self.books[i]

    def __iter__(self):
        return iter(self.books)


s = Shelf(["C 程序设计", "流畅的 Python", "算法导论"])
print(len(s))
print(s[0])
print(s[-1])
for name in s:
    print("  读完了:", name)
print([n for n in s if "Python" in n])

  读完了: 流畅的 Python
  读完了: 算法导论

方法解锁的写法说明
__len__len(s)返回一个整数
__getitem__s[0]、s[-1]、s[0:2]切片时收到的是一个 slice 对象，直接转给内部列表就行
__iter__for x in s、list(s)、in、推导式返回一个迭代器；D012 会专门讲它
只要写了 __getitem__，for 循环其实也能跑——Python 会从下标 0 开始一个个取，直到抛 IndexError。这是老式写法，能跑但慢（每次都从头找），所以 __iter__ 还是要写。D012 会讲清楚两者差别。
这就是「鸭子类型」的实用价值：调用方不需要知道你是 list 还是 Shelf，只要你能被 for 遍历、能 len()，就能塞进任何接受「可迭代对象」的地方——sum()、max()、sorted()、enumerate()，一个都不用改。

5__call__：让对象像函数

class Multiplier:
    def __init__(self, n):
        self.n = n

    def __call__(self, x):
        return x * self.n


double = Multiplier(2)
triple = Multiplier(3)
print(double(5), triple(5))
print(callable(double), callable(5))

books = ["C 程序设计", "流畅的 Python", "算法导论"]
print(list(map(double, [1, 2, 3])))
print(sorted(books, key=Multiplier(1)) == sorted(books))

写了 __call__，对象就能像函数一样加括号调用。callable(double) 从 False 变成 True。

那为什么不直接写个函数？因为函数记不住状态，而对象可以：

写法能不能带状态例子
def double(x): return x * 2不能，除非用默认参数或全局变量固定倍率
class Multiplier: + __call__能，倍率存在 self.n 里Multiplier(2) / Multiplier(0.8) 各自独立
真实项目里这个模式用得很多，而且理由都很实际：需要一个「带配置的函数」时，写成类能让配置和逻辑待在一起，还能顺手加校验、加日志。D013 的装饰器本质就是「能记住配置的可调用对象」，今天这个是它的前置知识。

6@property：看起来是属性，其实是方法

想让「给价格赋值」这件事自动做校验，又不想让调用方写 b.set_price(99)。用 @property：

class Book:
    def __init__(self, title, price):
        self.title = title
        self.price = price              # 注意：这里会走下面的 setter

    @property
    def price(self):
        return self._price

    @price.setter
    def price(self, v):
        if v < 0:
            raise ValueError("价格不能为负")
        self._price = v


b = Book("流畅的 Python", 128.0)
print(b.price)
b.price = 99.9
print(b.price)
try:
    b.price = -1
except ValueError as e:
    print("ValueError:", e)
print("价格还是:", b.price)
128.0
99.9
ValueError: 价格不能为负
价格还是: 99.9

四点必须记住：

点说明
调用方看不出区别b.price 长得像读属性，b.price = 99.9 长得像写属性，实际走的是两个方法
内部存到 self._price下划线开头表示「内部字段，别直接碰」。不能也叫 self.price，那会无限递归
__init__ 里也会走 setter所以 Book("书名", -1) 一样会被拦下来，校验只需要写一处
@property 单独用是只读只写 getter 不写 setter，赋值就报错

只读的计算属性

8今日笔记要点

# D010 笔记

## 打印
- __str__  → print(obj) / str(obj) / f"{obj}"     给人看
- __repr__ → repr(obj) / 打印列表 / 调试器          给开发者看，最好能重建对象
- print([obj]) 走的是 __repr__，不是 __str__ → 两个都要写
- repr 里用 !r：f"Book({title!r})" → Book('书名')

## 比较
- 默认 == 和 is 一个意思，比的是「是不是同一个对象」
- __eq__ 里先 isinstance 检查，比不了就 return NotImplemented（不是 False）
- 定义了 __eq__ 不定义 __hash__ → 类变成不可哈希，不能进 set、不能当 dict key
- __hash__ 要和 __eq__ 用同一个字段算

## 排序
- sorted(books) 需要 __lt__，否则 TypeError
- sorted(books, key=lambda b: b.x) 更常用，key 优先于 __lt__
- __eq__ 和 __lt__ 口径要一致，否则排序结果不稳定

## 让它像容器
- __len__      → len(obj)
- __getitem__  → obj[0] / obj[-1] / obj[0:2]（切片收到 slice 对象）
- __iter__     → for x in obj / in / 推导式 / list()
- 只写 __getitem__ 也能 for，但慢；能写 __iter__ 就写

## 让它像函数
- __call__ → obj(x)
- 比函数强的地方：能带状态（self.n 就是配置）

## @property
- @property + @x.setter → 长得像属性，实际走方法
- 内部字段用 self._x，不能同名（会无限递归）
- __init__ 里赋值也会走 setter → 校验只写一处
- 只写 getter 就是只读，赋值报 AttributeError
- 调用时不加括号！d.total 不是 d.total()

## 三种装饰器
- @classmethod  cls    第二个构造函数
- @staticmethod 无参数  工具函数
- @property    不加括号 当属性用
