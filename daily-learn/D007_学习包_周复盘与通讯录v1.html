2项目设计：先想清楚存什么

需求：一个命令行通讯录，能添加、删除、查找、显示全部，关掉程序再打开数据还在。

关键决策：用什么存联系人

方案数据结构评价
方案 A[("张三","138..."), ("李四","139...")]查一个人要遍历整个列表，O(n)
方案 B{"张三": "138...", "李四": "139..."}直接按名字取，O(1)；名字天然唯一，正好当 key
选方案 B，理由就是 D003 那张复杂度表：「按名字找」是通讯录最高频的操作，字典的 in 和取值都是 O(1)，列表是 O(n)。
而且名字本身就不允许重复——「唯一」这个特性正好对应「key 唯一」，用字典等于让语言帮你做约束，不用自己写查重逻辑（只需处理「已存在」的提示）。

文件结构

day07/ ├── contacts_v1.py ← 主程序 ├── contacts.json ← 数据文件（程序自动生成） ├── .gitignore ← 不上传的文件 └── README.md ← 项目说明
为什么数据和代码分开：contacts.json 是运行时产生的数据，不是代码。它不该进 Git 仓库（每台电脑的数据都不一样）。.gitignore 就是干这个的。

4第二步：把功能拆成函数

不要在 if 分支里直接写一堆代码，那样主循环会变得非常长。每个功能一个函数，主循环只负责「分发」。

添加（含重复检查）

def add_contact(data):
    name = input("  姓名: ").strip()
    if not name:
        print("  姓名不能为空")
        return
    if name in data:                      # 字典的 in 是 O(1)
        print(f"  {name} 已存在，电话是 {data[name]}")
        return
    phone = input("  电话: ").strip()
    if not phone:
        print("  电话不能为空")
        return
    data[name] = phone
    save(data)
    print(f"  已添加 {name}")
这个函数里有四个「防御」：空姓名、重名、空电话、及时保存。
每一个都是「如果不写，用户一定会踩到」的场景。用户输入空格、重复添加同一个人、忘了填电话——这些不是极端情况，是每天都会发生的情况。

写函数时先问自己：这个函数被乱用会怎样？这就是 D005 说的「边界意识」，也是专业和业余的分界线。

def find_contact(data):
    keyword = input("  输入姓名关键字: ").strip()
    hits = {k: v for k, v in data.items() if keyword in k}
    if not hits:
        print("  没有匹配的联系人")
        return
    for name, phone in hits.items():

find_contact 那行推导式是 D003 的字典推导式：「遍历所有键值对，留下 key 里包含关键字的」。
用关键字而不是全名搜索，是因为人记不全名字——输「张」就能列出所有姓张的。这个体验细节比技术本身重要。

5第三步：持久化（关了还在）

到这一步为止，程序关了数据就没了——全在内存里。用 D006 学的 JSON 就解决了。

import json
import os

FILE = "contacts.json"


def load():
    """读数据；文件不存在就返回空字典"""
    if not os.path.exists(FILE):
        return {}
    with open(FILE, "r", encoding="utf-8") as f:
        return json.load(f)


def save(data):
    """写数据"""
    with open(FILE, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
contacts.json 的内容：
{
  "张三": "13800001111",
  "李四": "13900002222"
}
读文件必须有的两样东西：
① os.path.exists 判断 —— 第一次运行时文件还不存在，直接 open 会抛 FileNotFoundError。返回空字典，程序就能正常启动。
② encoding="utf-8" —— 不写的话，中文名字在 Windows 上会存成乱码。

ensure_ascii=False 是为了让文件里的人名是可读的中文，而不是 "\u5f20\u4e09"。
⚠️ 每次增删后都调用 save()。不要「退出时统一保存」——中途断电、Ctrl+C、程序崩了，所有操作全丢。改一次存一次，这是最简单也最可靠的做法。做 AI 应用时同理，对话记录要随时落盘。

6完整代码（复制这份就能跑）

# contacts_v1.py
"""命令行通讯录 v1 —— 字典存储 + JSON 持久化 + 菜单循环"""

import json
import os

FILE = "contacts.json"


# ---------- 数据层 ----------
def load():
    if not os.path.exists(FILE):
        return {}
    with open(FILE, "r", encoding="utf-8") as f:
        return json.load(f)


def save(data):
    with open(FILE, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)


# ---------- 功能层 ----------
def show_all(data):
    if not data:
        print("  通讯录是空的")
        return
    print(f"  {'序号':<4}{'姓名':<8}{'电话'}")
    for i, (name, phone) in enumerate(data.items(), start=1):
        print(f"  {i:<4}{name:<8}{phone}")


def add_contact(data):
    name = input("  姓名: ").strip()
    if not name:
        print("  姓名不能为空")
        return
    if name in data:
        print(f"  {name} 已存在，电话是 {data[name]}")
        return
    phone = input("  电话: ").strip()
    if not phone:
        print("  电话不能为空")
        return
    data[name] = phone
    save(data)
    print(f"  已添加 {name}")


def delete_contact(data):
    name = input("  要删除的姓名: ").strip()
    if name not in data:
        print(f"  没找到 {name}")
        return
    del data[name]
    save(data)
    print(f"  已删除 {name}")


def find_contact(data):
    keyword = input("  输入姓名关键字: ").strip()
    hits = {k: v for k, v in data.items() if keyword in k}
    if not hits:
        print("  没有匹配的联系人")
        return
    for name, phone in hits.items():
        print(f"  {name}: {phone}")


# ---------- 界面层 ----------
def show_menu(menu):
    print("\n" + "=" * 30)
    for i, item in enumerate(menu, start=1):
        print(f"  {i}) {item}")
    print("=" * 30)


def main():
    data = load()
    menu = ["添加联系人", "删除联系人", "查找联系人", "显示全部", "退出"]

    while True:
        show_menu(menu)
        choice = input("请选择: ").strip()

        if choice == "1":
            add_contact(data)
        elif choice == "2":
            delete_contact(data)
        elif choice == "3":
            find_contact(data)
        elif choice == "4":
            show_all(data)
        elif choice == "5":
            print("  再见")
            break
        else:
            print("  无效选项，请输入 1-5")


if __name__ == "__main__":
    main()
注意代码分成三层，用注释隔开了：
数据层（load / save）—— 只管读写文件，不知道菜单长什么样
功能层（增删查显示）—— 只管处理数据，不知道界面怎么显示
界面层（show_menu / main）—— 只管交互，不知道数据怎么存

为什么要这么分：以后 D008 要把字典换成 Contact 类，只改数据层；D014 要加图形界面，只改界面层。这就是「分层」的全部意义——改一处不影响别处。

git add 和 git commit 的区别：

常见问题速查
· 第 4 条不过（重开数据没了）→ 检查 save() 是不是每次增删后都调了；contacts.json 有没有真的出现在文件夹里
· 中文变乱码 → open() 漏了 encoding="utf-8"
· json.decoder.JSONDecodeError → contacts.json 内容坏了（可能手改过），删掉它让程序重新生成
· 菜单无限打印停不下来 → while True 里漏了 break，或者 input 被跳过了
· git push 卡住/超时 → GitHub 网络问题，换 Gitee
· git commit 报「Please tell me who you are」 → 没配 user.name / user.email
