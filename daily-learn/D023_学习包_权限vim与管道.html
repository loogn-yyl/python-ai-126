1权限：那 10 个字符到底在说什么

昨天 ls -l 的第一列你没细看，今天把它拆开。整个权限系统只有三个维度：谁、能做什么、对什么。

先认字符

- rwx r-x r-- 1 loogn staff 218 Nov 22 18:02 access.log │ │ │ │ │ │ │ └── 其他人（other）：r-- 只能读 │ │ └─────── 同组用户（group）：r-x 能读、能进目录 │ └──────────── 属主（user）：rwx 能读能写能进 └─────────────── 类型：- 普通文件 d 目录 l 软链接
位对文件的意思对目录的意思（不一样！）
r（4）能读内容（cat）能列出里面有什么（ls）
w（2）能改内容（写入、编辑）能在里面新建、删除、改名文件
x（1）能执行（脚本、程序）能进入（cd）和访问里面的文件
全章最反直觉的一条：删一个文件，靠的是它所在目录的 w 位，不是文件自己的 w 位。
一个文件即使设成 r--r--r--（谁都只读），只要它所在目录你有 w 权限，照样能删掉它——因为「删除」改的是目录里的名单，不是文件内容。
反过来，你对文件有 w 权限，但目录没有 w，你改得动内容、删不掉文件。这两件事在真实环境里天天打架。

数字写法：4 = r、2 = w、1 = x，三个加起来

数字字符含义什么时候用
7rwx读写执行全给目录、脚本
6rw-读写，不能执行普通数据文件
5r-x读和执行，不能改目录（能进不能改）、只读脚本
4r--只读配置文件、证书
0---什么都不给极少用

三个数字按属主、组、其他人顺序排，这就是你天天见的那三个：

写法等价典型场景
chmod 755 目录rwxr-xr-x目录的默认正确答案：我能改，别人能进能看
chmod 644 文件rw-r--r--普通文件的默认正确答案：我能改，别人能看
chmod 600 私钥rw-------只有我能看。ssh 私钥必须是这个，否则拒绝使用
chmod +x 脚本给三组都加 x让 ./脚本.sh 能跑
cd ~/linux-lab
mkdir -p perm && cd perm
echo "hello" > a.txt
chmod 644 a.txt
ls -l a.txt
chmod 600 a.txt
ls -l a.txt
chmod +x a.txt
ls -l a.txt
-rw-r--r--  1 loogn  staff  6 Nov 22 19:10 a.txt
-rw-------  1 loogn  staff  6 Nov 22 19:10 a.txt
-rwx--x--x  1 loogn  staff  6 Nov 22 19:10 a.txt
看第三行：chmod +x 在 macOS 上给三组都加了执行位（rwx--x--x）。它不会改 r 和 w，只在原来基础上加 x。所以「chmod +x 之后就安全了」是错的——它会把「其他人」也变成可执行。
给脚本加执行权，用 chmod 755 脚本.sh 更准确：属主全权限、其他人只读和执行，不多不少。

符号写法：有时候比数字好读

chmod u+x  script.sh     # 只给属主加执行
chmod go-w file          # 去掉组和其他人的写权限
chmod a+r  report.md     # 所有人可读（a = all）
chmod -R 755 site/       # 递归改整个目录（小心）
什么时候用符号写法：只想加减某一个位、不想推测其他位现在是什么的时候。比如「把这个私钥变成只有我能读」，chmod 600 最直接；「把这三个脚本批量加上执行权限」，chmod +x *.sh 最省事。其他情况一律用三位数字——数字写的是「最终状态」，符号写的是「相对变化」，前者不容易出错。

umask：为什么新建的文件是 644

umask
022

新建文件 = 666 减掉 umask，新建目录 = 777 减掉 umask。umask 022 就是「从默认权限里拿走其他人的写权限」：666 − 022 = 644，777 − 022 = 755。所以你从来不用手动设这两个数——它们是 umask 算出来的。

chown 和 sudo：为什么有些东西你改不了

ls -l /etc/hosts
sudo cat /etc/hosts | head -n 3
whoami
groups
-rw-r--r--  1 root  wheel  213 Nov 20 09:12 /etc/hosts
##
# Host Database
##
loogn
staff admin _lpadmin _lpoperator ...
/etc/hosts 的属主是 root，你只有 r 权限，所以只能看不能改。要改就得用 sudo——它不是「管理员密码」那么笼统，准确说是「以 root 身份执行这一条命令」，命令结束后立刻退回你自己。
你的账户在 admin 组里，这才是能用 sudo 的原因。不在这个组里的账户，密码输对了也会被拒。
sudo chown -R 你的用户名 ~/ 和 sudo chmod -R 777 / 是两条能毁掉系统的命令。前者的常见事故是手滑多打一个空格（sudo chown -R loogn /）；后者会把所有系统文件变成人人可改，系统直接不再可信。
用 -R 之前，先不加 -R 跑一遍看范围；路径里凡是出现 / 结尾、*、~，都要读三遍。
回答昨天的 Permission denied：不是你操作错了，是那个文件的权限里没给你 r（读）或 x（进目录）。排查顺序固定三步：ls -l 看属主和权限 → whoami 看你是谁 → ls -ld 看上级目录你能不能进。90% 的权限问题卡在「上级目录没有 x 位」，而不是文件本身。

2管道与重定向：三个流，四个符号

shell 里每个命令都有三个通道：标准输入 stdin（0）、标准输出 stdout（1）、标准错误 stderr（2）。所有重定向都是在这三个数字上做文章。

符号作用例子
>stdout 写进文件，覆盖ls -l > list.txt
>>stdout 追加到文件末尾echo hi >> log.txt
2>stderr 写进文件ls nope 2> err.txt
&>stdout 和 stderr 都写进文件make &> build.log
<用文件当 stdinwc -l < access.log
|前一个的 stdout 当后一个的 stdincat f | grep err
tee一边写文件一边往屏幕打... | tee out.txt
/dev/null黑洞，丢掉不要的输出cmd 2>/dev/null

最容易错的一行：2>&1 的位置

想把「正常输出 + 报错」都存进文件，写法是 > out.txt 2>&1。写成 2>&1 > out.txt 就错了。差别在于「2>&1 复制的是那一刻 stdout 指向哪里」。

# 对：先把 stdout 指向文件，再把 stderr 也指到同一个地方
ls nope > out1.txt 2>&1
cat out1.txt

# 错：此刻 stdout 还指着屏幕，stderr 就被复制成了「屏幕」
ls nope 2>&1 > out2.txt
cat out2.txt
ls: nope: No such file or directory
（out2.txt 是空的，报错跑到屏幕上去了）
记法：从左往右读，&1 的意思是「1 号现在指哪儿，我就指哪儿」。所以 > out.txt 2>&1 读作「1 号去 out.txt，2 号跟着 1 号」——对；2>&1 > out.txt 读作「2 号跟着 1 号（此时是屏幕），然后 1 号去 out.txt」——2 号被留在了屏幕上。
在 bash 里 &> out.txt 一句就能做到同样的事，更省心；但脚本的第一行如果写 #!/bin/sh，&> 不一定支持，还是用 > f 2>&1 最稳。

覆盖还是追加：一个能让脚本「只输出最后一行」的 bug

cd ~/linux-lab
for i in 1 2 3; do
  echo "第 $i 行" > /tmp/loop.txt
done
cat /tmp/loop.txt
第 3 行
循环里写 >，每圈都把文件清空重写，最后只剩最后一遍。改成 >> 才是三条都在。这个 bug 的特征是「程序没报错、文件也有内容、只是少了很多」——比崩溃难查得多。写循环时默认用 >>，除非你明确想重建整个文件。

tee 与 /dev/null

cd ~/linux-lab
grep " 500 " logs/access.log | tee /tmp/err500.log | wc -l
cat /tmp/err500.log
ls nope 2> /dev/null
echo "上一句的退出码: $?"
1
2026-11-20 10:02:30 GET /api/users 500 64
上一句的退出码: 1
tee 的价值：既要存文件又要看结果。不加 tee 的话，命令一接管道，输出就全跑到下一步去了，屏幕上是空的。
2>/dev/null 只丢掉报错、保留正常输出；>/dev/null 2>&1 是「什么都不要」。注意 2>/dev/null 不会改变退出码——上面 echo $? 仍然是 1，说明 ls 失败了。丢掉输出 ≠ 假装成功，脚本里判断成败始终看退出码。

管道的退出码取最后一个，这是个陷阱

ls nope | head -n 1
echo "默认: $?"
set -o pipefail
ls nope | head -n 1
echo "开了 pipefail: $?"
默认: 0
开了 pipefail: 1
默认情况下，管道的退出码只看最后一个命令——ls nope 明明失败了，但 head 成功，整条管道就报成功。在脚本里这意味着「错误被吞掉，后面的步骤照常跑」。
set -o pipefail 让管道里任何一个命令失败，整条就算失败。D024 写脚本时这三个开关会一起用：set -euo pipefail。

3tar：打包和压缩是两件事

tar 只负责「打包」（把多个文件装进一个），压缩是额外加的。所以参数里既有 -c（create）又有 -z（用 gzip 压缩），两个一起写才是 .tar.gz。

要干的事命令记忆
打包并压缩tar -czf out.tar.gz 目录/create zip file
看包里有什么（不解开）tar -tzf out.tar.gztell
解压到当前目录tar -xzf out.tar.gzxtract
解压到指定目录tar -xzf out.tar.gz -C /目标/目录Change dir
打包时排除某些文件tar -czf out.tar.gz --exclude="*.log" 目录/—
cd ~/linux-lab
tar -czf /tmp/lab.tar.gz .
tar -tzf /tmp/lab.tar.gz | head -n 8
mkdir -p /tmp/lab-restore
tar -xzf /tmp/lab.tar.gz -C /tmp/lab-restore
ls /tmp/lab-restore
./
./logs/
./logs/access.log
./logs/old.log
./docs/
./docs/readme.txt
./src/
./src/main.py
docs  logs  my note.txt  src
-f 后面必须紧跟文件名，中间不能塞别的参数。tar -czf out.tar.gz dir 里 out.tar.gz 是 -f 的值，dir 才是要打包的目录。写成 tar -cfz out.tar.gz dir 会把 z 当成文件名，生成一个叫 z 的文件——不报错，只是结果不对。
另外打包时最好先 cd 到目标目录的上一级，用相对路径（tar -czf out.tar.gz myproject）；用绝对路径会把整条 /Users/loogn/... 打进去，解压时还原出一堆嵌套目录。
解压别人的 tar 包之前，一定先 tar -tzf 看一眼内容。tar 包里可以有 ../../ 这种路径，解压时能写到当前目录外面去（叫「tar 路径穿越」）。看一遍列表花三秒，能避免把文件覆盖到系统目录。再谨慎一点：先解到一个空目录里 -C /tmp/check，看完再搬。
.tar.gz 和 .zip 怎么选：给自己备份、给 Linux 服务器传，用 .tar.gz（保留权限位和符号链接）；要发给用 Windows 的人，用 zip -r out.zip 目录，Windows 双击就能开。.tar.gz 在 Windows 资源管理器里是打不开的，别在这上面浪费对方时间。

4vim：只需要会二十个操作，就够改配置文件了

先说清楚为什么非学不可：任何一台 Linux 服务器上都有 vim 或 vi，但不一定有 nano。你今天可能觉得 vim 反人类，等你 ssh 上一台机器、发现只有 vi 时，会庆幸自己练过。

最好的入门方式不是看这一节，是敲这个命令：vimtutor（macOS 自带，中文界面）。它是一份交互式教程，45 分钟做完，比任何速查表都有效。今天的目标是做完第一章到第三章。下面的内容当复习用。

核心只有一件事：你在哪个模式

按 i 按 Esc 普通模式 ────────▶ 插入模式 │ ▲ │ │ └──────────────┘ │ │ 按 : ▼ 命令行模式 ── 输入 wq 回车 ──▶ 存盘退出
模式能干什么怎么进
普通模式移动、删除、复制、粘贴（按键就是命令）打开就是，按 Esc 随时回来
插入模式像普通编辑器一样打字i 光标前插 / a 后插 / o 下一行新开

新手最常卡住的地方：不知道自己在哪个模式，打字全是命令。看到屏幕上出现 -- INSERT -- 就是插入模式；什么都没显示就是普通模式。迷路了就按两下 Esc，回到普通模式再想。这也是为什么很多人「一进 vim 就出不来」——他一直在普通模式里打字，:wq 根本打不进去。

5ssh：不用密码连服务器

D026 要传作品集、D027 要部署服务器，都靠 ssh。现在就把密钥配好，后面两天会省很多事。

一次生成，长期使用

ssh-keygen -t ed25519 -C "loogn@mac"
ls -l ~/.ssh
~/.ssh/ ├── id_ed25519 ← 私钥，绝对不能外传（权限 600） ├── id_ed25519.pub ← 公钥，随便给（权限 644） ├── known_hosts ← 连过的服务器指纹 └── config ← 别名配置（权限 600）
私钥文件（id_ed25519，没有 .pub 后缀的那个）等于你的身份。它泄漏了，别人就能以你的身份 push 代码、登录服务器。三条铁律：① 不复制到任何聊天工具、网盘、笔记软件；② 不放进任何 git 仓库；③ 权限必须是 600——权限太宽时 ssh 会直接拒绝使用这把钥匙，这正是第 1 节那个「权限」的真实应用场景。
ssh-keygen 会让你设一个 passphrase，设了更安全，但要输密码；本机个人用可以不设，直接回车两次。共用电脑必须设。

把公钥装到服务器上

# 有 ssh-copy-id 的话（macOS 自带），一条命令搞定
ssh-copy-id -p 22 用户名@服务器IP

# 没有的话，手动追加到服务器的授权文件里
cat ~/.ssh/id_ed25519.pub | ssh 用户名@服务器IP "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
注意最后那两个 chmod：.ssh 目录 700、authorized_keys 600。这两个数字错了，ssh 会认为「这个文件被别人动过」，直接忽略你的公钥、退回密码登录，而且不告诉你原因。这是配置密钥登录最常见的失败点。

写 config：把长命令变成两个字母

mkdir -p ~/.ssh
vim ~/.ssh/config
chmod 600 ~/.ssh/config
Host myserver
    HostName 192.168.10.20
    User loogn
    Port 22
    IdentityFile ~/.ssh/id_ed25519

Host github.com
    HostName ssh.github.com
    Port 443
    User git
配完之后 ssh myserver 四个字就够了，不用再记 IP、用户名、端口。第二段是给 GitHub 用的——国内 22 端口经常被拦，走 443 端口能通。你的 gl 能正常 push，多半就是靠这一段。

排错：连不上时看这三层

ssh -v myserver 2>&1 | tail -n 20
现象大概率原因怎么查
Connection refused机器开着，但 ssh 服务没跑 / 端口不对nc -vz IP 端口
Connection timed out网络不通，或被防火墙/安全组挡了先 ping IP，再看安全组
还是问密码，公钥没生效.ssh 或 authorized_keys 权限太宽服务器上 chmod 700 ~/.ssh; chmod 600 ~/.ssh/authorized_keys
Permission denied (publickey)公钥没装上，或用了错的钥匙ssh -v 看它试了哪把
WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED服务器重装过，或真的有人在中间确认是自己重装的，再 ssh-keygen -R IP
最后那条警告不要习惯性删掉就重连。它的意思是「这台服务器的指纹变了」——可能是你重装了系统，也可能是有人在中间劫持。只有在你确定自己重装过的情况下，才用 ssh-keygen -R 清掉旧记录。公用网络下见到它，先换网络再说。

6五组命令组合：今天的产出

单条命令不难，难的是把五条串起来解决一件事。这五组覆盖了日常八成场景，每组都跑一遍再写进笔记。

组合 1 · 找出占空间最多的东西

# 当前目录下每个子目录多大，倒序取前 5
du -sh ~/python-learn/* 2>/dev/null | sort -h | tail -n 5

# 找出大于 50MB 的单个文件
find ~ -type f -size +50M 2>/dev/null -exec ls -lh {} \; | sort -k5 -n | tail -n 10
2>/dev/null 在这里是必需的——du 和 find 走到没权限的目录会刷一屏 Permission denied，把真正的结果淹没。这不是「隐藏错误」，是「过滤掉不相关的噪音」，因为你本来就没打算统计那些目录。

组合 2 · 从日志里定位问题

log=~/linux-lab/logs/access.log

# ① 状态码分布
awk '{print $5}' $log | sort | uniq -c | sort -rn

# ② 只看 5xx，带行号
grep -n " 5[0-9][0-9] " $log

# ③ 出错最多的 URL 前 3
awk '$5>=400 {print $4}' $log | sort | uniq -c | sort -rn | head -n 3

# ④ 把错的行单独存一份，同时看有多少条
grep " 5[0-9][0-9] " $log | tee ~/linux-lab/logs/err.log | wc -l
   3 200
   1 500
   1 401
2:2026-11-20 10:00:05 POST /api/login 401 88
5:2026-11-20 10:02:30 GET /api/users 500 64
   1 /api/users
   1 /api/login
1
第 ③ 条里的 $5>=400 是 awk 的条件判断——它比正则更准确，因为不依赖「状态码两边有空格」这种格式假设。awk '$5>=400 {print $4}' 读作「第 5 列的值大于等于 400 时，打印第 4 列」。昨天用 grep 写正则筛 4xx/5xx，今天用 awk 一行就干净了——这就是为什么两个工具都要会。

组合 3 · 打包备份，排除垃圾

cd ~/python-learn
tar -czf ~/backup-python-learn-$(date +%Y%m%d).tar.gz \
    --exclude="__pycache__" \
    --exclude=".git" \
    --exclude="*.pyc" \
    .

ls -lh ~/backup-python-learn-*.tar.gz
--exclude 的路径要写对。打包 . 时，tar 里的路径是 ./xxx，所以 --exclude=".git" 能匹配 ./.git；但如果写成 --exclude="./.git"，某些版本就匹配不上。排除项目不对时，先 tar -tzf 看包里到底有什么，别靠猜。
另外 $(date +%Y%m%d) 会展开成 20261122，这样每次备份都是一个新文件名，不会互相覆盖——D024 的备份脚本就靠这一句。

组合 4 · 批量改名 / 批量加权限

cd ~/linux-lab
mkdir -p rename-demo && cd rename-demo
touch a.txt b.txt c.txt

# 把 .txt 全改成 .md（先 echo 演练，确认无误再执行）
for f in *.txt; do echo "mv \"$f\" \"${f%.txt}.md\""; done

# 确认后去掉 echo 真正执行
for f in *.txt; do mv "$f" "${f%.txt}.md"; done
ls
mv "a.txt" "a.md"
mv "b.txt" "b.md"
mv "c.txt" "c.md"
a.md	b.md	c.md
批量操作前先 echo 演练一遍，这是铁律。上面第一轮循环只打印不执行，用眼睛确认每一条都对，第二遍才真删真改。${f%.txt} 是「去掉结尾的 .txt」，${f%%.*} 是「去掉第一个点之后的所有内容」——一个 % 匹配最短、两个 %% 匹配最长，这个区别在文件名带多个点时很致命。
还有："$f" 外面的引号必须加，否则文件名带空格时又会被切开（昨天的坑）。

组合 5 · 传到远程 / 从远程取回

# 传一个文件上去
scp ~/backup-python-learn-20261122.tar.gz myserver:~/

# 传整个目录（-r）
scp -r ~/python-learn/day22 myserver:~/backup/

# 从服务器拉一个文件下来
scp myserver:/var/log/nginx/access.log ./access-from-server.log

# 更推荐：rsync（断点续传、只传改动部分、能排除）
rsync -avz --exclude="__pycache__" ~/python-learn/day22 myserver:~/backup/
scp 简单，rsync 更适合重复同步。差别在于 scp 每次都全量重传，rsync 只传差异部分。传几十 MB 以上、或者要反复同步同一个目录，用 rsync；偶尔传一个小文件，scp 更省脑子。macOS 两个都自带。
-avz 三个字母：a 保留权限和时间（archive）、v 显示过程、z 传输时压缩。

7练习八道

1–5 在本机就能做，6–8 需要第 5 节配好的 ssh（没有服务器就跳过，D027 再补）。

第 1 题 · 让一个脚本可执行，但其他人只能读

答案 
cd ~/linux-lab
printf '#!/bin/bash\necho "跑了"\n' > hello.sh
chmod 755 hello.sh
ls -l hello.sh
./hello.sh
-rwxr-xr-x  1 loogn  staff  28 Nov 22 19:20 hello.sh
跑了

为什么不用 chmod +x：它会连「其他人」的 x 也加上，变成 rwx--x--x（第 1 节实测过）。755 才是「我能改、别人能读能跑」。
另外注意 ./hello.sh 前面那个 ./ 不能省——直接敲 hello.sh 会在 $PATH 里找，而当前目录通常不在 $PATH 里。这是出于安全考虑：否则你在某个目录里 cd 进去，一个叫 ls 的恶意脚本就会被执行。

第 2 题 · 把 stderr 丢掉，只保留正常输出

答案 
find / -name "ssh_config" 2>/dev/null | head -n 5

2>/dev/null 把报错扔进黑洞，stdout 照常走管道。不写这个，find / 会刷几十屏 Permission denied，真正的结果被埋在中间找不到。

第 3 题 · 一条命令：统计 logs 目录下所有文件的总行数

答案 
cd ~/linux-lab
find logs -type f -exec cat {} + | wc -l
      10

数字取决于你日志里有几行（这里是 access.log 5 行 + old.log 5 行 = 10）。关键是 -exec cat {} + 把所有文件内容拼成一条流，再交给 wc -l。
不要写成 wc -l logs/*——那会每个文件单独给一行，最后再加个 total，你还得自己加总。

第 4 题 · 打包一个目录，排除所有 .log 和 __pycache__

答案 
cd ~/linux-lab
tar -czf /tmp/clean.tar.gz --exclude="*.log" --exclude="__pycache__" .
tar -tzf /tmp/clean.tar.gz

验证一步不能省：tar -tzf 看一眼，确认 access.log 和 old.log 都不在列表里。排除规则写错了不会报错，只会安静地把你不想要的东西打进去。

第 5 题 · 在一份配置文件里把所有 8080 换成 8000，只改这一处

答案 
cp config.conf config.conf.bak 2>/dev/null || touch config.conf
vim config.conf
# 在 vim 里输入：  :%s/8080/8000/g  然后回车，再 :wq

% 表示整个文件，g 表示每行的所有匹配（不加 g 只换每行第一个）。少了 % 就只改光标那一行——这是 vim 替换最容易出的错，改完以为全改了，其实只改了一处。
先 cp 备份：:%s 是全局操作，u 虽然能撤销，但如果你顺手 :wq 又关了文件，就只能靠备份了。

第 6 题 · 看 ssh 到底在做什么

答案 
ssh -vT git@github.com 2>&1 | tail -n 10
debug1: Offering public key: /Users/loogn/.ssh/id_ed25519 ED25519 SHA256:...
debug1: Authentications that can continue: publickey
Hi loogn-yyl! You've successfully authenticated, but GitHub does not provide shell access.

看到 Hi 你的用户名! 就说明密钥通了。中间那行 Offering public key 是它在试哪把钥匙——连不上时就看这一行，试的钥匙不对就是 IdentityFile 配错了。
-T 是「不要分配终端」，-v 是「打印调试信息」，2>&1 把调试信息（走 stderr）也一起接进管道，tail 才能看到——这三样缺一个都看不到输出。

第 7 题 · 给 .ssh 和私钥设正确的权限

答案 
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519
chmod 644 ~/.ssh/id_ed25519.pub
chmod 600 ~/.ssh/config
ls -l ~/.ssh

四种文件四个数，别混：目录 700、私钥 600、公钥 644、config 600。私钥是 600 而不是 400，因为你偶尔要重新生成；公钥 644 因为本来就是要给别人看的。
权限太宽时 ssh 的表现是「默默不用这把钥匙」，然后在 ssh -v 里给你一行 WARNING: UNPROTECTED PRIVATE KEY FILE。不主动看调试信息，根本不知道发生了什么。

第 8 题 · 从服务器拉一个日志文件下来，只看错误行

答案 
scp myserver:/var/log/nginx/access.log ./remote-access.log
awk '$9>=400 {print}' ./remote-access.log | wc -l

注意真 nginx 日志的列号和练习日志不一样：combined 格式第 1 列是 IP、第 9 列是状态码（前面有 IP、两个 -、时间（含空格，实际拆成两列）、请求（含引号，拆成三列））。所以一定要先 head -n 1 看一行，再决定用第几列。
另外 /var/log/nginx/ 普通用户读不了，直接 scp 会 Permission denied——要么先用 sudo 拷一份到有权限的地方，要么配置 ssh 用户对该目录的读权限。

八题里第 2、4、5 是最常用的三个动作：丢掉噪音、打包排除垃圾、改配置文件。这三个练熟，日常维护就不用求助别人了。
