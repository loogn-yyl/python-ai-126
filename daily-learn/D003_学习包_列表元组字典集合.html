1列表：可变的有序序列

字符串是「一串字符且不能改」，列表是「一串任意东西且能改」。就这两点差别，但用法完全不同。

nums = [3, 1, 4, 1, 5]
mixed = [1, "hello", 3.14, True]     # 可以混装不同类型
empty = []
nested = [[1, 2], [3, 4]]            # 可以嵌套

print(nums[0], nums[-1])             # 索引和字符串一样
print(nums[1:3])                     # 切片也一样
print(len(nums))
3 5
[1, 4]
5
和 C 数组的区别：C 的数组长度固定、类型统一、名存实亡（退化成指针）。Python 列表长度随便变、类型随便混、还自带长度。你以后基本不用再关心「开多大」这件事。

增删改：六个必须记住的操作

nums = [3, 1, 4, 1, 5]

nums.append(9)        # 末尾加一个
nums.insert(0, 0)     # 在下标 0 处插入
print(nums)
[0, 3, 1, 4, 1, 5, 9]
nums = [0, 3, 1, 4, 1, 5, 9]

nums.remove(1)        # 删掉「第一个值等于 1」的元素（不是下标 1！）
print(nums)

last = nums.pop()     # 删掉末尾并把它返回
print(last, nums)

del nums[0]           # 按下标删
print(nums)
[0, 3, 4, 1, 5, 9]
9 [0, 3, 4, 1, 5]
[3, 4, 1, 5]
⚠️ remove(1) 删的是「值 1」，del nums[1] 删的是「下标 1 上的东西」。这两个最容易混。列表里有重复值时 remove 只删最先出现的那个。
操作写法说明
末尾追加lst.append(x)最常用，一次加一个
末尾追加一批lst.extend([a,b])把列表「拆开」接上去
指定位置插入lst.insert(i, x)后面元素整体后移，代价 O(n)
按值删除lst.remove(x)找不到会 ValueError
按下标弹出lst.pop(i)不传参数默认弹末尾
按下标删除del lst[i]不返回值
清空lst.clear()变成 []
查找下标lst.index(x)找不到会 ValueError
统计次数lst.count(x)找不到返回 0
是否包含x in lst返回 True/False

排序：sort 和 sorted 的区别（考点）

a = [3, 1, 4, 1, 5]

b = a.sort()              # 原地排序，返回 None
print("a =", a)
print("b =", b)

c = sorted(a, reverse=True)   # 生成新列表，原列表不变
print("a =", a)
print("c =", c)
a = [1, 1, 3, 4, 5]
b = None
a = [1, 1, 3, 4, 5]
c = [5, 4, 3, 1, 1]
⚠️ 这个错误一定要现在就记住：
nums = nums.sort()  →  nums 会变成 None，数据全丢了。

因为 sort() 是原地改列表、返回 None；sorted() 是返回新列表、原列表不动。
规律：列表自己的方法（append / sort / remove / reverse）都是原地改；内置函数（sorted / len / sum / max）都是返回新值。

今天最重要的一节：赋值不是拷贝

a = [1, 2, 3]
b = a                 # 这不是复制！
b.append(4)

print("a =", a)
print("b =", b)
a = [1, 2, 3, 4]
b = [1, 2, 3, 4]
⚠️ 我只改了 b，a 也变了。因为 b = a 只是让两个名字指向同一个列表对象，不是把内容拷一份。

用 C 来理解就通了：int a[3]; int *b = a; —— b 和 a 指向同一块内存，通过 b 改，a 看到的也变。Python 的列表变量本质就是个指针，赋值只是复制指针。

要真正复制一份，用切片或 copy()：

a = [1, 2, 3]
c = a[:]              # 切片 → 新列表
c.append(5)

print("a =", a)
print("c =", c)
a = [1, 2, 3]
c = [1, 2, 3, 5]

浅拷贝的坑：嵌套列表还是要穿透

a = [[1, 2], [3, 4]]
b = a[:]              # 只复制了外层

b[0].append(99)       # 改的是内层列表（还是同一个对象）
print("a =", a)

b.append([5, 6])      # 改外层（这次不会影响 a）
print("a =", a)
print("b =", b)
a = [[1, 2, 99], [3, 4]]
a = [[1, 2, 99], [3, 4]]
b = [[1, 2, 99], [3, 4], [5, 6]]
切片是「浅拷贝」：外层换了个新列表，但里面装的还是原来那些子对象的指针。所以改子列表会穿透。 真要完全独立，用 import copy; copy.deepcopy(a)。

什么时候需要在意：处理二维表格（Excel 数据、矩阵、API 返回的嵌套 JSON）时，浅拷贝的穿透会让你改了一行结果全表都变了。现在知道有这回事，遇到时能想起来就行。

2列表推导式：一行生成列表

昨天第 8 题你用过一次 [int(x) for x in s.split(",")]。这个写法叫列表推导式，是 Python 最标志性的语法，必须写熟。

# 普通写法
sq = []
for x in range(1, 6):
    sq.append(x * x)

# 推导式写法（完全等价）
sq = [x * x for x in range(1, 6)]

print(sq)
[1, 4, 9, 16, 25]

加条件：把 if 写在后面

# 1~10 里的偶数
ev = [x for x in range(1, 11) if x % 2 == 0]
print(ev)

# 把一组单词转大写
words = ["hello", "world"]
print([w.upper() for w in words])
[2, 4, 6, 8, 10]
['HELLO', 'WORLD']
记忆口诀：先说「要什么」（x * x），再说「从哪来」（for x in ...），最后说「筛掉谁」（if ...）。写的时候顺序就是读的顺序。

顺便把其他三个容器也各来一句（后面会用，先混个脸熟）：

d = {k: v for k, v in [("a", 1), ("b", 2)]}    # 字典推导式
s = {x % 3 for x in range(10)}                 # 集合推导式

print(d)
print(s)
{'a': 1, 'b': 2}
{0, 1, 2}
⚠️ 别为了「一行」把推导式写复杂。超过一个 for 加一个 if 就该换回普通循环——推导式是给「简单转换」用的，嵌套两层以上可读性会崩，尤其以后别人要读你的代码。

3元组：不可变的列表

元组的语法几乎和列表一样，区别只有两个：用圆括号、创建后不能改。

t = ("张三", 18, "北京")

print(len(t), t[0], t[-1])
print(t[1:])               # 切片同样支持
print(t[::-1])             # 反转

元组最有用的功能：解包

t = ("张三", 18, "北京")

name, age, city = t        # 一次拆成三个变量
print(name, age, city)

# 用 * 接住剩下的
first, *rest = (1, 2, 3, 4)
print(first, rest)

解包是后面天天要用的东西。遍历字典、读函数返回值、处理 API 返回的 (key, value) 对，全靠它。a, b = b, a 这个交换写法也请直接记住——Python 里不需要临时变量。

单元素元组的坑

print(type((5,)))    # 加了逗号 → 元组
print(type((5)))     # 没加逗号 → 只是加了个括号的 int
<class 'tuple'>
<class 'int'>
⚠️ 只有一个元素的元组，逗号不能省：(5,)。括号在 Python 里只是分组符号，逗号才决定它是元组。(5) 就是整数 5。

既然不能改，为什么还要用它

场景为什么用元组
函数返回多个值return x, y 本质就是返回元组
字典的 key字典 key 必须不可变，元组可以，列表不行
固定配置 / 常量组如 RGB = (255, 0, 0)，语义上就是「不该改」
性能与内存比列表省内存、创建更快

4字典：靠名字找东西

列表靠下标找（第几个），字典靠 key 找（叫什么）。这是两种完全不同的取数思路。

d = {"apple": 3, "banana": 5}

print(d["apple"])

d["orange"] = 2       # 不存在 → 新增
d["apple"] = 10       # 已存在 → 覆盖

print(d)
3
{'apple': 10, 'banana': 5, 'orange': 2}
字典的增和改是同一个写法：d[key] = value。key 不存在就是新增，存在就是覆盖——不需要先判断。

取值的两种方式：[] 和 get()

d = {"apple": 10}

print(d.get("pear"))          # 不存在 → 返回 None，不报错
print(d.get("pear", 0))       # 不存在 → 返回你给的默认值
print(d["pear"])              # 不存在 → 直接报错
None
0
Traceback ... KeyError: 'pear'
（前两行正常输出；第三行在程序遇到时才会中断）
⚠️ 读字典优先用 get()。数据来源不可控时（用户输入、API 返回、CSV 列名），key 不一定存在，用 [] 会让整个程序崩在 KeyError。这条和第 1 节「能用切片就别用索引」是同一个思路——选不会崩的写法。

遍历的三个姿势

d = {"apple": 10, "banana": 5, "orange": 2}

print(list(d.keys()))       # 所有 key
print(list(d.values()))     # 所有 value
print(list(d.items()))      # 所有 (key, value) 对

for k, v in d.items():      # 最常用：同时拿 key 和 value
    print(k, v)
['apple', 'banana', 'orange']
[10, 5, 2]
[('apple', 10), ('banana', 5), ('orange', 2)]
apple 10
banana 5
orange 2
给 keys() / values() / items() 外面套 list() 只是为了看清楚内容。实际遍历时不用套：for k in d: 直接就是遍历 key。

计数：字典最经典的用法

sentence = "to be or not to be"
freq = {}

for w in sentence.split():
    freq[w] = freq.get(w, 0) + 1

print(freq)
{'to': 2, 'be': 2, 'or': 1, 'not': 1}
freq.get(w, 0) + 1 这一行是核心。意思是：字典里有 w 就拿它的值，没有就当 0，然后加 1 写回去。如果是第一次遇到这个词，get 返回 0，加 1 后存进去 1——不用写 if w in freq 判断。

这个模式（词频统计）就是后面做文本分析、推荐系统、数据聚合的雏形。

字典的 key 有什么要求

d = {}
d[(1, 2)] = "元组当 key，可以"
print(d)

d[[1, 2]] = "列表当 key"
{(1, 2): '元组当 key，可以'}
Traceback ... TypeError: unhashable type: 'list'
（只有第一行能输出，第二行写完立刻报错）
⚠️ key 必须「不可变」（准确说是可哈希）。数字、字符串、元组可以；列表、字典、集合不行。
直觉理解：字典靠 key 算出一个位置来存值，如果 key 能被改，改完之后就找不回来了。所以可变的东西不能当 key。

嵌套：这才是真实数据的样子

student = {
    "name": "张三",
    "age": 18,
    "scores": {"语文": 88, "数学": 95}
}

print(student["name"])
print(student["scores"]["数学"])       # 一层层取下去

student["scores"]["英语"] = 76         # 直接往里加
print(student["scores"])
张三
95
{'语文': 88, '数学': 95, '英语': 76}
记住这个结构。你以后从任何 API 拿到的 JSON、读进来的每一行配置，都是这种「字典套字典 / 字典套列表」的形状。会用 [] 一层层剥进去，就等于会处理真实数据了。

5集合：去重和二选一之外的能力

集合就两件事：去重 和 集合运算。看着简单，但用得极多。

s = {1, 2, 2, 3, 3, 3}
print(s, len(s))          # 自动去重

lst = [1, 2, 2, 3, 1]
print(list(set(lst)))     # 列表去重的经典写法
{1, 2, 3} 3
[1, 2, 3]
⚠️ 两个坑：
① 空集合要写 set()，不能写 {} —— {} 是空字典。
② set() 去重会打乱顺序，上例输出 [1, 2, 3] 只是碰巧。
为什么说「碰巧」：集合内部靠哈希值决定元素放在哪个位置，而打印时是按位置顺序输出的。

· 小整数的哈希值就是它自己（hash(1)=1, hash(2)=2），所以整数集合看起来总是「从小到大」，像个错觉。
· 字符串的哈希值每次运行都不同（Python 启动时会加随机种子），所以中文/英文集合每次打印顺序都可能变。

动手验证一下，连跑三次看结果是否一样： 
print(set(["张三", "李四", "王五", "赵六"]))
结论：别依赖集合的打印顺序。要稳定输出就套 sorted()；要「去重且保持原来的顺序」，用第 7 节第 2 题的循环写法。

集合运算：交集、并集、差集

a = {1, 2, 3, 4}
b = {3, 4, 5}

print(a & b)      # 交集：两个都有
print(a | b)      # 并集：合起来去重
print(a - b)      # 差集：在 a 不在 b
print(a ^ b)      # 对称差：只在一个里的
{3, 4}
{1, 2, 3, 4, 5}
{1, 2}
{1, 2, 5}
符号记忆：& 像「与」→ 都要有；| 像「或」→ 有一个就行；- 就是减法。
这三个符号对应 intersection() / union() / difference()，效果一样，符号更短。
实际用在哪：两个用户群的共同好友（交集）、推荐系统里「排除已看过」（差集）、统计今天有多少独立访客（去重）。做数据处理时，「去重」这一步几乎每个项目都要做。

判断「在不在里面」的速度差异

这条对以后处理大数据很关键，现在先建立一个直觉：

操作列表字典集合
放一个元素到末尾O(1)O(1)O(1)

⚠️ 最实用的一条：判断「某个值在不在」时，别用列表，用集合。

列表要一个一个比，1 万条数据就要比 1 万次；集合是算出一个位置直接跳过去，不管多少条都差不多快。

后面处理用户 ID 黑名单、敏感词表、已读集合这类「只需要判断存在」的场景，写成 if x in some_set 会比 if x in some_list 快几个数量级。

选型口诀

① 一串顺序重要的数据 → 列表
② 一条不该被改的记录（坐标、RGB、函数返回多值） → 元组
③ 每个东西有名字，要按名字取 → 字典
④ 只关心「有没有」「去重」「交并差」 → 集合

拿不准的时候：先用列表。99% 的场景列表都够，等发现「我要按名字取值」再换字典，发现「要判重」再换集合。

三个重点：
第 2 题 —— if x not in seen 是「去重保序」的标准解法。别图省事用 set，顺序会丢。
第 5 题 —— max(scores, key=scores.get) 这个写法值得背下来：max 默认比 key，加了 key= 参数就改成「按 value 比，但返回 key」。
第 8 题 —— lambda x: x[1] 的意思是「拿每个元组的第 2 个元素（分数）来比较」。这是排序题的标准套路，后面会反复出现。
⚠️ 第 6 题为什么外面要套 sorted()：集合是无序的，直接 print 一个集合，每次运行打印出来的顺序都可能不一样——因为 Python 每次启动都会给字符串换一套随机哈希值。

你可以自己试试：把 sorted() 去掉，连跑三次 python p6_friends.py，看输出顺序变不变。

实际意义：凡是「要给人看」或「要写进文件做对比」的输出，内容来自集合就套一个 sorted()。否则今天跑出来是这样，明天跑出来是那样，出了问题根本没法复现。
