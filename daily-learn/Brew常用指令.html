Homebrew 常用指令速查

formula vs cask · 12 类命令 · 依赖排查 · 五条纪律

配套文档：学习包索引 · GitHub 注册与每日上传 · Mac 环境配置 · Brew 速查 · Git 速查
配套文档：Mac新手环境配置指南.html 第 4 步（安装 Homebrew）
适用：Mac（Apple Silicon / Intel 通用）。本机 brew 前缀为 /opt/homebrew，命令本身不区分芯片。

0. 先搞懂两个词

Homebrew 把软件分成两类，这是最容易搞混的地方：

类型是什么装在哪例子
formula命令行工具、库/opt/homebrew 内部，自动加进 PATHgit、python@3.12、wget、uv
cask图形界面 App（.app）/Applicationsvisual-studio-code、applite、atoll

判断方法：有图标的 App 就是 cask，要在终端里敲的就是 formula。 装 cask 必须带 --cask，装 formula 不加。

1. 安装

brew install git                 # 装 formula
brew install --cask visual-studio-code    # 装 GUI App

brew install wget curl jq        # 一次装多个
brew install --cask --no-quarantine <app>  # 装完不弹「无法验证开发者」
别加 sudo。Homebrew 明确禁止用 root 运行，加了会报错，硬来会搞坏权限。

2. 查看装了什么

brew list                    # 全部（含依赖，列表很长）
brew list --formula          # 只看命令行工具
brew list --cask             # 只看 GUI App
brew list --versions git     # 查某个包的版本

brew leaves                  # ★ 只看「你主动装的」，过滤掉所有被依赖的包
brew info git                # 包的详情：版本、依赖、装在哪、是否最新

brew list vs brew leaves 的区别值得记住：brew list 会把自动安装的依赖一起列出来（本机 17 个），brew leaves 只列你没被别人依赖的顶层包（本机 4 个：git、python@3.12、uv、wget）。想知道"我到底装了什么"，永远用 brew leaves。

3. 搜索

brew search python           # 搜 formula
brew search --cask chrome    # 搜 GUI App
brew search --cask /gmail/   # 斜杠包起来 = 正则精确匹配

brew info --cask mimestream  # 装之前先看详情（版本、官网、是否废弃）
brew home git                # 直接打开官网

4. 更新与升级（两件事不一样）

brew update          # 只更新「软件清单索引」，不升级任何软件
brew outdated        # 列出哪些包有新版本（不改动任何东西）
brew upgrade         # 升级全部（新版默认同时升级 formula 和 cask）
brew upgrade git     # 只升级指定包

日常维护一条龙（建议每月一次）：

brew update && brew upgrade && brew cleanup

brew update 跑得慢是正常的（在拉 Git 仓库），不是卡死。

5. 卸载

brew uninstall git                    # 卸 formula
brew uninstall --cask applite         # 卸 GUI App
brew uninstall --zap --cask applite   # 卸 App 并清掉它的配置残留（更彻底）

brew reinstall git                    # 装坏了先试这个，比重装省事

不要手动删 /opt/homebrew 里的文件。 brew 靠内部的符号链接和元数据工作，手删会让状态错乱，之后 brew doctor 一堆红。要删就走 uninstall。

6. 清理（省磁盘）

brew cleanup -n        # ★ 先干跑，只展示「将要删什么」，不动手
brew cleanup           # 删旧版本安装包和过期缓存
brew cleanup -s        # 连下载缓存一起清（占地最大的一步）
brew autoremove --dry-run   # 看哪些依赖已经没人用了
brew autoremove             # 真正删掉孤儿依赖

顺序建议：先 -n / --dry-run 看清单，确认没问题再执行。不要手动 uninstall 依赖包——一旦还有别的软件依赖它，会连带搞坏。

7. 依赖关系排查

brew deps --tree --installed git      # 树状看 git 依赖了谁
brew deps --installed --installed     # 所有已装包的依赖关系
brew uses --installed openssl@3       # ★ 反查：谁在用 openssl@3

brew uses 是卸载前的必查命令。看到某个包占地方想删，先跑一次，输出有内容就说明不能删。

多个版本共存是正常的，例如本机的 openssl@3 和 openssl@4——不同软件锁定了不同大版本（python@3.12 认 3，新版 git 已迁到 4）。这不是冗余，别清理。

8. 后台服务（MySQL / Redis 会用到）

brew services list                  # 看所有服务状态
brew services start mysql           # 启动 + 开机自启
brew services stop mysql            # 停止 + 取消开机自启
brew services restart mysql         # 重启
brew services run mysql             # 只本次运行，不开机自启（临时用）

学习阶段建议用 run：开机不自启，不占后台资源，用完就没了。确认长期要用再改 start。

9. 换 Mac 一键恢复

# 老机器：把已装清单导出成一个文件
brew bundle dump --file=~/Brewfile --force

# 新机器：装好 Homebrew 后，一条命令全部装回来
brew bundle install --file=~/Brewfile

Brewfile 是纯文本，可以直接放进 GitHub 仓库，等于给开发环境做了版本管理。

10. 出问题先跑这两条

brew doctor      # 体检，按提示逐条修（黄色警告多数可忽略，红色要处理）
brew config      # 看当前配置：前缀、芯片、Xcode 版本、镜像设置
brew update-reset   # 索引彻底乱了才用（会重置 brew 自己的仓库）

brew doctor 输出的 Warning: ... 大部分是"你装了某个 App 在 /Applications 里，可能影响 brew"这类无害提示，不用见红就慌。

11. 高频场景对照

12. 五条纪律

  1. 不给 brew 加 sudo —— 会报错，硬来会破坏权限。
  2. 不手动删 /opt/homebrew 里的任何文件 —— 卸载一律走 brew uninstall。
  3. 不手动删依赖包 —— 删前先 brew uses --installed 查一下谁在用。
  4. 不把 brew 装到外接硬盘或改前缀 —— 符号链接依赖固定路径，一挪全断。
  5. cleanup / autoremove 先加 -n / --dry-run —— 看一眼再动手，养成习惯。
