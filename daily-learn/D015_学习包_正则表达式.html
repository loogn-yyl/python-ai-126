1先看看字符串方法为什么会碰壁

前两周处理文本，靠的是 split()、in、切片。这些方法对付「格式永远不变」的文本够用，一旦格式有变化就撑不住了。拿一条 nginx 日志试试：

line = '127.0.0.1 - - [13/Nov/2026:02:15:33 +0800] "GET /index.html HTTP/1.1" 200 512'

print("IP      :", line.split()[0])
print("第 4 段  :", line.split()[3])
print("第 9 段  :", line.split()[8])

# 换一种日志格式，同一个下标就错位了
line2 = '127.0.0.1 [13/Nov/2026:02:15:33] "GET /index.html" 200'
print("第 9 段  :", line2.split()[8] if len(line2.split()) > 8 else "IndexError")
print("状态码在哪:", [x for x in line2.split() if x.isdigit()])
IP      : 127.0.0.1
第 4 段  : [13/Nov/2026:02:15:33
第 9 段  : 200
第 9 段  : IndexError
状态码在哪: ['200']

三处都出问题了，每一处的原因还不一样：

  • 时间被切断了。[13/Nov/2026:02:15:33 后面还跟着 +0800]，因为中间有空格，split() 就把它劈成两半。
  • 下标是假的。split()[8] 能拿到 200，纯属这条日志刚好这么长。换一条格式稍变的，直接 IndexError。
  • isdigit() 也不可靠。它只判断「这一段是不是纯数字」，但日志里哪一段是状态码、哪一段是响应大小，它不知道。这条日志里 /index.html 没有数字所以侥幸，换成 /api/v2/user 就会多出杂音。
问题的本质：split() 只认「空格」，不认「意思」。
它把字符串切成段，但不知道哪一段是 IP、哪一段是状态码。正则解决的正是这件事——你描述「状态码长这样：三个数字，夹在引号和空格之间」，而不是「第 9 段」。

2四个函数就够用了

re 模块有十几个函数，日常真正用到的就四个。先记住它们的区别，比记语法重要得多。

import re

text = "订单 A1024 金额 299 元，订单 A2048 金额 1580 元"

print("match  :", re.match(r"A\d+", text))
print("search :", re.search(r"A\d+", text))

print("group()  :", m.group())
print("group(1) :", m.group(1))

函数找几个从哪里找返回什么典型用途
match1 个只从位置 0Match 或 None校验整条格式（配 $ 或改用 fullmatch）
search1 个全串，第一个Match 或 None从一行里找出想要的那一小段

最关键的一条：match 不是「更严格的 search」

很多人以为 match 是「必须整条字符串完全匹配」，其实它只管起点，不管结尾。只管开头、不管结尾这个描述才是准确的：

import re

print("1", re.match(r"\d+", "abc123"))
print("2", re.search(r"\d+", "abc123"))
print("3", re.match(r"abc", "abcdef"))
print("4", re.fullmatch(r"\d+", "123"))
print("5", re.fullmatch(r"\d+", "123abc"))
print("6", re.search(r"^abc", "xxabc"))
print("7", re.search(r"abc$", "abcxx"))
1 None
2 <re.Match object; span=(3, 6), match='123'>
3 <re.Match object; span=(0, 3), match='abc'>
4 <re.Match object; span=(0, 3), match='123'>
5 None
6 None
7 None
行结果说明
1 / 2None / 命中\d+ 不在开头，match 立刻放弃，search 往后扫到了
3命中abcdef 只匹配了前三个字符 就成功了，剩下的 def 它不管
4 / 5命中 / None要「整条都得是数字」，只有 fullmatch 能做到。校验用 fullmatch，不要用 match
6None^ 锚定开头，search 也救不了——它不会从中间再试一次开头
这是最常见的错误来源：用 match 做格式校验。
re.match(r"\d{11}", "13800001111xyz") 会返回 Match，看着像「手机号合法」，其实后面还跟着三个字母。校验一律用 fullmatch，或者自己给正则加上 $。
还有一个小习惯，现在就该养成：正则字符串一律加 r 前缀。
r"\d+" 里的反斜杠是字面意思的反斜杠，直接交给 re 去解释；不加 r 的话，Python 会先自己解释一遍 \d，而它不认识这个转义，虽然碰巧能跑，但只要正则里出现 \b \n \t 就必错。第 3 节末尾会演示。

3元字符：把「形状」翻译成符号

这一张表是正则的全部家底。不用背，但要能看懂——写的时候照着查，查两次就记住了。

符号含义例子
\d一个数字（等价 [0-9]）r"\d{3}" → 200
\D一个非数字r"\D+" → 连续的非数字
\w字母、数字、下划线、汉字r"\w+" → abc / 中文
\W非 \w（空格、标点）r"\W" → 空格 ，
\s空白：空格 / 制表符 / 换行r"\s+" → 压缩连续空白
\S非空白（抓「不含空格的一串」最常用）r"\S+" → /index.html
.除换行外的任意一个字符r"a.c" → abc / a1c
^ $开头 / 结尾r"^\d+$" → 整条都是数字
*前一个字符 0 次或多次r"ab*" → a / ab / abbb
+前一个字符 1 次或多次r"ab+" → 至少一个 b（a 不算）
?前一个字符 0 次或 1 次r"https?" → http / https
{n} {n,m}恰好 n 次 / n 到 m 次r"\d{11}" → 11 位数字
[abc]这个位置是 a、b、c 之一r"[Gg]et" → Get / get
[^abc]这个位置不是 a、b、cr"[^\]]+" → 直到 ] 之前的所有内容
|或r"GET|POST"
()分组（见第 4 节）r"(\d{4})-(\d{2})"

跑一遍看它到底抓到了什么——尤其是 \w 对汉字的态度，这个和 C 完全不同：

最后两行是本节最重要的两行

"\bword" 长度是 5，因为 \b 在 Python 普通字符串里是退格符（'\x08'），而 r"\bword" 长度是 6，反斜杠和 b 各算一个字符。

两者在正则里的意思天差地别：\b 是「单词边界」——匹配位置，不消耗字符。r"\bword\b" 的意思是「word 前后不能紧挨着字母」。但你如果写成 "\bword\b"，它变成了「退格 + word + 退格」，永远匹配不到任何东西。

不加 r 前缀的三个必错场景：
① \b 单词边界 → 变成退格符
② \n \t → 变成换行和制表符，正则里的 `\n` 应该交给 re 解释
③ Windows 路径 "C:\Users\new" → \U \n 都被转义了
规则很短：写正则的地方，字符串一律 r"..."。没有例外。
顺便记住 \w 认汉字这件事。以前 C 语言里处理中文字符要一堆判断，Python 3 的 \w 默认就包含 Unicode 字母，所以 r"\w+" 一次能抓出「中文」两个字。代价是你写 r"\w+" 想抓英文单词时，它会把中文一起吞了。真要限定 ASCII，用 r"[a-zA-Z_]+" 或加 re.ASCII 标志。

4分组：一次匹配，多处取值

不带括号的正则只能告诉你「找到了」。加了括号，它才能告诉你「每一部分各是什么」——这是正则从「能找」变成「能解析」的分界线。

import re

s = "张三 13800001111 李四 13900002222 王五 13700003333"

print("简单分组:", re.findall(r"(\S+) (\d{11})", s))
print()
pat = re.compile(r"(?P<name>\S+) (?P<phone>\d{11})")
for m in pat.finditer(s):
    print(m.groupdict())
print()
print("非捕获组:", re.findall(r"(?:\S+) (\d{11})", s))
print("整个匹配:", [m.group(0) for m in pat.finditer(s)])
简单分组: [('张三', '13800001111'), ('李四', '13900002222'), ('王五', '13700003333')]

{'name': '张三', 'phone': '13800001111'}
{'name': '李四', 'phone': '13900002222'}
{'name': '王五', 'phone': '13700003333'}

非捕获组: ['13800001111', '13900002222', '13700003333']
整个匹配: ['张三 13800001111', '李四 13900002222', '王五 13700003333']
写法名字能取值吗什么时候用
(...)捕获组group(1)，下标从 1 开始要取出这一部分
(?P<name>...)命名分组group("name") / groupdict()组数超过 2 个就用它
(?:...)非捕获组不能只想把量词作用在一串上，但不想要这个值

为什么要用命名分组

三个组以上，group(3) 这种写法就没人看得懂了。更麻烦的是改需求的时候：你在正则中间插了一个新的捕获组，后面所有 group(2) group(3) 全部错位，而且不会报错——它只是悄悄取到了另一个值。

结论很明确：只要组数 ≥ 2，一律用命名分组。
groupdict() 直接给你一个字典，键就是你在正则里起的名字，这跟 D011 学的 dataclass 是一路思路——让数据自己说明自己是什么，而不是靠位置。

findall 和 finditer 的区别

看上面的输出：findall 在有分组时返回的是元组列表，你拿不到「整个匹配」和「位置」。要这些信息就得用 finditer，它返回 Match 对象，每个对象上有 group()、groupdict()、start()、span()。

还有一个反直觉的点：findall 只返回「最外层分组」的内容。
正则里有一个组时，findall 返回的是这个组的列表，不是整个匹配；有两个以上，返回元组列表。想看整个匹配，要么用 group(0) 配 finditer，要么把整体也包一层括号。

5贪婪与非贪婪：多出来的那一个问号

这是正则最容易被绊住的地方，但它的机制其实只有一句话：量词默认贪婪，先吃到最远，再往回退。

import re

html = '<a href="a.html">A</a> <a href="b.html">B</a>'

print("贪婪  :", re.findall(r'<a href="(.*)">', html))
print("非贪婪:", re.findall(r'<a href="(.*?)">', html))
print()
s = "a1b2c3"
print("贪婪  \\d+ :", re.findall(r"\d+", s))
print("贪婪  .+  :", re.search(r".+", s).group())
print("非贪婪 .+? :", re.search(r".+?", s).group())
print()
print("为什么 .+? 只到 1 :", re.search(r".+?(\d)", s).groups())
贪婪  : ['a.html">A</a> <a href="b.html']
非贪婪: ['a.html', 'b.html']

贪婪  \d+ : ['1', '2', '3']
贪婪  .+  : a1b2c3
非贪婪 .+? : a

为什么 .+? 只到 1 : ('1',)

第一组结果最能说明问题。贪婪版本抓回来的是 a.html">A</a> <a href="b.html——它把两个标签之间的东西全吞了。因为 .* 会一路吃到整行末尾，然后发现后面还要求有 ，于是往后退，退到最后一个 "> 才停下。

非贪婪版本加了 ?，逻辑反过来：先尽量少地吃，每吃一个就试一下后面能不能接上。吃到 a.html 时后面正好是 ">，立刻收工。

写法策略用在哪
.* .+ \d+贪婪：先吃到底，再回退想抓「最后一段」、整行内容
.*? .+? \d+?非贪婪：先吃最少，逐步加抓「成对符号之间」的所有内容——标签、引号、括号
怎么判断该用哪个？看右边界是否存在。
如果正则最后有明确的「结束标记」（">、]、"），而且这个标记在一行里可能出现多次，就用非贪婪。
如果整个模式就是「一直吃到行尾」，那贪婪反而是对的，写 .*$ 就行。

最后一行 .+?(\d) 的结果是 ('1',)，值得单独看：非贪婪的 .+? 最少要吃 1 个字符（+ 保证的），所以它先吃 a，然后检查后面能不能接上 \d——接得上，就是 1，立刻成功。它不是「抓最短的数字」，而是「整体最早成功的那一次匹配」。

6实战：把一条日志拆成六个字段

现在把前面的东西拼起来。目标：从 nginx 标准日志里取出 IP、时间、方法、路径、状态码、响应大小。

第一步：先写正则，逐段对

import re

LOG = '127.0.0.1 - - [13/Nov/2026:02:15:33 +0800] "GET /index.html HTTP/1.1" 200 512'

PATTERN = re.compile(
    r'(?P<ip>\d{1,3}(?:\.\d{1,3}){3})'
    r' - - '
    r'\[(?P<time>[^\]]+)\]'
    r' "(?P<method>[A-Z]+) (?P<path>\S+) HTTP/[\d.]+"'
    r' (?P<status>\d{3})'
    r' (?P<size>\d+)'
)

m = PATTERN.match(LOG)
print(m.groupdict())
print()
print("IP     :", m.group("ip"))
print("时间    :", m.group("time"))
print("方法    :", m.group("method"))
print("路径    :", m.group("path"))
print("状态码  :", m.group("status"))
print("大小    :", m.group("size"))

逐段拆开看，每一段都对应日志里的一截：

片段对应日志里的为什么这么写
\d{1,3}(?:\.\d{1,3}){3}127.0.0.1四段数字用点连。用非捕获组 (?:...) 包住「点 + 数字」，让它重复三次——如果写成 (...)，会多出一个没用的捕获组
\[(?P<time>[^\]]+)\][13/Nov/... +0800][^\]]+ 而不是 .+：时间里有空格，.+ 会一直吃到行尾；[^\]]+ 明确表示「直到右方括号为止」
(?P<path>\S+)/index.html\S+ 而不是 \w+：路径里有 / 和 .，\w 不认
HTTP/[\d.]+HTTP/1.1版本号可能变成 2 或 1.0，用 [\d.]+ 都吃得下
(?P<status>\d{3})200状态码固定三位，写死比 \d+ 更准
两个高频错误，都在这张表里：
① 该用 [^\]]+ 的地方用了 .+——因为 .+ 是贪婪的，会越过右方括号一路吃到行尾，然后回退到最后一个 ]。
② 该用 \S+ 的地方用了 \w+——路径 /api/user 会被切成 api，前面的斜杠直接丢了，而且不报错。

第二步：多行 + 容错

真实日志一定有脏行。解析器必须能跳过坏行继续跑，而不是一遇到脏数据就整个崩掉。这是 D006 学的异常处理在这里的具体用法：

import re

LOG_LINES = """127.0.0.1 - - [13/Nov/2026:02:15:33 +0800] "GET /index.html HTTP/1.1" 200 512
10.0.0.5 - - [13/Nov/2026:02:15:35 +0800] "POST /api/login HTTP/1.1" 200 128
10.0.0.5 - - [13/Nov/2026:02:15:36 +0800] "GET /api/user HTTP/1.1" 401 64
192.168.1.9 - - [13/Nov/2026:02:16:01 +0800] "GET /static/app.js HTTP/1.1" 304 0
坏行这一行故意不符合格式
127.0.0.1 - - [13/Nov/2026:02:16:10 +0800] "GET /missing HTTP/1.1" 404 32""".split("\n")

PATTERN = re.compile(
    r'(?P<ip>\d{1,3}(?:\.\d{1,3}){3}) - - '
    r'\[(?P<time>[^\]]+)\] '
    r'"(?P<method>[A-Z]+) (?P<path>\S+) HTTP/[\d.]+" '
    r'(?P<status>\d{3}) (?P<size>\d+)'
)

rows, bad = [], []
for line in LOG_LINES:
    m = PATTERN.match(line)
    if m:
        rows.append(m.groupdict())
    else:
        bad.append(line)

print("成功解析:", len(rows), "行")
print("解析失败:", len(bad), "行")
print()
for r in rows:
    print(f"{r['ip']:<15} {r['time'][:20]:<20} {r['method']:<4} {r['path']:<18} {r['status']} {r['size']}")

很多人写解析器只写 if m: 那一支，坏行被默默丢掉，你永远不知道有多少条没解析到。等哪天统计数字对不上，你连从哪查起都不知道。把「解析失败的行」收集起来，是数据处理的第一条纪律。

第 1 题 · 抓邮箱

import re

text = "联系 zs@example.com 或 ls@test.org，无效的 a@b"
print("邮箱:", re.findall(r"[\w.+-]+@[\w-]+\.[\w.]+", text))
邮箱: ['zs@example.com', 'ls@test.org']

[\w.+-]+ 里那个 . 在字符集内部就是普通字符，不用转义；而 @[\w-]+\.[\w.]+ 里的 \. 在字符集外面，必须转义，否则它会匹配任意字符，a@bc 也会被当成合法邮箱。

第 2 题 · 校验手机号

import re

print("手机:", bool(re.fullmatch(r"1[3-9]\d{9}", "13800001111")))
print("假手机:", bool(re.fullmatch(r"1[3-9]\d{9}", "1380000111")))
手机: True
假手机: False

试着把 fullmatch 换成 match，再拿 "13800001111abc" 测一次——你会得到 True。这就是第 2 节那个警告的实证。

第 3 题 · 提取域名

import re

urls = ["https://a.com/x", "http://b.org/y", "ftp://c.net"]
print("域名:", [re.search(r"://([^/]+)", u).group(1) for u in urls])
域名: ['a.com', 'b.org', 'c.net']

用 [^/]+ 而不是 \w+\.\w+：域名里可能有连字符、可能有端口号 :8080，[^/]+ 表示「从 :// 之后一直取到第一个斜杠」，不猜具体形状就不会漏。

第 4 题 · 改日期格式（反向引用）

import re

s = "2026-11-13 发布，2026-12-01 更新"
print("改格式:", re.sub(r"(\d{4})-(\d{2})-(\d{2})", r"\2/\3/\1", s))
改格式: 11/13/2026 发布，12/01/2026 更新

替换串里的 \1 \2 \3 叫反向引用，代表「第 1、2、3 个分组抓到的东西」。注意替换串也加了 r 前缀——不加的话 \1 会变成八进制转义字符，输出一堆看不见的控制符。

第 5 题 · 命名分组版

import re

s = "2026-11-13 发布，2026-12-01 更新"
print("命名版 :", re.sub(r"(?P<y>\d{4})-(?P<m>\d{2})-(?P<d>\d{2})",
                        r"\g<d>.\g<m>.\g<y>", s))
命名版 : 13.11.2026 发布，01.12.2026 更新

替换串里引用命名分组必须写 \g<name>，不能写 \name——后者会被当成「反斜杠 + 字母 n」。

第 6 题 · 抓所有 h2

import re

page = "<h2>第一章</h2><p>x</p><h2>第二章</h2>"
print("标题:", re.findall(r"<h2>(.*?)</h2>", page))
标题: ['第一章', '第二章']

去掉 . 后面的 ? 再跑一次，会得到 ['第一章</h2><p>x</p><h2>第二章']——一个元素，两个标题粘在一起。这就是第 5 节那个贪婪问题的原样重现。

第 7 题 · 统计状态码

import re
from collections import Counter

LOG = """127.0.0.1 - - [13/Nov/2026:02:15:33 +0800] "GET /index.html HTTP/1.1" 200 512
10.0.0.5 - - [13/Nov/2026:02:15:35 +0800] "POST /api/login HTTP/1.1" 200 128
10.0.0.5 - - [13/Nov/2026:02:15:36 +0800] "GET /api/user HTTP/1.1" 401 64
192.168.1.9 - - [13/Nov/2026:02:16:01 +0800] "GET /static/app.js HTTP/1.1" 304 0
127.0.0.1 - - [13/Nov/2026:02:16:10 +0800] "GET /missing HTTP/1.1" 404 32"""

codes = re.findall(r'"\s(\d{3})\s', LOG)
print("抓到的状态码:", codes)
print("统计:", sorted(Counter(codes).items()))
抓到的状态码: ['200', '200', '401', '304', '404']
统计: [('200', 2), ('304', 1), ('401', 1), ('404', 1)]

这题的正则刻意写得很脆弱："\s(\d{3})\s 依赖「状态码前面紧贴着引号加空格」，换一行 "GET /x HTTP/1.1" 200 512 能过，但 "-" 400 0 这种没引号的就漏了。
想清楚一件事：抓字段用第 6 节那个完整正则，别为了省事写半截模式。这里只是演示「统计」这一步该怎么写。

第 8 题 · 带行号的报错

import re

PATTERN = re.compile(
    r'(?P<ip>\d{1,3}(?:\.\d{1,3}){3}) - - '
    r'\[(?P<time>[^\]]+)\] '
    r'"(?P<method>[A-Z]+) (?P<path>\S+) HTTP/[\d.]+" '
    r'(?P<status>\d{3}) (?P<size>\d+)'
)


def parse_file(lines):
    ok, fail = [], 0
    for no, line in enumerate(lines, 1):
        m = PATTERN.match(line)
        if m:
            ok.append(m.groupdict())
        else:
            fail += 1
            print(f"  第 {no} 行解析失败: {line[:30]}")
    return len(ok), fail


lines = [
    '127.0.0.1 - - [13/Nov/2026:02:15:33 +0800] "GET /a HTTP/1.1" 200 10',
    '这一行是坏的',
    '10.0.0.5 - - [13/Nov/2026:02:15:35 +0800] "GET /b HTTP/1.1" 404 0',
]
ok, fail = parse_file(lines)
print(f"成功 {ok} 行，失败 {fail} 行")
  第 2 行解析失败: 这一行是坏的
成功 2 行，失败 1 行

enumerate(lines, 1) 那个 1 很关键——默认从 0 开始，但跟人说「第几行」时没人从 0 数。这种小地方错了，你去日志文件里翻第 2 行，看到的是第 3 行，能白找半小时。

# D015 笔记 · 正则表达式

## 一句话
正则不是「更复杂的字符串方法」，是「描述形状」——告诉程序长什么样，而不是第几段。
split() 只认空格，不认意思；格式一变就错位，而且不报错。

## 四个函数
- match     : 只从位置 0 开始匹配 —— 不是「整条必须匹配」
- search    : 全串找第一个
- findall   : 全串找全部，有分组返回元组列表
- sub       : 替换，替换串里可用 \1 \g<name>
- fullmatch : 整条都必须匹配 —— 校验用这个，不要用 match

## 元字符
\d 数字 / \w 字母数字下划线（含汉字）/ \s 空白 / . 任意（除换行）
* 0+ / + 1+ / ? 0或1 / {n} / {n,m} / [abc] / [^abc] / | / ( )
^ 开头  $ 结尾

## r 前缀（必须）
r"\bword" 长度 6（反斜杠 + b + word）
"\bword"  长度 5（退格符 + word）
必错三场景：\b 单词边界 / \n \t / Windows 路径
规矩：写正则的地方，字符串一律 r"...". 没有例外。

## 分组
(...)        捕获组，group(1) 从 1 开始
(?P<name>...) 命名分组，groupdict() 直接拿字典 ★组数≥2 就用它
(?:...)      非捕获组，只想让量词作用在一串上
findall 只返回最外层分组的内容；要 group(0) 和位置就用 finditer

## 贪婪 vs 非贪婪
.*   先吃到最远再回退 —— 抓「成对符号之间」会吞掉中间的
.*?  先吃最少再逐步加 —— 抓标签/引号/括号内的内容必须用它
判断：右边界是否在一行里出现多次？是 → 用 ?；整行到末尾 → 贪婪

## 实战正则（nginx 日志）
(?P<ip>\d{1,3}(?:\.\d{1,3}){3}) - - \[(?P<time>[^\]]+)\]
"(?P<method>[A-Z]+) (?P<path>\S+) HTTP/[\d.]+" (?P<status>\d{3}) (?P<size>\d+)

两个高频错：
- 该用 [^\]]+ 的地方用了 .+    会越界到最后的 ]
- 该用 \S+ 的地方用了 \w+      路径 /api/user 被切成 api，不报错

## 解析器的纪律
- 收集「解析失败的行」，别默默丢掉
- enumerate(lines, 1)，行号从 1 数
- 报错要带行号 + 前 30 字符
