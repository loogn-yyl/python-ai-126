1try / except：把「崩」变成「处理」

try:
    x = 10 / 0
except ZeroDivisionError:
    print("不能除以 0")
不能除以 0

没有 try 的话，这两行会让整个程序立刻终止，后面的代码一行都不执行。有了 try，错误被「接住」，程序继续往下走。

最实用的场景：把用户输入变成安全的值

def safe_int(s):
    try:
        return int(s)
    except ValueError:
        return None

print(safe_int("42"))
print(safe_int("abc"))
42
None
这个模式以后你会用几百次。用户输入、API 返回、CSV 里的一列数字——没有一处能保证格式正确。int() 遇到 "abc" 会抛 ValueError，接住它返回 None，调用方就能判断「这条数据坏了，跳过」。

这比 if s.isdigit(): 更可靠——isdigit() 判断不了 "-5"、"3.14"、" 42 " 这些情况，但 int() 能。

else 和 finally

try:
    n = int("10")
except ValueError:
    print("转换失败")
else:
    print("转换成功，结果", n)
finally:
    print("无论如何都会执行")
转换成功，结果 10
无论如何都会执行
块什么时候执行用在哪
try总是先试可能出错的代码
except出错时兜底处理
else没出错时把「成功后才做的事」和 try 分开
finally无论如何（哪怕 return 或崩了）关文件、关连接、清临时文件
else 有什么用：把「可能出错的代码」缩到最小。try 里只放 int("10")，后面用 n 的逻辑放 else 里——这样 except 就只可能捕获 int 转换的错误，不会把后续代码的 bug 也一起吞掉。

2纪律：捕获什么，不捕获什么

Python 里可以写一个「什么错都接」的 except，但那是危险写法。

# ❌ 别这么写
try:
    do_something()
except:
    pass
⚠️ 裸 except + pass 是「把错误扫进地毯下」。

它连 Ctrl+C 中断都能吞掉，程序卡死了你也看不出来。更糟的是：代码里打错一个字（NameError）、传错参数（TypeError）这类你自己的 bug，也会被它悄悄吃掉，然后程序带着错误数据继续跑——最后在完全不相干的地方出问题，查一天都查不出来。

规则：except 后面必须写具体的异常类型。

一个 try 捕获多种异常

# 写法一：元组
try:
    value = int("abc")
except (ValueError, TypeError) as e:
    print("转换失败:", type(e).__name__)

# 写法二：分开放，处理方式不同
try:
    value = int("abc")
except ValueError:
    print("格式不对")
except TypeError:
    print("类型不对")
转换失败: ValueError
格式不对
该捕获哪些？记住这条：except 后面写的，应该是你真的知道怎么处理的异常。
不知道怎么处理就别捕获——让它崩，让报错信息告诉你问题在哪。**崩掉比带着错误默默跑下去好得多。**

你以后最常遇到的几个异常

异常什么时候出现典型原因
ValueError类型对但值不对int("abc")、解包个数不匹配
TypeError类型不对"a" + 1、len(5)
KeyError字典 key 不存在d["不存在"]（用 get 避免）
IndexError下标越界[1,2][5]
FileNotFoundError文件不存在路径写错、文件没创建
ZeroDivisionError除以 01/0
AttributeError对象没这个属性/方法"abc".push()
⚠️ NameError 和 SyntaxError 不要去捕获。这两个一百次里一百次是你自己写错了（变量名打错、少个冒号）。捕获它们只会让你看不见自己犯的错。

看报错信息：最后一行才是病根

Traceback (most recent call last):
  File "main.py", line 8, in <module>
    result = compute(a, b)
  File "main.py", line 3, in compute
    return a / b
ZeroDivisionError: division by zero
读 traceback 的顺序：从下往上。
① 最后一行 ZeroDivisionError: division by zero —— 什么错
② 上面几行「File ..., line 3, in compute」—— 在哪错的（最靠近底部的是出错点，再往上是调用链）

绝大多数人的错误是：只看第一行「Traceback」就慌了。那是「调用栈开始」，不是错误信息。

3raise 与自定义异常：主动报错

def set_age(age):
    if age < 0:
        raise ValueError(f"年龄不能为负数：{age}")
    return age

try:
    set_age(-5)
except ValueError as e:
    print("被捕获:", e)
被捕获: 年龄不能为负数：-5
raise 就是 C 里的「返回错误码」，但强得多：它会中断当前函数，一路往上冒泡，直到有人 except 接住；没人接程序就崩，并打印完整调用栈。
C 里 return -1 之后必须每一层都检查并往上传递，漏一处就出错。Python 里 raise 一次，中间所有层自动跳过。

自定义异常：给错误分类

class ScoreError(Exception):
    pass

def check(score):
    if score > 100:
        raise ScoreError("分数不能超过 100")
    return score

try:
    check(150)
except ScoreError as e:
    print("自定义异常:", e)
自定义异常: 分数不能超过 100
class XxxError(Exception): pass 这两行就够了。不用写 __init__，不用写方法。它的价值不在功能，在于名字——调用方可以精确地 except ScoreError，而不会把别的错误也接住。

这就是「给错误分类」：文件相关用 FileError，数据校验用 ValidationError，业务规则用 ScoreError。后面的项目里，一个好的自定义异常体系能让排错快十倍。

4with 语句：文件一定要关

# 不推荐的写法
f = open("hello.txt", "w", encoding="utf-8")
f.write("第一行\n")
f.write("第二行\n")
f.close()          # 忘了这行，文件可能没写完
# 推荐：with
with open("hello.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n")
    f.write("第二行\n")

print("写入完成")
写入完成
with 做的事：无论代码块里正常结束、中途 return、还是抛异常，退出时都会自动 close()。
这就是第 1 节 finally 的升级版——写起来更短，而且不会忘。

以后见到 open() 就配 with，别用 f = open(); f.close() 这种写法。

encoding="utf-8" 为什么必须写

⚠️ 不写 encoding="utf-8"，你的中文在别人电脑上会变乱码。

原因是 open() 不指定编码时，会用操作系统的默认编码：
· macOS / Linux → 一般是 UTF-8 ✅
· Windows 中文版 → 是 GBK ❌

所以你的 Mac 上跑得好好的代码，拷到 Windows 就 UnicodeDecodeError。养成每次 open() 都写 encoding="utf-8" 的习惯，这是 D002 编码那一节的实战意义。

读写模式

模式含义文件不存在时
"r"只读（默认）报 FileNotFoundError
"w"写入，清空原内容自动创建
"a"追加到末尾自动创建
"x"新建，文件已存在则报错自动创建
⚠️ "w" 会清空整个文件。用 "w" 打开一个已有文件，内容立刻就没了——哪怕你后面一行都没写。想保留原内容只在末尾加东西，用 "a"。

三种读法

with open("hello.txt", "r", encoding="utf-8") as f:
    content = f.read()          # 一次性全读成一个大字符串
print(content)

with open("hello.txt", "r", encoding="utf-8") as f:
    for line in f:              # 逐行读（推荐，省内存）
        print(line.strip())
第一行
第二行

第一行
第二行
逐行读为什么加 .strip()：每行末尾带着换行符 \n，直接打印会多一个空行；而且和别的字符串比较时（比如判断 line == "第二行"）会因为那个 \n 永远不相等。读文件逐行处理时，第一件事永远是 strip()。

文件不存在怎么办

try:
    with open("nope.txt", "r", encoding="utf-8") as f:
        f.read()
except FileNotFoundError:
    print("文件不存在")

import os
print("路径存在吗:", os.path.exists("hello.txt"))
文件不存在
路径存在吗: True
两种写法各有用途：os.path.exists() 适合「先检查再决定要不要读」；try/except 适合「直接读，出问题再说」。后者更 Pythonic——因为两次操作之间文件可能被删掉（所谓的「先检查后执行」竞态），而 try/except 没有这个问题。

5CSV：表格数据的标准格式

CSV 就是「用逗号分隔的纯文本表格」。Excel 能直接打开，是所有数据工具之间通用的交换格式。

写 CSV

import csv

with open("scores.csv", "w", newline="", encoding="utf-8") as f:
    w = csv.writer(f)
    w.writerow(["姓名", "成绩"])      # 表头
    w.writerow(["张三", 88])
    w.writerow(["李四", 95])

print("csv 写入完成")
csv 写入完成
⚠️ newline="" 不能省。不加的话，Windows 上写出来的 CSV 每隔一行会出现一个空行——因为 csv 模块自己会加换行符，open 又会帮它转换一次，换行符被加了两遍。这是 csv 模块的强制要求，不是可选优化。

读 CSV

import csv

with open("scores.csv", "r", encoding="utf-8") as f:
    r = csv.reader(f)
    for row in r:
        print(row)
['姓名', '成绩']
['张三', '88']
['李四', '95']
⚠️ 看仔细：写进去的是数字 88，读出来的是字符串 '88'。

CSV 是纯文本格式，没有类型概念。读出来的每一格都是字符串，要算数必须自己转：int(row[1])。

而且转换可能失败（比如某个格子是空的、或者写着 "缺考"），所以要用第 1 节的 safe_int 思路处理。这就是今天练习要练的东西。

用 DictReader 按列名取值（更推荐）

import csv

with open("scores.csv", "r", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        print(row)
{'姓名': '张三', '成绩': '88'}
{'姓名': '李四', '成绩': '95'}
为什么推荐 DictReader：每一行变成一个字典，按列名取值 row["成绩"]，不用数下标。
实际价值：以后表格的列顺序变了、中间插了一列，用下标 row[1] 的代码全要改，用 row["成绩"] 的代码一行都不用动。这是 D003 学的字典在真实场景里的第一个大用处。

6JSON：给程序看的格式

CSV 适合表格，JSON 适合「有层次的配置和数据」。你以后调的每一个 AI 接口，请求和响应都是 JSON。

写 JSON 文件

import json

data = {"name": "张三", "scores": [88, 95]}

with open("stu.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)

文件里长这样：

{ "name": "张三", "scores": [ 88, 95 ] }

读 JSON 文件

import json

with open("stu.json", "r", encoding="utf-8") as f:
    back = json.load(f)

print(back)
print(type(back))
{'name': '张三', 'scores': [88, 95]}
<class 'dict'>
注意这里的关键：JSON 读回来会自动变回 Python 的字典和列表，而且数字还是数字（88 不是 '88'）。
这是 JSON 和 CSV 最大的区别——JSON 保留类型。所以存配置、存结构化数据一律用 JSON，只有「要给人用 Excel 打开」时才用 CSV。

四个函数，别记混

函数方向对象
json.dump(data, f)Python → JSON文件
json.load(f)JSON → Python文件
json.dumps(data)Python → JSON字符串（s = string）
json.loads(s)JSON → Python字符串
import json

s = json.dumps({"a": 1}, ensure_ascii=False)
print(s)
print(json.loads(s))
{"a": 1}
{'a': 1}
⚠️ 记忆法：带 s 的用于字符串（dumps / loads），不带的用于文件。
ensure_ascii=False 也要记住——不加的话，中文会被转成 "\u5f20\u4e09" 这样的转义序列。虽然读回来还是对的，但文件内容人看不懂。

类型对照：JSON 和 Python 的对应关系

JSONPython
对象 { }字典 dict

注意最后两行的差别：JSON 是小写 true / false / null，Python 是大写 True / False / None。以后手写 JSON 配置文件时写错了会解析失败，这是最常见的低级错误之一。

第 8 题：成绩统计脚本（今天的成品）

# p8_summary.py
import csv


def to_number(s):
    """能转数字就转，转不了返回 None"""
    try:
        return int(s)
    except ValueError:
        pass
    try:
        return float(s)
    except ValueError:
        return None


# 1. 造一份测试数据
with open("scores.csv", "w", newline="", encoding="utf-8") as f:
    w = csv.writer(f)
    w.writerow(["姓名", "语文", "数学", "英语"])
    w.writerow(["张三", 88, 95, 76])
    w.writerow(["李四", 92, 78, 85])
    w.writerow(["王五", 70, "缺考", 90])       # 故意留一条坏数据
    w.writerow(["赵六", 85, 88, 79])

# 2. 读进来，坏数据跳过
students = []
skipped = 0

with open("scores.csv", "r", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        name = row["姓名"]
        scores = []
        for subject in ["语文", "数学", "英语"]:
            n = to_number(row[subject])
            if n is None:
                scores = None
                break
            scores.append(n)

        if scores is None:
            skipped += 1
            print(f"跳过（数据不完整）: {name}")
            continue

        total = sum(scores)
        students.append({"姓名": name, "总分": total,
                         "平均分": round(total / len(scores), 1)})

# 3. 写汇总
with open("summary.csv", "w", newline="", encoding="utf-8") as f:
    w = csv.writer(f)
    w.writerow(["姓名", "总分", "平均分"])
    for s in students:
        w.writerow([s["姓名"], s["总分"], s["平均分"]])

# 4. 打印结果
print()
for s in students:
    print(f"{s['姓名']}  总分 {s['总分']}  平均 {s['平均分']}")

if students:
    class_avg = sum(s["平均分"] for s in students) / len(students)
    print(f"\n班级平均分: {class_avg:.1f}")
print(f"共处理 {len(students)} 人，跳过 {skipped} 人")

# D006 笔记

## 异常处理
- try / except / else / finally
- else = 没出错时执行；finally = 无论如何执行
- **不要裸 except + pass**，要写具体异常类型
- 不知道怎么办的异常，就让它崩 —— 崩掉比默默跑错好
- raise 主动抛错，会中断当前函数并向上冒泡
- 自定义异常：class MyError(Exception): pass 两行就够

## 常见异常
- ValueError 值不对（int("abc")）
- TypeError 类型不对
- KeyError 字典没这个 key
- IndexError 下标越界
- FileNotFoundError 文件不存在
- ZeroDivisionError 除以 0

## 读报错
- traceback 从下往上读：最后一行是「什么错」，往上是「在哪错的」

## 文件
- 一律 with open(...)，自动关文件
- **encoding="utf-8" 必须写**，否则跨平台乱码
- "w" 会清空文件！追加用 "a"
- 逐行读记得 strip()，去掉 \n
- csv 写文件要 newline=""

## CSV
- csv.reader 读出全是字符串，数字要自己转
- csv.DictReader 按列名取，更推荐
- 有坏数据要 skip + 计数，不要让整个流程崩

## JSON
- dump / load 对文件；dumps / loads 对字符串
- ensure_ascii=False 中文才不转义
- JSON 保留类型，CSV 不保留
- json 的 true/false/null → Python 的 True/False/None

## C 对比
- 错误码 return -1 vs raise 异常自动冒泡
- 必须 fclose() vs with 自动关闭
