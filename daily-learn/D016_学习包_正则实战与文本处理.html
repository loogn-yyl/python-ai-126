1多行匹配：re.M 改的是 ^$，re.S 改的是 .

这两个标志经常被混为一谈，其实它们改的是完全不同的东西。一个管「^ $ 认哪一行」，一个管「. 吃不吃换行」。

import re

text = """200 OK
404 Not Found
500 Error"""

print("不加标志:", re.findall(r"^\d+", text))
print("re.M    :", re.findall(r"^\d+", text, re.M))
print("re.M + $:", re.findall(r"^\d+$", text, re.M))
print()
block = """<div class="a">
  内容
</div>"""
print("不加标志:", re.findall(r'<div class="a">(.*)</div>', block))
print("re.S    :", re.findall(r'<div class="a">(.*)</div>', block, re.S))
print("re.S 非贪婪:", re.findall(r'<div class="a">(.*?)</div>', block, re.S))
不加标志: ['200']
re.M    : ['200', '404', '500']
re.M + $: []

不加标志: []
re.S    : ['\n  内容\n']
re.S 非贪婪: ['\n  内容\n']
标志它改动的东西不加时加了以后
re.M^ 和 $只认整段文本的开头和结尾认每一行的开头和结尾
re.S.. 不吃换行，遇到 \n 就停. 把换行也当普通字符吃掉

第三行那个空列表，是个容易看走眼的地方

re.M + $ 那行返回 []，看着像「re.M 不起作用」，其实是因为 ^\d+$ 要求整行只有数字，而 200 OK 后面还有 OK。re.M 只是让 $ 认行尾，不会让 $ 变松。

第二个例子更能说明 re.S 的必要性：不加标志时，(.*) 遇到第一个换行就停了，而后面还要求有 </div>，接不上，于是整体失败——返回空列表，一个报错都没有。

加了 re.S 之后，.* 的贪婪问题会放大。
上面那个例子里非贪婪和贪婪结果一样，因为只有一个 div。但换成一整页 HTML（有几十个 </div>），.* 会从第一个 div 一路吃到最后一个。用 re.S 的时候，几乎总要配非贪婪 .*?。
速记：re.M 的 M 是 Multi-line，管「行」；re.S 的 S 是 DOTALL，管「点」。
一个改锚点，一个改点号，互不相干。真要两个都改，写成 re.M | re.S。

3编码：UnicodeDecodeError 到底在说什么

这个报错每个人都遇到过，但很多人只是「换个编码再试试」。今天把它彻底讲清楚——字符和字节是两回事，编码就是两者之间的翻译表。

GBK 字节  : b'\xd6\xd0\xce\xc4\xb2\xe2\xca\xd4'

按 gbk 解回来: 中文测试
按 utf-8 硬解:

报错那句话拆开看：0xd6 这个字节，按 utf-8 的规则解释不通。utf-8 里一个中文字符占 3 个字节，而且第一个字节必须以 1110 开头；0xd6 是 11010110，它表示「后面还跟 1 个字节」，可后面那个 0xd0 又是另一个开头——这就是 invalid continuation byte 的字面意思。

编码一个汉字占什么时候会遇到
utf-83 字节默认全用它。Linux / macOS / 网页 / git 都是
gbk2 字节Windows 中文系统导出的 csv、老系统日志
utf-8-sig3 字节 + 开头 3 字节 BOMExcel 另存的 csv 几乎都带 BOM

BOM：看不见但会让你判断失败的三个字节

bom = b"\xef\xbb\xbfabc"
print("原始字节 :", bom)
print("utf-8 解 :", repr(bom.decode("utf-8")), "长度", len(bom.decode("utf-8")))
print("utf-8-sig:", repr(bom.decode("utf-8-sig")), "长度", len(bom.decode("utf-8-sig")))
print()
print("比较:", bom.decode("utf-8") == "abc", bom.decode("utf-8-sig") == "abc")
原始字节 : b'\xef\xbb\xbfabc'
utf-8 解 : '\ufeffabc' 长度 4
utf-8-sig: 'abc' 长度 3

比较: False True
这就是「删掉 BOM 三个字节，为什么用 utf-8 读不出来」的原因。
它不是「编码错了」，而是那三个字节被当成了一个真实字符 \ufeff，粘在你第一个字段的最前面。表现出来是：
  • rows[0]["ip"] 打印出来看着是 "127.0.0.1"，但 == "127.0.0.1" 是 False
  • csv 的第一列名变成了 "\ufeffip"，row["ip"] 直接 KeyError
  • 用 Excel 打开完全正常，所以你根本想不到是它

解法只有一句：读可能来自 Excel 的 csv，一律用 encoding="utf-8-sig"。它对没有 BOM 的文件同样有效，是个安全的默认值。

errors 参数三档

取值遇到解不了的字节该不该用
"strict"（默认）抛 UnicodeDecodeError数据要准就必须用这个，报错比静默丢数据好
"replace"换成 \ufffd（上方那个方框）只做粗看、能做下去就行
"ignore"直接删掉危险。4 个字符读成了 1 个，你还不知道

看上面那行 ignore 后长度: 1——原本 4 个汉字，静默变成了 1 个字符。它不报错、不警告，你的程序照样跑完，只是数据是错的。

处理编码问题的正确顺序：
① 先确定文件原本是什么编码（file -I 文件名 或看它从哪来）
② 用对编码去读，不要用 errors="ignore" 硬扛
③ 读进来之后统一转成 str（Python 内部就是 Unicode），出去时再 encode
中间这段全是 str，只有进出文件和网络的时候才是 bytes。记住这条界线，编码问题会少一大半。

from collections import Counter

LOG = """127.0.0.1 - - [13/Nov/2026:02:15:33 +0800] "GET /index.html HTTP/1.1" 200 512
10.0.0.5 - - [13/Nov/2026:02:15:35 +0800] "POST /api/login HTTP/1.1" 200 128

127.0.0.1 - - [13/Nov/2026:03:18:44 +0800] "GET /missing HTTP/1.1" 404 32"""

PATTERN = re.compile(
    r'(?P<ip>\d{1,3}(?:\.\d{1,3}){3}) - - '
    r'\[(?P<time>[^\]]+)\] '
    r'"(?P<method>[A-Z]+) (?P<path>\S+) HTTP/[\d.]+" '

)

rows = [m.groupdict() for m in PATTERN.finditer(LOG)]
print("解析:", len(rows), "行")
print()
print("Top IP:")
for ip, n in Counter(r["ip"] for r in rows).most_common(3):
    print(f"  {ip:<15} {n}")
print()
print("Top URL:")
for p, n in Counter(r["path"] for r in rows).most_common(3):
    print(f"  {p:<18} {n}")
print()
print("状态码:")
for s, n in sorted(Counter(r["status"] for r in rows).items()):
    print(f"  {s}  {n}")

Counter 是这一步的关键工具。Counter(可迭代对象) 直接给你「每个值出现几次」，most_common(n) 按次数从多到少给你前 n 个。

现在加上汇总信息——总请求数、总流量、错误率、按小时分布：

import re
from collections import Counter

LOG = """127.0.0.1 - - [13/Nov/2026:02:15:33 +0800] "GET /index.html HTTP/1.1" 200 512
10.0.0.5 - - [13/Nov/2026:02:15:35 +0800] "POST /api/login HTTP/1.1" 200 128
10.0.0.5 - - [13/Nov/2026:02:15:36 +0800] "GET /api/user HTTP/1.1" 401 64
192.168.1.9 - - [13/Nov/2026:02:16:01 +0800] "GET /static/app.js HTTP/1.1" 304 0
127.0.0.1 - - [13/Nov/2026:02:16:10 +0800] "GET /index.html HTTP/1.1" 200 980
10.0.0.5 - - [13/Nov/2026:03:01:02 +0800] "GET /api/order HTTP/1.1" 500 32
127.0.0.1 - - [13/Nov/2026:03:18:44 +0800] "GET /missing HTTP/1.1" 404 32"""

PATTERN = re.compile(
    r'(?P<ip>\d{1,3}(?:\.\d{1,3}){3}) - - '
    r'\[(?P<time>[^\]]+)\] '
    r'"(?P<method>[A-Z]+) (?P<path>\S+) HTTP/[\d.]+" '
    r'(?P<status>\d{3}) (?P<size>\d+)'
)
HOUR = re.compile(r":(\d{2}):\d{2}:\d{2}")

rows = [m.groupdict() for m in PATTERN.finditer(LOG)]
total = len(rows)
bytes_total = sum(int(r["size"]) for r in rows)
errors = [r for r in rows if r["status"].startswith(("4", "5"))]

print("=" * 42)
print(f"总请求 {total} 条 · 流量 {bytes_total} 字节")
print(f"错误请求 {len(errors)} 条 · 错误率 {len(errors) / total:.1%}")
print("=" * 42)
print()
print("按小时")
for h in sorted({HOUR.search(r["time"]).group(1) for r in rows}):
    n = sum(1 for r in rows if HOUR.search(r["time"]).group(1) == h)
    print(f"  {h} 点  {'#' * n} {n}")

  02 点  ##### 5
  03 点  ## 2

三个写法值得单独说：

写法为什么这么做
r["status"].startswith(("4", "5"))用元组，不是 or。写成 startswith("4") or startswith("5") 也对，但字符串会被调两次；写成 startswith("4" or "5") 则只判 "4"，因为 "4" or "5" 求值结果是 "4"
{HOUR.search(...).group(1) for r in rows}集合推导先拿到「有哪些小时」，省得对每一行都试一次。顺序不定，所以外面套 sorted()
{len(errors) / total:.1%}:.1% 自动乘 100 并加百分号，比手写 f"{x*100:.1f}%" 少一处出错
注意 total = len(rows) 这个位置。
如果日志一行都没解析出来，total 就是 0，len(errors) / total 会抛 ZeroDivisionError。真实日志里这一定会发生（比如文件是空的，或者格式完全不对）。
防御写法：rate = len(errors) / total if total else 0。

import csv
import io
from collections import Counter

rows = [
    {"ip": "127.0.0.1", "path": "/index.html", "status": "200", "size": "512"},
    {"ip": "10.0.0.5", "path": "/api/login", "status": "200", "size": "128"},
    {"ip": "10.0.0.5", "path": "/api/user", "status": "401", "size": "64"},
]

buf = io.StringIO()
w = csv.DictWriter(buf, fieldnames=["ip", "count"])
w.writeheader()
for ip, n in sorted(Counter(r["ip"] for r in rows).items()):
    w.writerow({"ip": ip, "count": n})
print("\n".join(buf.getvalue().splitlines()))
ip,count
10.0.0.5,2
127.0.0.1,1
为什么这里要用 splitlines() 转一道？
因为 csv 写出来的行尾是 \r\n，print 出来时那个 \r 会让光标回到行首，看着像是每行之间多了个空行。
splitlines() 专门处理这件事——它认 \n、\r\n、\r 三种换行，比 split("\n") 稳。这也是第 5 节末尾那个 newline="" 讨论的同一个根因：csv 模块自己管换行符。
为什么这里用 io.StringIO() 而不是真写文件？
一是演示时不污染目录，二是测试时更好用——csv.DictWriter 接收任何「有 write 方法的对象」，字符串缓冲区也算。你以后写测试，就可以断言输出的 csv 内容，而不用去读磁盘文件。
真写文件时，那个 newline="" 不是可选项。
open(path, "w", newline="", encoding="utf-8")——不加它，Windows 上 csv 每行之间会多出一个空行。原因是 csv 模块自己写 \r\n，而文本模式的 open 又会把 \n 再转一次。这个坑只在 Windows 上出现，所以 Mac 上写好的代码拿到 Windows 运行才发现。

最大的3个: [('/index.html', '980'), ('/index.html', '512'), ('/api/login', '128')]
4xx=1 5xx=0

第 1 题最容易写错的地方：Counter(r["size"] for r in rows) 统计的是「每个 size 值出现几次」，不是「每个 IP 的总字节」。Counter 只会数个数，求和必须自己 +=。或者用 defaultdict(int)。

第 1 题的排序：key=lambda kv: -kv[1] 里的负号是「降序」的意思——sorted 默认升序，取负就反过来了。也可以用 reverse=True，两者等价，但取负能同时表达「按第 2 个元素排、倒序」。

第 5 题 · 写成 csv

import csv
import io
from collections import Counter

rows = [
    {"ip": "127.0.0.1"}, {"ip": "10.0.0.5"},
    {"ip": "10.0.0.5"}, {"ip": "192.168.1.9"},
]

buf = io.StringIO()
w = csv.DictWriter(buf, fieldnames=["ip", "count"])

for ip, n in sorted(Counter(r["ip"] for r in rows).items()):

第 7 题 · GBK 转 UTF-8

gbk_bytes = "用户名,数量".encode("gbk")
utf8_bytes = gbk_bytes.decode("gbk").encode("utf-8")

print("GBK  :", gbk_bytes, len(gbk_bytes), "字节")
print("UTF-8:", utf8_bytes, len(utf8_bytes), "字节")
print("解回来:", utf8_bytes.decode("utf-8"))
print("一致:", utf8_bytes.decode("utf-8") == "用户名,数量")
GBK  : b'\xd3\xc3\xbb\xa7\xc3\xfb,\xca\xfd\xc1\xbf' 11 字节
UTF-8: b'\xe7\x94\xa8\xe6\x88\xb7\xe5\x90\x8d,\xe6\x95\xb0\xe9\x87\x8f' 16 字节
解回来: 用户名,数量
一致: True

关键在 decode 再 encode 这个顺序。不能直接 gbk_bytes.encode("utf-8")——bytes 没有 encode，只有 decode。bytes → str 叫解码，str → bytes 叫编码，方向搞反是新手最常见的错。

第 8 题 · report() 函数

import json
from collections import Counter

rows = [
    {"ip": "127.0.0.1", "status": "200", "size": "512"},
    {"ip": "10.0.0.5", "status": "200", "size": "128"},
    {"ip": "10.0.0.5", "status": "401", "size": "64"},
    {"ip": "192.168.1.9", "status": "304", "size": "0"},
]


def report(rows):
    total = len(rows)
    errors = sum(1 for r in rows if r["status"][0] in "45")
    return {
        "total": total,
        "bytes": sum(int(r["size"]) for r in rows),
        "error_rate": round(errors / total, 3) if total else 0,
        "top_ip": Counter(r["ip"] for r in rows).most_common(3),
    }


r = report(rows)
print(json.dumps(r, ensure_ascii=False, indent=2))
print()
print("空列表也能跑:", report([]))
{
  "total": 4,
  "bytes": 704,
  "error_rate": 0.25,
  "top_ip": [
    [
      "10.0.0.5",
      2
    ],
    [
      "127.0.0.1",
      1
    ],
    [
      "192.168.1.9",
      1
    ]
  ]
}

空列表也能跑: {'total': 0, 'bytes': 0, 'error_rate': 0, 'top_ip': []}

三个细节：
① most_common() 返回的是元组列表，json.dumps 会自动把它转成 JSON 数组里的数组——所以 indent=2 之后每个元组被拉成了多行。觉得丑就包一层 [{"ip": k, "n": v} for k, v in ...]，结构更清楚。
② error_rate 用了 round(..., 3)，因为 1/4 是 0.25 没问题，但 1/3 会变成 0.3333333333333333，写进报告不好看。
③ if total else 0 就是第 4 节那个 ZeroDivisionError 的防御。

# D016 笔记 · 正则实战与文本处理

## re.M 与 re.S 管的是两件不同的事
re.M : 让 ^ $ 认「每一行」的开头结尾（不加只认整段文本）
re.S : 让 . 能吃换行（DOTALL）
两个都要 → re.M | re.S
用 re.S 时几乎总要配非贪婪 .*?，否则跨过所有成对标签

## csv / json
csv.DictReader → 字典列表，★值全是字符串，算数前必须 int()
csv.DictWriter → 必须 writeheader()，否则第一行数据当表头
真写文件：open(path, "w", newline="", encoding="utf-8")   ★newline="" 只在 Windows 有影响
json.dumps(obj, ensure_ascii=False)  ★不加中文变 \u4e2d\u6587
dump/load 收文件对象，dumps/loads 收字符串（s = string）
json 会还原数字/布尔类型，csv 不会

## 编码
- 字符 ≠ 字节。bytes → str 叫 decode，str → bytes 叫 encode
- 程序内部一律 str，只有进出文件和网络才是 bytes
- UnicodeDecodeError = 这个字节按该编码的规则解释不通
- 常见：utf-8（3 字节/汉字）/ gbk（2 字节）/ utf-8-sig（带 BOM）
- BOM：Excel 另存的 csv 几乎都带，读出来第一个字段前面粘了 \ufeff
  → 表现：看着一样，== 是 False，row["ip"] 却 KeyError
  → 解法：读 csv 一律 encoding="utf-8-sig"（对无 BOM 也安全）
- errors 三档：strict（默认，推荐）/ replace（替换成 \ufffd）/ ignore（★静默删掉，危险）
  实测：4 个汉字用 ignore 只剩 1 个字符，不报错

## 统计
- Counter(可迭代) 计数；most_common(n) 取前 n，次数相同按首次出现顺序
- Counter 只会计数，求和要自己 += 或用 defaultdict(int)
- 降序：sorted(items, key=lambda kv: -kv[1]) 或 reverse=True
- 字符串格式化：{x:.1%} 自动 ×100 加百分号
- startswith(("4", "5")) 用元组；startswith("4" or "5") 只判 "4"

## 健壮性
- 除零：rate = errors / total if total else 0
- 空输入必须能跑通，别假设总有数据
- 测试 csv 输出用 io.StringIO()，不用真写文件
