1socket：你 C 里那五个函数，Python 一个没少

先看对照表。你会发现除了写法变了，调用顺序一模一样。

CPython作用
socket(AF_INET, SOCK_STREAM, 0)socket.socket(socket.AF_INET, socket.SOCK_STREAM)创建一个 IPv4 的 TCP 套接字
connect(fd, &addr, len)s.connect((host, port))发起三次握手
send(fd, buf, n, 0)s.sendall(b"...")发数据
recv(fd, buf, n, 0)s.recv(4096)收数据
close(fd)s.close()关闭（或 with 自动关）

三处真正的差别，都在「谁帮你管内存」上：

  • 不用传长度。C 里 connect 要传 sizeof(struct sockaddr_in)，Python 传个元组就行。
  • 不用管缓冲区大小。C 里你得自己 malloc 一块 char buf[4096]；Python 的 recv(4096) 直接返回 bytes 对象，长度就是实际收到的字节数。
  • 不用手动 htons。字节序转换 Python 内部做了，你写端口号就写 80。
import socket

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.settimeout(5)

print("family:", s.family, "-> AF_INET =", socket.AF_INET)
print("type  :", s.type, "-> SOCK_STREAM =", socket.SOCK_STREAM)

s.close()
print("已关闭")
family: 2 -> AF_INET = 2
type  : 1 -> SOCK_STREAM = 1
已关闭

AF_INET 就是数字 2，SOCK_STREAM 就是数字 1。这些常量在 C 里也是 #define 出来的整数，Python 只是把它们做成了模块属性。所以你看到 print(s.family) 输出 2 不用奇怪。

settimeout(5) 这行别省。
不加的话，connect 和 recv 会永久阻塞——对方不响应，你的程序就一直卡在那儿，Ctrl+C 都不一定管用。网络编程里「超时」不是可选项，是必需品。C 里对应 setsockopt(SO_RCVTIMEO)，麻烦得多。

2HTTP 报文：说到底就是一个字符串

很多人觉得 HTTP 很神秘，其实它就是「几行文本 + 一个空行 + 正文」。你自己拼一个出来看看：

host = "example.com"

request = (
    f"GET / HTTP/1.1\r\n"
    f"Host: {host}\r\n"
    f"Connection: close\r\n"
    f"\r\n"
)

print("报文长度:", len(request), "字节")
print("逐行拆开（repr 让 \\r\\n 显形）:")

    print("   ", repr(line))
报文长度: 56 字节
逐行拆开（repr 让 \r\n 显形）:
    'GET / HTTP/1.1'
    'Host: example.com'
    'Connection: close'
    ''
    ''

五段内容，每一段都有存在的理由：

内容含义漏了会怎样
GET / HTTP/1.1请求行：方法 + 路径 + 版本服务器直接断开
Host: example.comHTTP/1.1 必填，指明要哪个网站返回 400 Bad Request——一个 IP 上可能挂了几十个网站，服务器靠它分流
Connection: close收完就断，别保持长连接不算错，但你的 recv 会一直等对方关连接
（空行）头部结束的标志服务器会一直等更多头部，然后超时
那个空行是 \r\n\r\n——两个换行，不是一行。
最后一行 Connection: close\r\n 结束了这个头部字段，再来一个 \r\n 才是「头部结束」。你上面看到输出里有两个空字符串 ''，就是这个原因：split("\r\n") 在末尾切出了两个空段。
漏掉这个空行是最经典的错误：程序不报错，只是服务器一直不回你，直到超时。

响应也是同样的结构

partition("\r\n\r\n") 这一句是全部的关键。它把原始文本切成「头部 / 分隔符 / 正文」三段，比 split 好用——正文里也可能出现 \r\n\r\n，而 partition 只切第一个。

状态码第一位是类别：2xx 成功 / 3xx 重定向 / 4xx 你错了 / 5xx 服务器错了。4 和 5 的区别很重要——看到 404 别去查服务器日志，看到 500 别去改自己的参数。

3亲手发一次，你就知道 requests 替你做了什么

这段要联网，你按自己情况跑。跑不通也没关系，看懂它在做什么就行。

import socket

host, port = "example.com", 80
req = f"GET / HTTP/1.1\r\nHost: {host}\r\nConnection: close\r\n\r\n"

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    s.settimeout(10)
    s.connect((host, port))
    s.sendall(req.encode("ascii"))

    chunks = []
    while True:
        buf = s.recv(4096)
        if not buf:
            break
        chunks.append(buf)

raw = b"".join(chunks)
text = raw.decode("utf-8", errors="replace")
print("收到", len(raw), "字节")
print("首行:", text.split("\r\n")[0])
收到 1256 字节
首行: HTTP/1.1 200 OK

这段代码里有六个地方会出错，每一个都是真实项目里踩过的：

写法不加会怎样
s.settimeout(10)对方不响应时永久阻塞
req.encode("ascii")sendall 只收 bytes，传 str 报 TypeError
with ... as s异常时 socket 句柄泄漏（和 C 里忘记 close(fd) 一个道理）
while True + if not buf: break只 recv 一次会拿到半截数据——TCP 是字节流，不保证一次收完
b"".join(chunks)大文件下把 bytes 反复 + 是 O(n²)
errors="replace"服务器返回 gbk 编码的页面时直接 UnicodeDecodeError
那个 while True 循环是最容易被低估的一条。
很多人以为 recv(4096) 会把整个响应一次收完。不会。TCP 只保证「字节按顺序到达」，不保证「一次到齐」。一个 100KB 的页面，你可能要 recv 二三十次。
这也是为什么实际项目没人手写这一层——这些边界情况 requests 全替你处理了。

import requests

r = requests.get("https://example.com", timeout=10)

print("状态码:", r.status_code)

刚才那六个坑，它全处理了：超时、编码、连接复用、分块接收、自动解压、Host 头自动填。这就是「库」的价值——不是帮你省几行，是帮你避开你不知道自己不知道的坑。

属性 / 方法给你什么注意
r.status_code整数状态码4xx/5xx 不会抛异常，要自己判
r.text按 r.encoding 解码后的字符串r.encoding 可能是猜的，猜错就乱码
r.content原始 bytes下图片、下文件必须用它，不能用 text
r.json()把正文当 JSON 解析成字典正文不是 JSON 时抛 JSONDecodeError
r.headers响应头，大小写不敏感拿 r.headers["content-type"] 也能取到
r.url最终地址发生重定向后它和请求的不一样

中文乱码：r.encoding 猜错了

requests 判断编码的依据是响应头里的 Content-Type: ...charset=xxx。如果服务器没写这一项，它会退而求其次猜一个 ISO-8859-1，于是中文全变问号。

# 遇到乱码，第一件事是盯住这两行
#   print(r.encoding)          -> 如果是 ISO-8859-1 或 None，基本就是它
#   r.encoding = "utf-8"       -> 手动改，然后再读 r.text
#
# 更稳的做法：从正文里找声明
#   requests 有个内置推断，但它只在 headers 没写 charset 时才用
#   手动指定最可靠：r.encoding = r.apparent_encoding

# 顺序记牢：
#   1. r.encoding       —— headers 里写的，可能是错的
#   2. r.apparent_encoding —— 从正文猜的，比较慢但通常更准
#   3. 都不对 —— 那就自己试 gbk / utf-8-sig
print("改 r.encoding 之后必须重新读 r.text，值不会自动刷新")
为什么强调「先赋值、再读 r.text」？
不是不生效，而是 r.text 每次读的时候才用当时 r.encoding 的值去解码——所以顺序必须是「先赋值，再读 r.text」。
如果你先读了 r.text（此时已经用错的编码解过一次），再改 r.encoding，下次读 r.text 会重新解码，是对的。但如果你把 r.text 存进了变量，那个变量不会变。

5六个必须设的东西：不设一定会出问题

参数怎么写不设的后果
timeouttimeout=10 或 timeout=(3, 10)永久挂起。默认值是没有超时——这是 requests 最坑的设计
headers{"User-Agent": "Mozilla/5.0 ..."}很多站点直接 403，因为默认 UA 是 python-requests/2.x，一眼就被认出来
raise_for_status()r.raise_for_status()404 / 500 页面被当成正常内容去解析，报一堆莫名其妙的错
paramsparams={"q": "python"}自己拼 URL 时忘了转义，中文和空格直接炸
verify默认 True，别改成 False改了就没法防中间人
Sessions = requests.Session()每次请求重新握手 + 重新登录（登录态丢了）

timeout 那个元组是两个超时

timeout=(3, 10) 意思是：连接最多等 3 秒，连上之后每次读最多等 10 秒。写一个数字则两处都用它。

为什么「服务器慢」和「服务器没响应」要分开？
连接超时短一点（3 秒），可以快速跳过已经挂掉的站点；读取超时长一点（10 秒），因为有些接口确实要算很久。写成一个数，只能取折中值，两头都不合适。

异常要分四类抓

import requests
from requests.exceptions import (
    ConnectionError, HTTPError, Timeout, TooManyRedirects,
)


def fetch(url):
    try:
        r = requests.get(url, timeout=(3, 10))
        r.raise_for_status()
        return r.text
    except Timeout:
        print(f"超时     : {url}")
    except HTTPError as e:
        print(f"状态码错 : {e.response.status_code}")
    except ConnectionError:
        print(f"连不上   : {url}")
    except TooManyRedirects:
        print(f"跳转太多 : {url}")
    return None


print("四种异常各对应一类失败，抓的时候要分开")
print("顺序也有讲究：Timeout 和 ConnectionError 都是 ConnectionError 的子类关系要理清")
为什么不能只写 except Exception？
因为「超时」和「状态码 500」的处理方式完全不同：超时可以重试，500 重试也没用（服务器本身有问题）。只抓一个 Exception，你就分不出该不该重试。
异常分类的价值不在「接住」，而在「分开处理」。

6实战：抓一个网页的标题

今天要交付的就是这个。核心只有一行正则，难点全在外围。

import re

html = """<html><head><title>Python 官方教程</title></head>
<body><h1>欢迎</h1></body></html>"""

m = re.search(r"<title>(.*?)</title>", html, re.S | re.I)
print("标题:", m.group(1).strip() if m else None)

dirty = "<title>\n   多个空格   的标题\n</title>"
m2 = re.search(r"<title>(.*?)</title>", dirty, re.S | re.I)
print("原始:", repr(m2.group(1)))
print("清理:", " ".join(m2.group(1).split()))
标题: Python 官方教程
原始: '\n   多个空格   的标题\n'
清理: 多个空格 的标题

三个细节：

  • re.S | re.I：S 让 . 吃换行（标题可能跨行），I 让 title 不区分大小写（有的是 <TITLE>）。
  • .*? 非贪婪：一个页面里可能有多个 <title>，贪婪会一路吃到最后一个。
  • " ".join(s.split())：这是「把所有连续空白压成一个空格」的标准写法。strip() 只去两头，中间的换行和多余空格去不掉。
为什么不用 BeautifulSoup？因为今天的重点是「网络」不是「解析」。抓标题这种单一字段用正则足够，等你需要按 DOM 结构提取（比如「第二个表格的第三行」），再用解析库。先别为一行需求引入一个框架。

把它变成完整脚本

# fetch_title.py —— 今天的产出
import re
import sys

import requests
from requests.exceptions import HTTPError, RequestException, Timeout

TITLE = re.compile(r"<title[^>]*>(.*?)</title>", re.S | re.I)
UA = {"User-Agent": "Mozilla/5.0 (compatible; learn-bot/1.0)"}


def fetch_title(url, timeout=(3, 10)):
    """返回标题字符串；失败返回 None（不抛异常，让调用方决定怎么办）"""
    try:
        r = requests.get(url, headers=UA, timeout=timeout)
        r.raise_for_status()
    except Timeout:
        print(f"[超时] {url}", file=sys.stderr)
        return None
    except HTTPError as e:
        print(f"[HTTP {e.response.status_code}] {url}", file=sys.stderr)
        return None
    except RequestException as e:
        print(f"[失败] {url} -> {type(e).__name__}", file=sys.stderr)
        return None

    if not r.encoding or r.encoding.lower() == "iso-8859-1":
        r.encoding = r.apparent_encoding
    m = TITLE.search(r.text)
    return " ".join(m.group(1).split()) if m else None


if __name__ == "__main__":
    for u in sys.argv[1:]:
        t = fetch_title(u)
        print(f"{u}\n    -> {t}")

三段结构值得注意：

片段为什么这么写
except RequestException它是 requests 所有异常的基类。前面三个具体异常抓完了，剩下的用基类兜底，保证函数永远不抛异常
return None失败返回 None 而不是抛异常——批量抓取时，一个站点失败不该中断整批
r.encoding = r.apparent_encoding只在「没写 charset」或「猜成 ISO-8859-1」时才改，能少一次全文扫描
不要在循环里 except 之后 continue 什么也不记。
批量抓 100 个链接，失败了 5 个，你要能说出来是哪 5 个。把失败列表收集起来，和分析日志时收集「解析失败行」是同一条纪律。

第 2 题 · 拼请求报文

def build_request(method, path, host, headers=None):
    lines = [f"{method} {path} HTTP/1.1", f"Host: {host}"]
    for k, v in (headers or {}).items():
        lines.append(f"{k}: {v}")
    lines.append("")
    lines.append("")
    return "\r\n".join(lines)


req = build_request("GET", "/index.html", "example.com",
                    {"User-Agent": "test/1.0", "Accept": "*/*"})
print(repr(req))
print()
print("以空行结尾:", req.endswith("\r\n\r\n"))
'GET /index.html HTTP/1.1\r\nHost: example.com\r\nUser-Agent: test/1.0\r\nAccept: */*\r\n\r\n'

以空行结尾: True

为什么 lines 里要 append 两次空字符串？
最后一行头部后面需要一个 \r\n，空行再需要一个 \r\n。"\r\n".join([..., "", ""]) 正好产生 ...\r\n\r\n。只 append 一个的话，结尾是 \r\n，服务器会一直等头部。
更直观的写法是 "\r\n".join(lines) + "\r\n\r\n"，但那样要多拼一次。

第 3 题 · 拆响应报文

def parse_response(raw):
    head, _, body = raw.partition("\r\n\r\n")
    lines = head.split("\r\n")
    status = int(lines[0].split()[1])
    headers = {}
    for line in lines[1:]:
        k, _, v = line.partition(": ")
        headers[k.lower()] = v
    return status, headers, body


raw = ("HTTP/1.1 404 Not Found\r\n"
       "Content-Type: text/plain\r\n"
       "\r\n"
       "not here")
status, headers, body = parse_response(raw)
print("状态码:", status)
print("头部  :", headers)
print("正文  :", body)
状态码: 404
头部  : {'content-type': 'text/plain'}
正文  : not here

头部键统一转小写是个好习惯——HTTP 规范说头部名不区分大小写，但不同服务器发出来的大小写不一样（Content-Type / content-type 都见过）。统一 .lower() 之后，取值就不用猜了。

第 4 题 · 重试

def fetch_with_retry(url, retries=3):
    for attempt in range(1, retries + 1):
        ok = attempt == 3 and "bad" not in url   # 假装前两次失败，bad 的永远失败
        if ok:
            print(f"第 {attempt} 次成功: {url}")
            return "内容"
        if attempt < retries:
            print(f"第 {attempt} 次失败，等 {2 ** (attempt - 1)} 秒后重试")
        else:
            print(f"第 {attempt} 次失败，已是最后一次")
    print("放弃")
    return None


print(fetch_with_retry("https://example.com"))
print()

import csv

第 7 题 · 串行版（明天要对比的基准）

import time


def fetch(url):
    time.sleep(0.1)          # 模拟一次网络往返
    return f"{url} 的内容"


def fetch_all(urls):
    return [fetch(u) for u in urls]


urls = [f"https://site{i}.com" for i in range(1, 6)]

start = time.perf_counter()
results = fetch_all(urls)
elapsed = time.perf_counter() - start

print("抓到", len(results), "个页面")
print(f"总耗时 {elapsed:.2f} 秒")
print(f"平均每个 {elapsed / len(urls) * 1000:.0f} ms")

总耗时 0.50 秒
平均每个 100 ms

第 8 题 · 分类统计

import time
from collections import Counter


def fetch(url):
    time.sleep(0.1)
    if "timeout" in url:
        return "timeout"
    if "bad" in url:
        return "error"
    return "ok"


def fetch_all(urls):
    stats = Counter()
    for u in urls:
        stats[fetch(u)] += 1
    return stats


urls = [
    "https://a.com", "https://timeout1.com", "https://b.com",
    "https://bad1.com", "https://timeout2.com",
]
s = fetch_all(urls)
print("成功:", s["ok"], "超时:", s["timeout"], "其他:", s["error"])
print("总数对得上:", sum(s.values()) == len(urls))
成功: 2 超时: 2 其他: 1
总数对得上: True

最后那行 sum(s.values()) == len(urls) 是个便宜的自检。批量任务里最怕的不是失败，是「丢了几条你还不知道」。加一句总数校验，问题当场暴露。

# D017 笔记 · 网络编程

## socket：和 C 一模一样的五个函数
socket(AF_INET, SOCK_STREAM) → connect((host, port)) → sendall/recv → close
不用传长度、不用 malloc 缓冲、不用 htons
settimeout 必设（C 里是 setsockopt(SO_RCVTIMEO)）

## HTTP 报文
请求 = 请求行 + 头 + 空行 + 正文
  GET / HTTP/1.1
  Host: example.com        ★HTTP/1.1 必填，否则 400
  Connection: close
  (空行)                   ★是 \r\n\r\n 两个换行，漏了服务器一直等
响应 = 状态行 + 头 + 空行 + 正文
  HTTP/1.1 200 OK
  Content-Type: ...; charset=utf-8
  (空行)
partition("\r\n\r\n") 切头部和正文（比 split 好：只切第一个）

## 手写 socket 的六个坑（requests 全替你处理）
1 不设 timeout          → 永久阻塞
2 sendall 传 str        → TypeError，必须 encode
3 不用 with             → 句柄泄漏
4 recv 只调一次         → 拿到半截（TCP 是字节流）
5 bytes 反复 +          → O(n²)
6 硬 decode utf-8       → 服务器发 gbk 就崩

## requests
r.status_code / r.text / r.content / r.json() / r.headers / r.url
★4xx 5xx 不抛异常，要 raise_for_status()
★r.encoding 可能猜成 ISO-8859-1 → 手动改 r.encoding = r.apparent_encoding
  （改了之后重新读 r.text 才生效；已存进变量的不会变）

## 六个必设
timeout=(3, 10)   连接 3s / 读取 10s，默认无超时是最大的坑
headers           User-Agent 不设，很多站点 403
raise_for_status  否则 404 页面被当正常内容解析
params            自动转义
verify=True       别关
Session()         复用连接 + 保持登录态

## 异常四类
Timeout / HTTPError / ConnectionError / TooManyRedirects
最后用 RequestException 兜底 → 函数永远不抛异常
超时可重试，500 重试没用 → 必须分类

## 抓标题
r"<title[^>]*>(.*?)</title>" + re.S | re.I
" ".join(s.split()) 压掉所有连续空白（strip 只去两头）
urlparse / parse_qs；parse_qs 的值永远是列表

## 纪律
- 批量任务收集失败列表，别 continue 了事
- 加总数自检：sum(统计) == 输入条数
- 计时结论只记量级，别记具体数字
