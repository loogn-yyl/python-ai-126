for 循环展开来就是四步：

it = iter(nums)          # ① 拿到迭代器
while True:
    try:
        x = next(it)     # ② 一个个取
    except StopIteration:  # ③ 取完了
        break
    print(x)             # ④ 你的循环体
关键是 ③：迭代器用「抛异常」来表示结束。这不是设计失误，是有意的——返回值里没有「空」这个概念的容器（比如数字序列），用异常告诉调用方「没有了」最干净。C 里你大概会返回 NULL 或 -1 当哨兵值，那就要额外约定「-1 不算数据」，万一真有一项是 -1 就出事了。

2手写一个迭代器

自己写一遍，比看十遍概念有用。目标：从 3 数到 1。

class CountDown:
    def __init__(self, start):
        self.n = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.n <= 0:
            raise StopIteration
        self.n -= 1
        return self.n + 1


for i in CountDown(3):
    print(i)

cd = CountDown(2)
print(list(cd))
print("第二次 list 同一个对象:", list(cd))
3
2
1
[2, 1]
第二次 list 同一个对象: []

两个方法各管一件事：

方法作用
__iter__(self)返回迭代器本身。for 进来第一件事就是调它
__next__(self)返回下一个值；没有下一个了就 raise StopIteration
return self因为这个对象自己就是迭代器。写成 return iter(self.items) 就是另一种模式
手写版有个同样的一次性坑：同一个 CountDown(2) 对象第二次 list() 得到 []，因为 self.n 已经被减到 0 了。
这就是为什么大多数人不手写迭代器——见下一节。

3yield：三行写完一个迭代器

同样的功能，用 yield 重写：

def countdown(start):
    n = start
    while n > 0:
        yield n
        n -= 1


for i in countdown(3):
    print(i)

cd = countdown(2)
print(list(cd))
print("第二次同一对象:", list(cd))
print("新建一个:", list(countdown(2)))
3
2
1
[2, 1]
第二次同一对象: []
新建一个: [2, 1]

10 行变 5 行，而且不用自己管 StopIteration、不用管 return self。函数里出现 yield，这个函数就变成了「生成器函数」：调用它不执行函数体，而是返回一个生成器对象；每次 next() 才继续往下跑。

普通函数生成器函数
return 返回一个值，然后结束yield 交出一个值，然后暂停，下次从暂停处继续
调用就执行到底调用只创建对象，执行时机由 next()/for 决定
def f(): return [1, 2, 3]def f(): yield 1; yield 2; yield 3

「暂停」到底是什么意思

def numbers(n):
    for i in range(n):
        print("  算出一个", i)
        yield i


print("开始循环")
for x in numbers(3):
    print("拿到", x)
print("结束")
开始循环
  算出一个 0
拿到 0
  算出一个 1
拿到 1
  算出一个 2
拿到 2
结束

看输出的交替顺序。如果生成器是一次性算完再交给你，应该是三个「算出一个」先全打印完。实际是一算一交、交替出现——证明它是真的懒：你要一个，它算一个。

这个特性带来三个好处：
① 省内存：一百万个结果不需要一百万个位置，只需要一个
② 能表示无限序列：斐波那契可以一直 yield 下去（D009 的练习里那个无限生成器就是）
③ 能边算边用：读一行处理一行，不用等文件读完
反过来也有一条限制：生成器只能往前走，不能回头、不能取下标、不能 len()。需要反复遍历的数据，还是老老实实用 list。

4真实场景：读一个装不进内存的文件

先造一个 5.4MB 的文件，两种读法比内存占用（tracemalloc 是标准库，专业测内存用的）：

import os
import tracemalloc

with open("big.txt", "w", encoding="utf-8") as f:
    for i in range(200000):
        f.write(f"第 {i} 行 一些内容\n")

print("文件大小:", round(os.path.getsize("big.txt") / 1024 / 1024, 1), "MB")

tracemalloc.start()
total = 0
for line in open("big.txt", encoding="utf-8"):
    total += int(line.split()[1])
cur, peak = tracemalloc.get_traced_memory()
tracemalloc.stop()
print("逐行读  累加 =", total, " 峰值内存 =", round(peak / 1024 / 1024, 1), "MB")

tracemalloc.start()
lines = open("big.txt", encoding="utf-8").readlines()
total2 = sum(int(l.split()[1]) for l in lines)
cur2, peak2 = tracemalloc.get_traced_memory()
tracemalloc.stop()
print("readlines 累加 =", total2, " 峰值内存 =", round(peak2 / 1024 / 1024, 1), "MB")
print("结果一样吗:", total == total2)
文件大小: 5.4 MB
逐行读  累加 = 19999900000  峰值内存 = 0.0 MB
readlines 累加 = 19999900000  峰值内存 = 18.5 MB
结果一样吗: True

结果完全一样，内存差 18 倍。注意 readlines() 用的 18.5MB 比文件本身还大——因为每行都是一个 Python 字符串对象，对象头 + 字符存储，比文件里的 UTF-8 字节要占得多。

写法内存适合
f.readlines()整个文件小文件，需要反复访问、需要下标
for line in f:一行任何大文件——养成这个习惯就对了
f.read()整个文件成一个字符串要整体替换、正则跨行匹配时
记住这一行：for line in f 背后就是迭代器协议。文件对象天生就是迭代器，所以 D006 学的「逐行读」和今天学的「生成器」是同一套机制。这不是巧合——Python 把「一次给一个」做大成了统一的语言特性，列表、字典、文件、生成器、数据库游标全都遵守它，所以 for 能遍历它们所有。

写法返回内存什么时候用
[x*x for x in nums]list全部元素都在要多次遍历、要下标、要 len()
(x*x for x in nums)generator只占一个元素的位置只遍历一次，直接喂给 sum / max / any
sum(x*x for x in range(1000000)) 这一行值得记住。如果用方括号，要先造一个一百万元素的列表再求和，内存瞬间涨到几十 MB；用圆括号，从头到尾只算一个加一个。并且方括号也能跑，结果一样——所以这个优化是零成本的，看到「生成一个临时列表只为了求和/求最大值」，就该换成圆括号。
只有一个参数时可以省掉一层括号：sum(x*x for x in nums)，但两个参数时不行：sorted((x*x for x in nums), reverse=True)。别为了省括号把可读性搞没了。

6itertools：把迭代器拼起来

标准库里有个模块专门做这件事，全部返回迭代器、全部省内存、全部是 C 实现（比自己写的快）。

import itertools

print(list(itertools.islice(itertools.count(10, 5), 4)))
print(list(itertools.chain([1, 2], "ab", (3,))))
print(list(itertools.islice(itertools.cycle("AB"), 6)))
print(list(itertools.product([1, 2], "ab")))
print([(k, len(list(g))) for k, g in itertools.groupby("AAABBBCCA")])
print(list(itertools.accumulate([1, 2, 3, 4])))
print(list(itertools.combinations([1, 2, 3], 2)))
[10, 15, 20, 25]
[1, 2, 'a', 'b', 3]
['A', 'B', 'A', 'B', 'A', 'B']
[(1, 'a'), (1, 'b'), (2, 'a'), (2, 'b')]
[('A', 3), ('B', 3), ('C', 2), ('A', 1)]
[1, 3, 6, 10]
[(1, 2), (1, 3), (2, 3)]
函数作用典型用途
count(start, step)无限递增必须配 islice 截断
islice(it, n)只取前 n 个给无限生成器套一个「取多少个」
chain(a, b)把多个序列接起来合并多份数据，不产生中间列表
cycle(it)无限循环一个序列轮询、轮流分配
groupby(it, key)相邻相同的一组必须先排序才能全局分组
accumulate(it)累积计算（默认累加）前缀和、累计值
product / combinations笛卡尔积 / 组合暴力枚举、参数组合
groupby 只合并「相邻」的相同项。上面 "AAABBBCCA" 的结果里 A 出现了两次（('A', 3) 和 ('A', 1)），因为它中间的 C 打断了。想要全局分组必须先 sorted()：groupby(sorted(data))。
为什么这些要放在标准库里：它们在 C 层实现，比自己写 for 循环快，而且不占内存。以后处理日志、文本、数据清洗会天天用到，现在不用背全表，记住「有这个模块，缺什么去查」就够了。

def chunked(iterable, size):
    buf = []
    for x in iterable:
        buf.append(x)
        if len(buf) == size:
            yield buf
            buf = []
    if buf:
        yield buf


for c in chunked(range(7), 3):
    print(c)
print(list(chunked("abcdef", 2)))

# D012 笔记

## for 背后
- it = iter(nums) → next(it) 一个个取 → 取不到抛 StopIteration → for 接住并结束
- 迭代器用「抛异常」表示结束，不是返回哨兵值

## 可迭代 vs 迭代器
- 可迭代：有 __iter__（list / str / dict / range / 生成器函数）
- 迭代器：有 __iter__ + __next__（iter(list)、生成器对象、文件对象）
- 可迭代可以反复遍历；迭代器一次性，走完就空
- 坑：sum(gen) 之后再 max(gen) 永远是空 → 不报错但结果错

## 手写迭代器
- __iter__ 返回 self
- __next__ 返回下一个值，没有了 raise StopIteration

## yield
- 函数里有 yield 就是生成器函数；调用只造对象，不执行
- 每次 next() 跑到下一个 yield 停住，下次从那里继续
- 好处：省内存、能表示无限序列、能边算边用
- 限制：只能往前，不能下标、不能 len、不能回头

## 惰性求值
- for line in f  → 一次只装一行（文件对象本身就是迭代器）
- f.readlines()  → 全部装进内存，5.4MB 文件峰值 18.5MB
- 大文件一律用 for line in f

## 生成器表达式
- [x for x in ...]  → list，全部算出来
- (x for x in ...)  → generator，算一个给一个
- sum/max/min/any/all 直接用圆括号，零成本优化

## itertools
- count / islice     无限序列 + 截断（必须配 islice）
- chain              拼接多个序列
- cycle              无限循环
- groupby            相邻分组！要全局分组先 sorted
- accumulate         前缀和
- product / combinations  笛卡尔积 / 组合

## C 对比
- 返回 NULL 当哨兵        vs  raise StopIteration
- 手动 malloc 整个数组     vs  yield 一个算一个
- 回调函数逐行处理        vs  for line in f
