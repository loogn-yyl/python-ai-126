## 一、语法速记
- 赋值不能有空格：name="x"
- 变量后接字母数字下划线 → 用 ${name}
- 数字比较：-eq -lt -gt   字符串：= !=
- [ -f "$f" ] 里每个空格都不能少。[ 是一个命令（等价于 test），它必须收到 ] 作为最后一个参数。写成 [-f "$f"] 会报 `[`-f: command not found
- 判断：用 [[ ]]，比 [ ] 安全  
  变量为空时: [ ] 会崩, 必须加引号; [[ ]] 安全, 可以不加引号  
  `&& ||`: [ ] 不行，要写 -a -o; [[ ]]可以  
  正则=~: [ ] 不支持; [[ ]] 支持  
  可移植性: [ ]所有 sh 都认; [[ ]] 只有 bash/zsh 认
- 读文件：while IFS= read -r line; do ...; done < 文件
- 转发参数：函数里写 "$@"
- 终端里 `$0` = `-zsh`（减号 = 登录 shell），`$#` = 0 —— **这三个变量在交互窗口里没有参考价值**，必须写进 .sh 再跑才看得到真实含义

| 对文件 | 对字符串 | 对数字 |
| --- | --- | --- |
| -e 存在 | -z "$s" 为空 | -eq 等于 |
| -f 是普通文件 | -n "$s" 非空 | -ne 不等 |
| -d 是目录 | "$a" = "$b" 相等 | -lt 小于 |
| -r 可读 / -w 可写 / -x 可执行 | "$a" != "$b" 不等 | -gt 大于 |

## 六、bash 和 zsh 不一样的两处

1. **zsh 交互窗口里 `#` 不是注释**
   - 现象：敲 `# name = "loogn"` → `zsh: command not found: #`
   - 原因：zsh 的 `INTERACTIVE_COMMENTS` 默认关，bash 默认开
   - 只影响交互窗口，脚本里 `#` 永远是注释
   - 已修：`setopt interactive_comments` 写进 `~/.zshrc`
   - 收益：现在能整块粘贴带注释的命令了

2. **变量赋值 `=` 两边不能有空格**
   - `name="loogn"` 对
   - `name = "loogn"` 被拆成命令 `name` + 参数 → `command not found: name`
   - 根因：shell 的赋值是**语句**，不是表达式，和 Python 的 `x = 1` 完全不同

3. **zsh 默认不对变量分词**（写循环时才暴露，先记着）
   - `f="a b"; for x in $f` → bash 循环两次，zsh 只循环一次
   - 想要两边一致：写 `for x in ${=f}`（zsh）或直接用数组

4. **管道里改变变量: bash 会丢 zsh 不会丢**（写 while 循环时）
   - bash / ksh：管道每一段都 fork 子 shell。`while` 循环在子 shell 里跑，循环内部改动变量的是子 shell 的副本，循环结束副本销毁，父 shell 的变量不变。
   - zsh：多段管道的**最后一段**在当前 shell 里跑，不另起子 shell。所以循环里改的就是父 shell 的变量。

## 七、今天踩的坑

1. 最坑的一个：`$today，` —— 变量名把中文标点的首字节吃掉了  
**现象**  
`variable.sh` 里这一行：  
```bash
echo "今天 $today，当前目录有 $n 项"
```
`bash -x` 显示 `today=2026-11-27`、`n=5` 全都正常，但输出是：
```
今天 ??当前目录有 5 项
```
日期整段消失，逗号变成两个问号。同一行里的 `$n` 却完全正常。

**修法**
```bash
echo "今天 ${today}，当前目录有 $n 项"
```
改成花括号之后立刻正常。原因：`${today}` 让变量名在 `}` 处**强制结束**，后面的字节再也进不了变量名。

- 变量后面紧跟**中文或任何非 ASCII 字节** → 一律写 `${var}`
- 变量后面紧跟下划线、数字、字母 → 也是 `${var}`（`$file_2026` 会被解析成变量 `file_2026`，不是 `file`）
- 变量后面跟**点号、斜杠、空格、引号** → 可以不加（点号不是合法变量名字符）：`$file.txt` 是安全的

2. `[ ]` 的两个硬要求
- `[` 是**命令**，不是关键字，所以它有两条不能破的规矩：
```bash
if [ -d ~/linux-lab]; then      # ✗ 报 missing ']'
if [ -d ~/linux-lab ]; then     # ✓ ] 前面必须有空格

if [ -f $f ]; then              # ✗ 变量为空时变成 [ -f ]，条件恒真
if [ -f "$f" ]; then            # ✓ 变量一律加引号
```
- 变量不加引号时还有一个更隐蔽的报错：变量值里含空格会被切开，`[` 收到多余的参数，报 `binary operator expected`。
- `[[ ]]` 是关键字，不要求引号、支持 `==` 通配和 `=~` 正则，但 `#!/bin/sh`（dash / ash）不认它。

3. `readonly` 再赋值 = 整个脚本当场退出
```bash
readonly MAX=7
MAX=8
```
- 在**脚本**里，第二行是致命错误，**整个脚本以 rc=1 退出**，后面的语句一条都不执行。
- 在**交互窗口**（`source` 同一份文件）里，只报一行 `read-only variable: MAX`，然后继续。
- 两个环境的差别很大，别拿交互窗口的体验去推断脚本。

4. BSD 的 `wc -l` 会右对齐补空格
```bash
n=$(wc -l < access.log)
echo "行数: $n"
```
在 macOS 上输出 `行数:        5`——前面多了一堆空格。因为 BSD 的 `wc` 输出是右对齐的，`$( )` 会把空格一起抓进来。GNU 的 `wc` 不补。

```bash
n=$(wc -l < access.log | tr -d ' ')
```

## 八、已解开的疑问
1. `set -e` 在 `if` 条件里不生效，为什么？（还欠一个能说清的机制，不是背结论）  
   POSIX 规定：失败命令只要出现在 if/while/until 的条件位、&& || 的非末位、  
   用 ! 取反的、管道的非末段，就属于「控制流」而不是「错误」，不触发退出。  
   set -e 只管「没人接的错误」。如果条件位也退出，if/else 这个语法就没法写了。
2. `trap cleanup EXIT` 里 `$?` 什么时候已经被覆盖了——第 6 题那个 `local rc=$?` 到底防的是什么
   防的是 `local` 自己，不是 trap 入口。trap 入口的 $? 是对的（实测 rc=1）。  
   但 `local` 是一条命令，执行成功返回 0，会把 $? 冲掉：  
     local rc=$?        → rc=1  ✅（先展开 $?，再执行 local）  
     local rc; rc=$?    → rc=0  ❌（local 已经把它冲成 0 了）
