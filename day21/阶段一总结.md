# 阶段一总结（D001–D020，三周）

## 一、我现在能独立做什么
- 给一份 CSV 或日志文件，读出它、按任意字段分组统计、结果存成 JSON
- 写一个别人能直接用的命令行工具：argparse 定义参数、三档输出（text / csv / json）、错误走 stderr、退出码分明
- 把上百行的脚本拆成「模型 / 存储 / 界面」三层，改一层不牵动另一层，并配上 pytest 测试
- 处理真实文件里的脏数据：编码试探（utf-8 → gbk）、坏行单独计数不崩、数据文件损坏时按空数据启动
- 用 requests 抓页面、用线程池把多个 IO 任务并发跑起来

## 二、三块地基，各记一句话
- 语法地基：可变/不可变 + 「变量只是引用」，决定了默认参数、闭包、赋值这些坑的全部形状
- 组织代码：把「数据怎么存」和「人怎么用」按模块分开
- 与外界打交道：文件会坏、编码会错、网络会挂，边界上必须分类讨论，不能用 errors="ignore" 糊过去

## 三、最容易被记反
| 听起来很对 | 实际 | 出处 |
| --- | --- | --- |
| match 是「更严格的 search」 | match 只管起点，不管结尾；要整串匹配用 fullmatch | D015 |
| 有 GIL，所以多线程是安全的 | GIL 只保证「同一时刻一个线程跑字节码」，不保证一段代码连续执行完，+= 照样丢更新 | D019 |
| findall 会把所有分组都返回 | 只返回最外层分组；组数 ≥2 时用 finditer + 命名分组 | D015 |
| csv 读出来的数字是数字 | 全是字符串，"200" + 1 直接 TypeError，得自己转 int | D016 |
| requests 自带超时 | 默认没有超时，对方不响应就永远挂着；每个请求都要显式 timeout= | D017 |
| basicConfig 可以随时重新配置 | 只有第一次生效，后面全部静默忽略 | D020 |
| return 1 能让进程退出码变 1 | 必须 sys.exit(main())，否则进程照样退 0 | D020 |
| errors="ignore" 只是「宽容一点」 | 它会静默删字节，数据错了你还不知道 | D016 D021 |

2. **编码**：utf-8 读 GBK 会崩这件事知道了，也有兜底函数，但「什么时候该 `errors="ignore"`、什么时候必须让它抛」还是靠试，没有判断标准。D016 和 D020 各栽过一次。
