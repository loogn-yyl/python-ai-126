# D015 笔记 · 正则表达式

## 一句话
正则不是「更复杂的字符串方法」，是「描述形状」——告诉程序长什么样，而不是第几段。
split() 只认空格，不认意思；格式一变就错位，而且不报错。

## 四个函数
- match     : 只从位置 0 开始匹配 —— 不是「整条必须匹配」
- search    : 全串找第一个
- findall   : 全串找全部，有分组返回元组列表
- sub       : 替换，替换串里可用 \1 \g<name>
- fullmatch : 整条都必须匹配 —— 校验用这个，不要用 match

## 元字符
\d 数字 / \w 字母数字下划线（含汉字）/ \s 空白 / . 任意（除换行）
* 0+ / + 1+ / ? 0或1 / {n} / {n,m} / [abc] / [^abc] / | / ( )
^ 开头  $ 结尾

## r 前缀（必须）
r"\bword" 长度 6（反斜杠 + b + word）
"\bword"  长度 5（退格符 + word）
必错三场景：\b 单词边界 / \n \t / Windows 路径
规矩：写正则的地方，字符串一律 r"...". 没有例外。

## 分组
(...)        捕获组，group(1) 从 1 开始
(?P<name>...) 命名分组，groupdict() 直接拿字典 ★组数≥2 就用它
(?:...)      非捕获组，只想让量词作用在一串上
findall 只返回最外层分组的内容；要 group(0) 和位置就用 finditer

## 贪婪 vs 非贪婪
.*   先吃到最远再回退 —— 抓「成对符号之间」会吞掉中间的
.*?  先吃最少再逐步加 —— 抓标签/引号/括号内的内容必须用它
判断：右边界是否在一行里出现多次？是 → 用 ?；整行到末尾 → 贪婪

## 实战正则（nginx 日志）
(?P<ip>\d{1,3}(?:\.\d{1,3}){3}) - - \[(?P<time>[^\]]+)\]
"(?P<method>[A-Z]+) (?P<path>\S+) HTTP/[\d.]+" (?P<status>\d{3}) (?P<size>\d+)

两个高频错：
- 该用 [^\]]+ 的地方用了 .+    会越界到最后的 ]
- 该用 \S+ 的地方用了 \w+      路径 /api/user 被切成 api，不报错

## 解析器的纪律
- 收集「解析失败的行」，别默默丢掉
- enumerate(lines, 1)，行号从 1 数
- 报错要带行号 + 前 30 字符

## 踩过的坑
- 正则中 {m,n} 不允许有空格, 否则就成了字符串
